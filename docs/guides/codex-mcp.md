# Codex 视频入库 MCP 指南

[返回 README](../../README.md)

Movie Harbor MCP 是运行在本机的 STDIO 服务。它让 Codex 用一组独立工具检查、转换和上传本地视频，创建电影或电视剧草稿，并在你再次确认后发布。视频按流上传，不会作为 Base64 或对话内容交给模型。

## 可调用函数

使用下表按操作查找工具。

### 文件检查与转换

| 函数 | 作用 |
| --- | --- |
| `inspect_video` | 只读检查本地视频的容器、编码、音轨、字幕轨、秒数时长及上传兼容性，返回需要时的转换方案。 |
| `validate_poster` | 只读检查用户提供的本地海报格式与基本结构；上传后的服务端完整解码是最终校验。 |
| `convert_video` | 单独确认后，将不兼容视频转换为受控目录中的 MP4，保留原视频。 |
| `delete_generated_video` | 仅删除由 MCP 转换生成且文件身份仍匹配的视频，不删除原视频。 |

### 内容与题材查询

| 函数 | 作用 |
| --- | --- |
| `search_movies` | 按名称查询电影候选，返回状态、版本、访问范围、整数分钟时长及海报和视频是否存在；不自动选择或合并。 |
| `search_series` | 按名称查询剧集候选，返回状态、版本、访问范围、海报是否存在及季、集数量；不自动选择或合并。 |
| `get_series_structure` | 只读获取指定剧集的季、单集、集名、秒数时长、状态、版本及视频是否存在。 |
| `list_missing_videos` | 按电影或具体单集分页查找缺视频的内容，返回位置、状态、版本和访问范围。 |
| `get_system_overview` | 读取系统采样时间、应用版本、内容与用户统计、媒体卷容量、备份状态和告警。 |
| `list_genres` | 只读列出全部题材，包括启用和停用项。 |

### 创建与元数据维护

| 函数 | 作用 |
| --- | --- |
| `create_genre` | 创建题材；精确同名的启用项直接复用，停用同名项交由管理员处理。 |
| `stage_poster` | 验证并暂存本地海报，返回有有效期的凭证，供创建电影或剧集时绑定海报。 |
| `create_movie` | 使用名称、简介、年份、题材、整数分钟时长和暂存海报凭证创建电影草稿；默认公开，也可选择私密。 |
| `create_series` | 使用名称、简介、年份、题材和暂存海报凭证创建剧集草稿；默认公开，也可选择私密，季和单集需另行创建。 |
| `create_season` | 在指定剧集下按季号创建一个季，使用剧集版本进行并发校验。 |
| `create_episode` | 在指定季下按集号、名称和秒数时长创建单集草稿；时长自动按分钟四舍五入，最少 1 分钟，访问范围继承整剧。 |
| `update_movie_metadata` | 按电影 ID 和版本修改草稿中明确提交的名称、简介、年份、题材或整数分钟时长。 |
| `update_series_metadata` | 按剧集 ID 和版本修改草稿中明确提交的名称、简介、年份或题材。 |
| `update_episode_metadata` | 按剧集、季、单集 ID 和单集版本修改草稿的集号、名称或时长；提交时长时自动按分钟四舍五入，最少 1 分钟。 |
| `update_content_synopsis` | 统一修改电影或剧集简介；已发布内容自动归档并转为草稿，已归档内容自动转为草稿，修改后保持草稿状态。 |

### 视频上传与替换

| 函数 | 作用 |
| --- | --- |
| `upload_movie_video` | 将本地兼容视频流式上传到电影的空视频槽，不覆盖已有视频，不自动发布。 |
| `replace_movie_video` | 按确认计划流式替换电影已有视频，成功后同步移除旧视频，不自动发布。 |
| `upload_episode_video` | 将本地兼容视频流式上传到指定单集的空视频槽，不覆盖已有视频，不自动发布。 |
| `replace_episode_video` | 按确认计划流式替换指定单集已有视频，成功后同步移除旧视频，不自动发布。 |

### 访问范围、海报与生命周期

| 函数 | 作用 |
| --- | --- |
| `set_content_visibility` | 在任意生命周期状态修改电影或整剧的公开、私密范围。季和单集继承整剧。 |
| `set_content_poster` | 用用户提供的本地图片为电影或整剧草稿补传或替换海报。替换成功会永久移除旧海报。 |
| `transition_content_lifecycle` | 独立确认后，把电影、整剧或指定单集转为已发布、已归档或草稿。 |

创建与上传前必须先确认完整入库计划；转换、入库和发布分别确认。公开草稿在发布前仍不可见。电影时长使用整数分钟；单集工具接收整数秒，写入时取整为整分钟对应的秒数。通用视频探测和转换保留秒数，所有写操作仍须遵守草稿编辑、版本校验和媒体独占约束。

## 安装与更新

安装机器需要 Node.js、npm、Codex CLI、FFmpeg 和 FFprobe。先确认 Movie Harbor 服务已经部署且可以从本机访问，再在仓库根目录执行：

```bash
./mcp/install.sh
```

脚本使用锁文件安装依赖并构建 MCP，然后通过 `codex mcp add` 注册全局服务。它只更新名为 `movie-harbor`、且确认属于当前仓库的条目，不会整体改写 Codex 配置，也不会覆盖其他工程的同名服务。

安装完成后可检查注册：

```bash
codex mcp list
codex mcp get movie-harbor --json
```

脚本不会自动重启 Docker Compose。请把输出的 SHA-256 摘要写入 Movie Harbor 部署环境中的 `MCP_API_KEY_SHA256`，自行重启 Movie Harbor，然后在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。不要把摘要误当作原始密钥。

更新仓库中的 MCP 后，需要重新执行 `./mcp/install.sh` 安装新构建，再在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。

## 独立密钥和本机配置

MCP 使用独立于管理员登录的 Bearer 密钥。原始密钥仅保存在权限为 `0600` 的 `credentials.env`，普通配置只引用该文件；安装输出、Codex 启动参数和 Git 中都不应出现原始密钥。后端只保存其 SHA-256 摘要。

默认配置目录是 `${XDG_CONFIG_HOME:-$HOME/.config}/movie-harbor-mcp`。默认允许读取 `/Users/zhangdi/Downloads`，可在运行安装脚本前通过 `MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON` 指定其他绝对目录，例如：

```bash
MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON='["/Volumes/Media/Incoming"]' ./mcp/install.sh
```

只把确实用于入库的目录加入允许列表。MCP 会解析真实路径，拒绝目录、非普通文件、符号链接逃逸和执行期间发生身份变化的文件。转换输出位于受控生成目录；上传明确成功后自动删除，上传失败或结果未知时保留以便重试，原视频永不删除。

远程 Movie Harbor 可通过 `MOVIE_HARBOR_MCP_BASE_URL` 指定无凭据、无额外路径的 HTTP(S) 根地址。例如，服务运行在可信局域网主机 `192.168.1.20` 时：

```bash
MOVIE_HARBOR_MCP_BASE_URL='http://192.168.1.20:8080/' ./mcp/install.sh
```

正式环境或不可信网络应使用 HTTPS。只有明确可信的局域网才可使用 HTTP，并且服务端还需要按[部署指南](deployment.md)显式启用可信局域网 HTTP。安装器仍只显示摘要；请在远程部署端人工配置摘要并重新创建 API 容器，不要复制原始密钥到命令行或聊天中。

## 在 Codex 中使用

安装并重启 `movie-harbor` MCP 后，可以直接在 Codex 桌面版对话中提供本地文件路径。例如，上传一部电影：

```text
上传影片 /Users/me/Downloads/movie.mp4，
影片名称是：示例电影，
海报是 /Users/me/Downloads/poster.webp
```

Codex 会先执行只读检查：验证视频和海报、查询 Movie Harbor 中的同名内容、读取现有题材，并为未提供的年份、简介和题材查询可靠互联网来源。随后会展示完整入库计划，包括本地文件路径、视频兼容性、整数分钟时长、访问范围、元数据来源以及将要执行的创建或替换动作。

核对计划后回复“确认”，Codex 才会暂存海报、创建草稿并上传视频。上传成功后内容仍是草稿；只有再次明确回复“发布”，Codex 才会调用 `transition_content_lifecycle` 发布指定内容。创建时默认使用公开访问范围，但公开草稿在发布前仍不能被访客访问。需要私密内容时，应在最初请求中明确说明“访问范围设为私密”。

上传电视剧时同时提供剧名、季号、集号、视频路径和剧集海报路径。未提供单集名称时，Codex 会联网查询并在计划中列出来源。剧集、季、单集、单集视频和父剧集发布是独立原子操作；发布单集不会自动发布父剧集。

如果视频不符合网站要求，Codex 会先说明不兼容轨道和转换方案。只有单独同意转换后才会生成兼容文件；转换完成后还会再次展示最终入库计划，并重新取得入库确认。原视频不会被删除。

## 典型操作流程

1. 在对话中提供视频路径、海报路径和已知元数据。
2. Codex 只读检查文件、目标内容和现有题材，并补全缺失元数据。
3. 核对完整计划；如需修改名称、类型、简介或访问范围，先提出修改。
4. 回复“确认”，授权计划中列明的创建与上传动作。
5. 等待上传结束并检查返回的草稿状态。
6. 需要上线时再回复“发布”，完成独立发布确认。

上传失败后先让 Codex 查询现有内容状态。已经成功创建的草稿或已经成功上传的视频会被保留；不要在未查询状态时反复要求重新创建，以免造成重复内容。

### 为已发布电影更换海报

1. 用 `search_movies` 查找电影，核对 UUID、当前版本和海报槽位。整剧可用 `search_series` 查找，再用 `get_series_structure` 核对。用 `validate_poster` 检查用户提供、位于允许目录内的本地绝对路径。
2. 确认电影将下线后，调用 `transition_content_lifecycle`，传入 `content_type: "movie"`、`content_id`、当前 `version`、`target_status: "draft"` 和 `confirmed: true`。已发布内容会先归档再转草稿，返回 `previous_status`、`transitioned_through`、最终 `status` 和 `version`。转草稿不会自动更换海报或重新发布。
3. 单独确认补传或永久替换后，调用 `set_content_poster`，传入 `content_type`、`content_id`、刚返回的 `version`、已验证的 `path` 和 `confirmed: true`。结果中的 `action` 为 `added` 或 `replaced`，同时返回 `media_id`、格式、字节数和新的内容版本。
4. 需要重新上线时，再确认以新版本调用 `transition_content_lifecycle`，将 `target_status` 设为 `"published"`。发布电影或单集需要有效视频，发布整剧须先发布至少一个单集。单集调用传 `content_type: "episode"`，`content_id` 填单集 UUID，并提供 `series_id` 和 `season_id`。结果另含 `series_version`，供独立确认发布父剧时使用。

目标状态还可设为 `"archived"`。当前状态与目标相同时，工具核对版本后直接返回。草稿不能直接归档。遇到 `partial_transition` 时，`last_confirmed_status` 表示最后确认成功的状态。可见性或生命周期写入的回执存疑时，工具按原 UUID 只读回查一次，并停止后续写入。用 `current_status` 或 `current_visibility` 和 `current_version` 查看最新快照，单集还返回父版本。回查失败时最新值为 `null`，最近已确认的版本在 `last_confirmed_version`。即使读到目标值，`commit_status: "unknown"` 仍表示本次写入的归属未确定。第二步被明确拒绝时，`partial_transition` 同时提供拒绝码和该步的 `not_committed` 状态。请按实际快照决定并独立确认后续操作。海报写入结果存疑时核对新旧海报 ID 和版本，再决定是否重新上传。

### 修改访问范围和查找缺视频条目

修改范围时先查明目标和版本，确认后调用 `set_content_visibility`，传入 `content_type`（`movie` 或 `series`）、`content_id`、`version`、`visibility`（`public` 或 `private`）及 `confirmed: true`。结果返回最终范围和版本。相同范围保留当前版本，切换范围会立即影响已发布内容的匿名可见性。

`list_missing_videos` 为只读查询。`content_type: "movie"` 列出缺视频的电影，`content_type: "series"` 列出已有的缺视频单集及其剧、季、集标识。空剧集没有单集条目。可选 `page` 默认为 1，每页 20 条，返回 `items`、`page`、`size` 和 `total`。选择条目后，可按返回的标识和版本另行确认上传。

### 上传前检查媒体卷

调用 `get_system_overview` 时传空对象 `{}`，即可读取管理员概览的同一份快照。查看 `sampled_at` 和 `volumes[0]` 的可用空间、预留空间、可写空间及 `accepts_uploads`。备份状态 `unverifiable` 表示服务无法核实备份。容量采样失败时容量字段为 `null`，告警会给出原因。

电影和单集的四个上传与替换工具在核对本地文件后、查询目标前，按“新文件大小 + 10 GiB 预留”检查卷 0 的可用量。等于门槛可以继续。替换时按整个新文件计算，旧视频仍占空间。MCP 与管理前端都会通过 `X-Media-Byte-Size` 声明文件自身的字节数。服务端在媒体变更锁内复核实际容量，并在流式写入时核对声明和实际字节数。预检通过后仍可能遇到其他上传占用空间。

- `storage_space_low` 表示空间不足。按返回的字节数及缺口释放空间。服务端返回 HTTP 507 且缺少容量数字时，重新调用 `get_system_overview` 查看卷 0 的可用量和预留量。
- `storage_capacity_unavailable` 表示容量暂不可读。恢复采样后再上传。
- `declared_size_invalid` 或 `declared_size_mismatch` 表示声明无效或与实收大小不符。重新检查本地文件及客户端版本后再试。
- 上传失败时普通源文件保留，转换生成的视频按返回提示保留供重试。结果未知时先检查目标版本及视频槽位。

## 检查与故障排查

使用以下命令确认全局 MCP 注册仍指向当前仓库构建和预期配置文件：

```bash
codex mcp get movie-harbor --json
```

如果重新部署后出现“认证失败，请检查 MCP 凭据”，通常是部署端的 `MCP_API_KEY_SHA256` 丢失或与本机原始密钥不匹配。重新执行 `./mcp/install.sh` 会复用安全保存的本机凭据并显示对应 SHA-256 摘要；将该摘要写入部署端 `.env`，然后重新创建 API 容器以加载新环境变量：

```bash
docker compose --env-file .env up -d --no-build --force-recreate api
```

最后在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。不要把 `credentials.env` 中的原始密钥打印到终端、写入部署端 `.env`、提交到 Git，或发送到对话中。普通的 `docker compose restart` 不会重新读取修改后的环境变量。

如果本地文件提示“不在允许目录中”，请使用 `MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON` 重新运行安装器，并只加入确实用于入库的绝对目录。视频格式不兼容时应按转换确认流程处理，不要通过放宽服务端媒体校验绕过安全检查。

## 入库要求

MCP 创建的新电影和电视剧默认公开，也可在入库计划中明确选择私密。新内容仍为草稿，选择公开也要等到发布后才能在公开站访问。创建前必须由你指定并验证本地海报路径；没有海报不能创建，Codex 不得联网下载海报。元数据要求如下：

- 电影：名称、年份、非空简介、至少一个题材、海报和整数分钟时长。
- 电视剧：名称、年份、非空简介、至少一个题材和海报。
- 单集：季号、集号、非空单集名称，以及由 FFprobe 探测的秒数时长；创建和修改时自动按分钟四舍五入，最少 `1` 分钟。

通用视频探测和转换工具保留精确秒数；电影入库计划和电影专属工具显示并提交四舍五入后的整数分钟，不足一分钟的正时长按 `1` 分钟处理。例如 `10176.1` 秒显示并提交为 `170` 分钟。单集创建和修改工具仍接收整数秒 `duration_seconds`，但会自动按同一规则取整，再以整分钟对应的秒数写入后端。例如 `3584` 秒保存为 `3600` 秒（`60` 分钟）。只修改名称或集号时不会改写原时长；查询旧内容也不会自动改写数据。时长只以本地视频的 FFprobe 结果为准。

你未提供名称、年份、简介、题材或单集名称时，Codex 必须联网查询可靠来源。优先使用制片方、发行方或流媒体官方页面，信息不足时参考可信影视资料库，并为每个联网补全字段展示来源链接。简介根据来源事实写成简洁中文摘要；你已提供的字段不会被联网结果静默覆盖。可靠来源冲突或信息不足时，Codex 会停止并询问你选择或补充，不得虚构。单集名称可根据剧名、季号和集号查询；海报仍由你指定本地路径，访问范围采用你的选择或默认公开。

联网题材会先映射到现有题材，缺少的题材列入完整入库计划，确认后再单独创建。搜索结果不会按近似名称自动合并；出现多个同名候选时必须由你明确选择。已有内容只按最新版本更新，遇到 `409` 版本冲突时应重新查询并重新确认，不能自动覆盖并发修改。

## 三次独立确认

转换、入库和发布是三个相互独立的阶段，一次确认不能代替另一次：

1. **转换确认**：视频不符合网站要求时，Codex 展示原因、轨道处理和输出位置；只有你同意后才调用转换工具。需要 FFmpeg/FFprobe，图像字幕等不支持情况会停止并提示处理。
2. **完整入库确认**：创建和上传前，Codex 展示完整入库计划：内容层级、名称、年份、简介、题材和单集名称，联网字段的来源链接，海报与视频路径，电影和单集的整数分钟（单集同时列出探测秒数），公开或私密范围，以及兼容性、转换结果和具体写入动作。一次明确的入库确认覆盖计划中列明的创建题材、海报暂存、创建内容层级和上传或替换视频；只有确认后才向入库写工具传 `confirmed: true`。空视频槽位使用普通上传；已有视频必须明确说明替换，并调用独立的替换工具。普通上传不会隐式覆盖。入库确认不覆盖转换或发布。
3. **发布确认**：上传完成后 Codex 再询问是否发布。电影、单集和父电视剧分别发布；发布单集不会自动发布仍为草稿的父电视剧。

计划、文件身份、内容或父剧集版本、目标槽位、访问范围或转换结果变化，都会使原入库确认失效。只确认部分内容、修改字段或提出疑问时，Codex 先更新完整计划并重新取得确认，不能继续写入。需要转换时，先取得转换确认，转换完成后再展示最终入库计划。

上传完成后禁止自动发布。部分步骤失败后，Codex 会保留已确认的成功结果，重新查询并规划失败步骤，避免重复创建；已经创建的草稿和已经成功上传的媒体不会因后续发布失败而回滚。

## 密钥轮换与卸载

轮换时重新生成独立原始密钥，将其保存到权限为 `0600` 的凭据文件，计算 SHA-256 摘要并更新部署端 `MCP_API_KEY_SHA256`。重启 Movie Harbor 后再重启 Codex 中的 MCP 服务；旧密钥会立即失效。轮换期间不要把原始密钥打印到终端历史或发送到对话。

只移除 Codex 注册时执行：

```bash
codex mcp remove movie-harbor
```

这不会删除 Movie Harbor 数据，也不会撤销后端摘要。确认不再需要后，可人工删除本机 MCP 配置目录，并从部署环境移除 `MCP_API_KEY_SHA256` 后自行重启 Movie Harbor。
