# Codex 视频入库 MCP 指南

[返回 README](../../README.md)

Movie Harbor MCP 是运行在本机的 STDIO 服务。它让 Codex 用一组独立工具检查、转换和上传本地视频，创建电影或电视剧草稿，并在你再次确认后发布。视频按流上传，不会作为 Base64 或对话内容交给模型。

## 安装与更新

安装机器需要 Node.js、npm、Codex CLI、FFmpeg 和 FFprobe。先确认 Movie Harbor 服务已经部署且可以从本机访问，再在仓库根目录执行：

```bash
./mcp/install.sh
```

脚本使用锁文件安装依赖并构建 MCP，然后通过 `codex mcp add` 注册全局服务。它只更新名为 `movie-harbor`、且确认属于当前仓库的条目，不会整体改写 Codex 配置，也不会覆盖其他工程的同名服务。

安装完成后可检查注册：

```bash
codex mcp list
codex mcp get movie-harbor --json
```

脚本不会自动重启 Docker Compose。请把输出的 SHA-256 摘要写入 Movie Harbor 部署环境中的 `MCP_API_KEY_SHA256`，自行重启 Movie Harbor，然后在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。不要把摘要误当作原始密钥。

更新仓库中的 MCP 后，需要重新执行 `./mcp/install.sh` 安装新构建，再在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。

## 独立密钥和本机配置

MCP 使用独立于管理员登录的 Bearer 密钥。原始密钥仅保存在权限为 `0600` 的 `credentials.env`，普通配置只引用该文件；安装输出、Codex 启动参数和 Git 中都不应出现原始密钥。后端只保存其 SHA-256 摘要。

默认配置目录是 `${XDG_CONFIG_HOME:-$HOME/.config}/movie-harbor-mcp`。默认允许读取 `/Users/zhangdi/Downloads`，可在运行安装脚本前通过 `MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON` 指定其他绝对目录，例如：

```bash
MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON='["/Volumes/Media/Incoming"]' ./mcp/install.sh
```

只把确实用于入库的目录加入允许列表。MCP 会解析真实路径，拒绝目录、非普通文件、符号链接逃逸和执行期间发生身份变化的文件。转换输出位于受控生成目录；上传明确成功后自动删除，上传失败或结果未知时保留以便重试，原视频永不删除。

远程 Movie Harbor 可通过 `MOVIE_HARBOR_MCP_BASE_URL` 指定无凭据、无额外路径的 HTTP(S) 根地址。例如，服务运行在可信局域网主机 `192.168.1.20` 时：

```bash
MOVIE_HARBOR_MCP_BASE_URL='http://192.168.1.20:8080/' ./mcp/install.sh
```

正式环境或不可信网络应使用 HTTPS。只有明确可信的局域网才可使用 HTTP，并且服务端还需要按[部署指南](deployment.md)显式启用可信局域网 HTTP。安装器仍只显示摘要；请在远程部署端人工配置摘要并重新创建 API 容器，不要复制原始密钥到命令行或聊天中。

## 在 Codex 中使用

安装并重启 `movie-harbor` MCP 后，可以直接在 Codex 桌面版对话中提供本地文件路径。例如，上传一部电影：

```text
上传影片 /Users/me/Downloads/movie.mp4，
影片名称是：示例电影，
海报是 /Users/me/Downloads/poster.webp
```

Codex 会先执行只读检查：验证视频和海报、查询 Movie Harbor 中的同名内容、读取现有题材，并为未提供的年份、简介和题材查询可靠互联网来源。随后会展示完整入库计划，包括本地文件路径、视频兼容性、整数分钟时长、访问范围、元数据来源以及将要执行的创建或替换动作。

核对计划后回复“确认”，Codex 才会暂存海报、创建草稿并上传视频。上传成功后内容仍是草稿；只有再次明确回复“发布”，Codex 才会调用独立发布工具。创建时默认使用公开访问范围，但公开草稿在发布前仍不能被访客访问。需要私密内容时，应在最初请求中明确说明“访问范围设为私密”。

上传电视剧时同时提供剧名、季号、集号、视频路径和剧集海报路径。未提供单集名称时，Codex 会联网查询并在计划中列出来源。剧集、季、单集、单集视频和父剧集发布是独立原子操作；发布单集不会自动发布父剧集。

如果视频不符合网站要求，Codex 会先说明不兼容轨道和转换方案。只有单独同意转换后才会生成兼容文件；转换完成后还会再次展示最终入库计划，并重新取得入库确认。原视频不会被删除。

## 典型操作流程

1. 在对话中提供视频路径、海报路径和已知元数据。
2. Codex 只读检查文件、目标内容和现有题材，并补全缺失元数据。
3. 核对完整计划；如需修改名称、类型、简介或访问范围，先提出修改。
4. 回复“确认”，授权计划中列明的创建与上传动作。
5. 等待上传结束并检查返回的草稿状态。
6. 需要上线时再回复“发布”，完成独立发布确认。

上传失败后先让 Codex 查询现有内容状态。已经成功创建的草稿或已经成功上传的视频会被保留；不要在未查询状态时反复要求重新创建，以免造成重复内容。

## 检查与故障排查

使用以下命令确认全局 MCP 注册仍指向当前仓库构建和预期配置文件：

```bash
codex mcp get movie-harbor --json
```

如果重新部署后出现“认证失败，请检查 MCP 凭据”，通常是部署端的 `MCP_API_KEY_SHA256` 丢失或与本机原始密钥不匹配。重新执行 `./mcp/install.sh` 会复用安全保存的本机凭据并显示对应 SHA-256 摘要；将该摘要写入部署端 `.env`，然后重新创建 API 容器以加载新环境变量：

```bash
docker compose --env-file .env up -d --no-build --force-recreate api
```

最后在 Codex 桌面版的 MCP servers 设置中重启 `movie-harbor`。不要把 `credentials.env` 中的原始密钥打印到终端、写入部署端 `.env`、提交到 Git，或发送到对话中。普通的 `docker compose restart` 不会重新读取修改后的环境变量。

如果本地文件提示“不在允许目录中”，请使用 `MOVIE_HARBOR_MCP_ALLOWED_ROOTS_JSON` 重新运行安装器，并只加入确实用于入库的绝对目录。视频格式不兼容时应按转换确认流程处理，不要通过放宽服务端媒体校验绕过安全检查。

## 入库要求

MCP 创建的新电影和电视剧默认公开，也可在入库计划中明确选择私密。新内容仍为草稿，选择公开也要等到发布后才能在公开站访问。创建前必须由你指定并验证本地海报路径；没有海报不能创建，Codex 不得联网下载海报。元数据要求如下：

- 电影：名称、年份、非空简介、至少一个题材、海报和整数分钟时长。
- 电视剧：名称、年份、非空简介、至少一个题材和海报。
- 单集：季号、集号、非空单集名称，以及由 FFprobe 探测的秒数时长。

通用视频探测和转换工具保留精确秒数；电影入库计划和电影专属工具显示并提交四舍五入后的整数分钟，不足一分钟的正时长按 `1` 分钟处理。例如 `10176.1` 秒显示并提交为 `170` 分钟。时长只以本地视频的 FFprobe 结果为准。

你未提供名称、年份、简介、题材或单集名称时，Codex 必须联网查询可靠来源。优先使用制片方、发行方或流媒体官方页面，信息不足时参考可信影视资料库，并为每个联网补全字段展示来源链接。简介根据来源事实写成简洁中文摘要；你已提供的字段不会被联网结果静默覆盖。可靠来源冲突或信息不足时，Codex 会停止并询问你选择或补充，不得虚构。单集名称可根据剧名、季号和集号查询；海报仍由你指定本地路径，访问范围采用你的选择或默认公开。

联网题材会先映射到现有题材，缺少的题材列入完整入库计划，确认后再单独创建。搜索结果不会按近似名称自动合并；出现多个同名候选时必须由你明确选择。已有内容只按最新版本更新，遇到 `409` 版本冲突时应重新查询并重新确认，不能自动覆盖并发修改。

## 三次独立确认

转换、入库和发布是三个相互独立的阶段，一次确认不能代替另一次：

1. **转换确认**：视频不符合网站要求时，Codex 展示原因、轨道处理和输出位置；只有你同意后才调用转换工具。需要 FFmpeg/FFprobe，图像字幕等不支持情况会停止并提示处理。
2. **完整入库确认**：创建和上传前，Codex 展示完整入库计划：内容层级、名称、年份、简介、题材和单集名称，联网字段的来源链接，海报与视频路径，电影整数分钟或单集秒数，公开或私密范围，以及兼容性、转换结果和具体写入动作。一次明确的入库确认覆盖计划中列明的创建题材、海报暂存、创建内容层级和上传或替换视频；只有确认后才向入库写工具传 `confirmed: true`。空视频槽位使用普通上传；已有视频必须明确说明替换，并调用独立的替换工具。普通上传不会隐式覆盖。入库确认不覆盖转换或发布。
3. **发布确认**：上传完成后 Codex 再询问是否发布。电影、单集和父电视剧分别发布；发布单集不会自动发布仍为草稿的父电视剧。

计划、文件身份、内容或父剧集版本、目标槽位、访问范围或转换结果变化，都会使原入库确认失效。只确认部分内容、修改字段或提出疑问时，Codex 先更新完整计划并重新取得确认，不能继续写入。需要转换时，先取得转换确认，转换完成后再展示最终入库计划。

所有工具都是原子操作。上传完成后禁止自动发布。部分步骤失败后，Codex 会保留已确认的成功结果，重新查询并规划失败步骤，避免重复创建；已经创建的草稿和已经成功上传的媒体不会因后续发布失败而回滚。

## 密钥轮换与卸载

轮换时重新生成独立原始密钥，将其保存到权限为 `0600` 的凭据文件，计算 SHA-256 摘要并更新部署端 `MCP_API_KEY_SHA256`。重启 Movie Harbor 后再重启 Codex 中的 MCP 服务；旧密钥会立即失效。轮换期间不要把原始密钥打印到终端历史或发送到对话。

只移除 Codex 注册时执行：

```bash
codex mcp remove movie-harbor
```

这不会删除 Movie Harbor 数据，也不会撤销后端摘要。确认不再需要后，可人工删除本机 MCP 配置目录，并从部署环境移除 `MCP_API_KEY_SHA256` 后自行重启 Movie Harbor。
