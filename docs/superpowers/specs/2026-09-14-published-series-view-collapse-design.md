# 已发布或归档剧集查看态的季折叠设计规格

日期：2026-09-14

## 1. 背景与目标

`2026-09-14-season-editor-collapse-design.md` 已让直接加载已有剧集时的季默认折叠，并保留新建剧集首季和后续新增季的自动展开。当前 `SeriesEditor` 在草稿中已展开的季发布成功后仍保留在 `expandedSeasons` 中：页面标题已切换为“查看剧集”，但季内容没有重新收起。内容列表的“查看”入口也需要对已发布和已归档剧集锁定同一查看态契约。

本次仅修正进入剧集查看态时的本地折叠集合。管理员从内容列表点击已发布或已归档剧集的“查看”，或将草稿剧集发布成功并原地进入查看态后，所有当时已有季必须默认折叠。新建剧集的首季、恢复创建流程的空季以及在任何允许状态下新添加的季继续自动展开。

## 2. 已确认交互

- 查看态定义为已加载剧集且状态不是 `draft`，即 `published` 或 `archived`。
- `draft` → 查看态时，清空 `expandedSeasons`；发布请求成功后的后续层级刷新完成后，所有已有季显示“展开第 N 季”。不强制重建 `SeriesEditor`，也不修改 `newSeasons`。
- 从内容列表通过“查看”进入已发布或已归档剧集时，编辑器首次加载保持空的展开集合，因此所有已有季折叠。
- 查看态内的 `published` ↔ `archived` 转换、保存子级内容、单集状态转换和其他层级刷新不得再次清空集合；管理员在查看态手动展开的季必须保持展开，除非服务端响应已删除该季。
- 新建剧集首季、恢复创建流程中空季和“添加一季”成功返回的新季仍加入 `expandedSeasons`，包括剧集已发布时新增的季。
- 折叠状态仍只存在于当前编辑器内存；返回列表后再次进入查看态，所有已有季重新折叠。

## 3. 方案与组件边界

采用已确认的 A 方案：`SeriesEditor` 计算 `viewOnly = !!series && series.status !== "draft"`，并以只依赖此布尔值的 effect 在其变为 `true` 时执行 `setExpandedSeasons(new Set())`。这既覆盖首次加载已发布或已归档剧集，也覆盖草稿发布完成后的原地状态切换；同时不会因 `series` 对象、版本号、季数组或已发布/已归档之间的状态替换而重复触发。

现有 `accept` 继续仅从集合中移除不在服务端最新层级中的季 ID。它不承担查看态重置职责，因而保存、上传、单集生命周期和刷新不会无故收起已展开季。`SeasonCard`、CSS、API 类型、后端和路由均不修改。

不采用给 `SeriesEditor` 增加 `key` 或在发布后重新挂载的方案：该方案会扩大重置范围，可能丢失编辑器内其他局部状态，且超出“只重置折叠集合”的需求。也不以 `series.status` 或整个 `series` 对象作为 effect 依赖，避免查看态内的归档、原样发布或普通层级刷新反复折叠季。

## 4. 测试与验收

Vitest 在 `SeriesEditor.test.tsx` 以草稿剧集为起点，先展开第 1 季，再点击“发布剧集”。测试先证明当前实现会错误保留“折叠第 1 季”按钮，再要求发布完成后为“展开第 1 季”；随后手动展开并归档，确认 `published` → `archived` 不重复折叠。该 RED 用例直接锁定真实缺口，而不是重复已有的初始加载折叠测试。

同一测试文件通过 `App` 覆盖内容列表入口：分别使用 `published` 和 `archived` fixture 点击对应剧集行的“查看”，确认进入“查看剧集”后季为折叠态。Playwright 的现有完整剧集流程在发布后先断言季已折叠、再显式展开后继续新增单集；它还保留已归档列表“查看”后的折叠断言和展开操作，覆盖真实服务的两类入口。

验收标准：

- 草稿发布后无需离开页面，所有已有季折叠。
- 从列表查看已发布或已归档剧集时，所有已有季折叠。
- 查看态内刷新或 `published`/`archived` 互转不再次收起管理员已展开的季。
- 新建和新增季自动展开行为、现有无障碍语义、权限、生命周期与删除流程保持不变。

## 5. 范围与非目标

修改范围限于 `frontend/admin-web/src/series/SeriesEditor.tsx`、`frontend/admin-web/src/series/SeriesEditor.test.tsx` 和 `tests/e2e/series.spec.ts`。不修改 `App.tsx`：它已经把内容列表 `view` 动作路由到同一个 `SeriesEditor`。不增加持久化、路由状态、折叠动画、手风琴限制或后端字段。
