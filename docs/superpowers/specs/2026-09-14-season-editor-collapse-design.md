# 剧集编辑页季折叠与操作按钮对齐设计规格

日期：2026-09-14

## 1. 背景与目标

剧集编辑页当前会同时完整展开所有季及其单集表单。季数量或单集数量较多时，页面会过长，管理员难以快速定位目标季。季标题区域中的“删除本季”按钮又位于季序号表单之外；父容器按整体高度居中，导致它与表单底部的“保存季序号”按钮虽然使用同一基础按钮组件，视觉上仍不能稳定等高、对齐。

本次变更只调整管理后台剧集编辑页：为每季增加独立折叠控制，默认折叠已有季，并修正季操作按钮的尺寸和底部对齐。剧集、季和单集的数据模型、API、权限、生命周期与删除确认流程保持不变。

## 2. 已确认交互

采用紧凑标题栏方案：

- 进入已有剧集的编辑页时，所有已有季默认折叠。
- 点击“添加一季”后，本次新创建的季自动展开，以便立即创建首个单集。
- 新建剧集流程自动创建的首季，以及当前创建流程中恢复出的空季，也自动展开。
- 每季独立展开或折叠；允许同时展开多季，不采用一次只能展开一季的手风琴模式。
- 折叠状态不写入数据库或浏览器持久存储。离开编辑器后再次进入，已有季重新默认折叠。
- 已展开的季在剧集详情刷新、单集状态转换或保存响应更新层级后保持展开，除非该季已被删除。

## 3. 折叠态与展开态

### 3.1 折叠态

折叠标题栏只显示：

- 展开按钮。
- “第 N 季”标题。
- 当前季的单集数量，格式为“N 集”，包含已保存的所有管理端可见单集，不包含尚未保存的新单集表单。

季序号输入、保存与删除按钮、锁定提示、已保存单集表单、未保存单集表单及“添加一集”按钮全部隐藏，使大量季保持一行一个紧凑入口。

### 3.2 展开态

展开后显示现有全部季编辑能力：

- 季序号输入与“保存季序号”。
- “删除本季”。
- 现有权限锁定提示。
- 已保存单集表单。
- 当前未保存的单集表单。
- “添加一集”。

折叠仅改变可见性，不卸载季内容组件。因此管理员在单集名称、序号、时长等字段中尚未保存的输入，以及尚未保存的新单集表单，在折叠后再次展开时必须保留。

## 4. 状态与组件边界

`SeriesEditor` 负责维护已展开季 ID 集合，因为服务端响应会更新整个剧集层级并使 `SeasonCard` 重新渲染；把展开状态放在父级可避免一次保存或状态刷新意外收起管理员正在操作的季。

`SeasonCard` 使用受控属性接收：

- 当前是否展开。
- 切换展开状态的回调。

`SeriesEditor` 在剧集标识变化或重新进入编辑器时将集合初始化为空；创建新季成功后只把新季 ID 加入集合，不收起其他季。删除季成功后，从集合中移除已经不存在的 ID。现有 `newSeasons` 仍只负责首个未保存单集表单；相同的新季 ID 同时用于触发自动展开，不把折叠状态与草稿数据职责混在一起。

季内容始终保留在 React 树中，并通过带稳定 ID 的容器使用 `hidden` 控制可见性，保证折叠时不会重置子组件本地表单状态。

## 5. 无障碍与键盘操作

- 折叠按钮使用原生 `button`，可通过键盘聚焦并用 Enter 或 Space 切换。
- 按钮提供 `aria-expanded`，值与当前状态一致。
- 按钮使用 `aria-controls` 指向对应季内容容器。
- 可访问名称随状态变化，例如“展开第 1 季”和“折叠第 1 季”。
- 折叠内容使用原生 `hidden`，不会继续出现在键盘焦点顺序或辅助技术浏览树中。
- 折叠按钮不受剧集业务编辑权限影响；只读季仍允许展开查看，但季序号、删除、添加和单集操作继续遵守现有权限结果。

## 6. 季操作按钮布局修订

将季序号表单与“删除本季”放入同一季操作区域，外层和表单均以底部对齐的弹性布局呈现。两个按钮使用同一季操作按钮类和明确的 `38px` 高度契约：

- “保存季序号”与“删除本季”在桌面布局中底边对齐且高度相同。
- 窄屏换行时两个按钮仍保持相同高度。
- 不修改共享 `Button` 的全局尺寸，避免影响管理后台其他页面。
- 危险按钮颜色、禁用态、点击行为和删除确认流程保持不变。

## 7. 错误与边界处理

- 0 集的季显示“0 集”。
- 新季创建请求失败时不增加展开 ID，保留现有错误提示和页面状态。
- 层级刷新失败时沿用现有写操作锁定逻辑，不改变当前可见内容或展开集合。
- 季被服务端刷新结果移除后，过期展开 ID 必须被清理，不能影响其他季。
- 季标题、单集数量和展开状态只来自当前管理端响应及本地 UI 状态，不新增接口字段。

## 8. 修改范围

生产实现预计只修改：

- `frontend/admin-web/src/series/SeriesEditor.tsx`
- `frontend/admin-web/src/series/SeasonCard.tsx`
- `frontend/admin-web/src/series/SeriesEditor.test.tsx`
- `frontend/admin-web/src/styles.css`

现有端到端剧集生命周期流程会在离开并重新进入编辑器后操作季内单集；该流程必须先显式展开默认折叠的季，因此同时调整：

- `tests/e2e/series.spec.ts`

不修改后端、数据库迁移、共享 API 类型、公开站、静态 Demo 或部署配置。

## 9. 测试策略

遵循测试驱动开发，先添加测试并确认失败原因来自尚未实现的折叠与布局契约，再编写最少实现。

管理后台测试覆盖：

- 多个已有季首次显示时全部折叠，季标题和已保存单集数量仍可见，季内容不可访问。
- 点击某季切换按钮只展开该季，`aria-expanded`、可访问名称和受控内容 ID 正确。
- 可同时展开多季；折叠其中一季不影响另一季。
- 在单集或新单集表单中输入未保存内容，折叠再展开后输入仍存在。
- 新创建的季自动展开，其他已展开季保持原状态。
- 服务端层级刷新后当前展开季保持展开；已删除季不留下可见或可操作入口。
- 只读或存在已发布单集的季仍能展开查看，但现有保存、删除和添加权限保持不变。
- “保存季序号”和“删除本季”同时带有统一的季操作按钮类；样式表为该类提供明确相同高度和底部对齐规则。

Playwright 端到端测试在重新进入已有剧集后必须通过可访问名称点击“展开第 N 季”，再继续归档、转草稿和删除单集及季，验证默认折叠没有破坏完整生命周期流程。

定向验证命令：

```bash
npm test --workspace @movie-harbor/admin-web -- src/series/SeriesEditor.test.tsx
npm run build --workspace @movie-harbor/admin-web
git diff --check
```

完整交付前按 `AGENTS.md` 运行与本次前端变更相关的工作区测试、构建、根契约测试和 Playwright E2E；若完整验收要求整组命令，则同时运行 Rust 和数据库测试，读取最新输出后再声明完成。

## 10. 验收标准

- 已有剧集无论包含多少季，首次进入编辑页时每季都只占一个紧凑折叠标题栏。
- 新添加的季立即展开并保留现有首个未保存单集流程。
- 各季独立展开，折叠不会丢失未保存输入，服务端刷新不会无故收起当前季。
- 折叠控制具备正确键盘和辅助技术语义。
- “保存季序号”和“删除本季”视觉高度一致、底边对齐。
- 所有现有剧集编辑权限、生命周期、删除确认、媒体上传及错误处理行为保持不变。
