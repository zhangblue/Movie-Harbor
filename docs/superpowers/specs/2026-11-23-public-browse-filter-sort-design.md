# 公开站浏览筛选与排序设计

日期：2026-11-23

## 1. 背景与目标

公开站当前把首页同时作为完整目录，支持内容类型、名称搜索、私密内容筛选和数字分页，但不提供题材、年份或排序。内容数量增长后，用户难以通过已有元数据缩小范围；若直接把更多控件堆到首页，又会削弱“继续观看”和直接开始播放的入口价值。

本次采用“简洁首页 + 独立浏览页”方案：首页用于继续观看和最近添加，新增 `/browse` 页面承载完整搜索、类型、题材、年份、访问范围、排序和分页。筛选状态全部由 URL 表达，可以刷新、分享、前进后退和从详情页返回恢复。

本文档增量修订主设计中“首页不提供题材、年份或排序筛选控件”的约定：该限制继续适用于首页，完整控件只出现在独立浏览页。

## 2. 信息架构

### 2.1 首页 `/`

首页保留品牌、账号区域和简洁导航，并按顺序显示：

1. 已登录用户存在有效记录时显示“继续观看”。
2. “最近添加”展示当前身份可见的最新 20 部电影或剧集，不显示数字分页。
3. 区块末尾提供“浏览全部”进入 `/browse`。

顶部的“全部 / 电影 / 剧集”入口改为导航到对应浏览页；短搜索框提交后进入 `/browse?q=...`。首页不显示题材、年份、排序、访问范围筛选或分页，避免形成两套完整目录状态。

### 2.2 浏览页 `/browse`

桌面端左侧显示筛选区域，右侧显示结果标题、排序、结果数量、海报网格和数字分页。移动端把筛选区域收进抽屉；抽屉关闭后，在结果上方显示当前生效条件的可移除标签和“清除全部”。

浏览页支持：

- 内容类型：全部、电影、剧集，单选。
- 关键词：继续匹配电影或剧集名称与简介。
- 题材：多选；同一维度内采用“任一匹配”，例如选择科幻和剧情会返回至少包含其中一个题材的内容。
- 年份：从当前身份可见内容中存在的年份里单选。
- 访问范围：只有已登录普通用户可选择“仅私密”；匿名用户不显示该控件。
- 排序：最近添加、年份从新到旧、年份从旧到新、名称 A–Z。
- 固定每页 20 条和现有数字页码窗口。

跨维度条件采用“同时满足”：例如“剧集 + 科幻或剧情 + 2025 年 + 名称关键词”必须满足全部维度。

## 3. URL 契约

浏览页使用以下查询参数：

- `kind=movie|series`；省略表示全部。
- `q=<文本>`；去除首尾空白，空值省略。
- `genres=<UUID>,<UUID>`；最多 20 个，去重后按 UUID 字符串排序形成规范 URL。
- `year=<四位整数>`；只接受现有内容模型允许的年份范围。
- `privacy=private`；只对已登录普通用户生效。
- `sort=recent|year_desc|year_asc|name_asc`；省略表示 `recent`。
- `page=<正整数>`；省略表示第 1 页。

新增、移除或修改任何筛选、关键词或排序时回到第 1 页；只有翻页保留其他条件并改变 `page`。前端用 `replace` 清理无效、重复或非规范参数，后端仍独立验证并对非法 API 参数返回 `400`。

用户退出、会话失效或匿名打开带 `privacy=private` 的地址时，前端移除该条件并重新请求公开结果，后端也绝不因客户端参数放宽可见范围。

## 4. 公开 API

### 4.1 目录查询

保留：

```text
GET /api/catalog
```

在现有参数上增加 `genres`、`year` 和 `sort`。`kind`、`q`、`privacy`、`page`、`size` 保持向后兼容；公开前端继续固定发送 `size=20`。

后端先确定普通用户可见范围，再应用内容类型、关键词、访问范围、年份和题材条件。题材筛选通过关联表的存在性或去重子查询实现，不能因为匹配多个已选题材而重复同一内容。

排序规则固定为：

- `recent`：`published_at DESC, kind ASC, id ASC`。
- `year_desc`：有年份优先，`year DESC, published_at DESC, kind ASC, id ASC`。
- `year_asc`：有年份优先，`year ASC, published_at DESC, kind ASC, id ASC`。
- `name_asc`：按当前 PostgreSQL 排序规则执行 `lower(name) ASC, name ASC, kind ASC, id ASC`。本次不新增名称规范化字段，不执行 Unicode 归一化，也不承诺跨数据库排序规则得到完全相同的语言学顺序。

年份为空的内容在两种年份排序中都位于有年份内容之后。所有排序都有稳定的最终键，翻页时不依赖数据库默认顺序。计数与当前页继续在同一个只读事务快照中读取。

### 4.2 筛选选项

新增：

```text
GET /api/catalog/facets
```

响应返回当前身份能够看到的已发布内容所引用的题材和实际存在的年份：

```json
{
  "genres": [{ "id": "UUID", "name": "科幻" }],
  "years": [2026, 2025, 2024]
}
```

题材按现有 `sort_order`、ID 稳定排序；即使题材后来停用，只要仍被当前可见的已发布内容引用，也继续出现在筛选项中。年份去重后降序。匿名响应不能因为只被私密内容引用而暴露题材或年份；登录用户可以看到全部已发布内容对应的选项。

目录和 facets 响应继续使用 `private, no-store` 并 `Vary: Cookie`，防止不同身份结果进入共享缓存。格式正确但数据库中不存在的题材 UUID 是可恢复的旧链接条件：API 返回空结果而不是 `400`；浏览页取得 facets 后通过 `replace` 从 URL 移除不存在的题材 ID，再按规范条件重新请求。格式错误的 UUID 仍返回 `400`。

## 5. 前端状态与交互

- 浏览页以 URL 为唯一可恢复状态来源，不另建会与 URL 分叉的持久筛选状态。
- 首次加载并行请求 facets 与目录；facets 失败时保留关键词、类型和排序能力，并提供单独重试，不把目录结果一并清空。
- 当前请求期间保留已经展示的结果和布局尺寸；快速修改条件时沿用请求世代保护，旧响应不得覆盖新 URL。
- 每个生效条件都能单独移除；“清除全部”保留当前登录身份但移除全部目录条件。
- 题材多选使用复选框，年份和排序使用单选或选择框，不能用颜色作为唯一选中提示。
- 翻页成功后焦点回到结果标题；打开和关闭移动筛选抽屉时正确管理键盘焦点。
- 无结果状态根据条件给出“清除筛选”入口，而不是只提示更换关键词。

从浏览页进入详情或播放页，再通过浏览器返回时，URL、页码和滚动位置按浏览器能力恢复；不额外把筛选写入本地存储。

## 6. 后端查询与索引

继续复用 `catalog` 边界和电影、剧集统一候选集合。实现时先用真实查询计划验证现有索引能否覆盖新增年份、发布时间和关联题材条件；只有证据表明确有需要时才新增迁移与索引，不在设计阶段预设无用索引。

facets 查询按电影和剧集的可见发布集合统一汇总，不逐条加载内容或题材，不产生 N+1 查询。目录卡片仍只在分页候选确定后连接海报和批量加载题材。

## 7. 非目标

- 推荐算法、个性化排序、评分、热度或编辑精选。
- 多年份区间、自定义排序组合或任意页面大小。
- 单集级搜索和筛选。
- 在首页复制完整筛选器或保留首页数字分页。
- 将私密内容是否存在泄露给匿名访客。
- 把筛选状态保存到数据库或跨账号同步。

## 8. 测试与验收

后端测试覆盖单项与组合筛选、题材 OR 语义、重复题材去重、年份为空排序、四种稳定排序、可见范围、facets 不泄露私密内容、分页计数快照和非法参数。真实 PostgreSQL 测试验证题材关联和排序语义。

公开前端测试覆盖首页导航、搜索跳转、URL 规范化、条件变化回到第一页、移动抽屉、条件标签、登录状态变化、facets 独立失败、过期响应保护、空状态、数字分页和焦点管理。端到端测试使用超过 20 条、多个题材和年份、公开与私密混合的数据验证匿名与登录用户结果。
