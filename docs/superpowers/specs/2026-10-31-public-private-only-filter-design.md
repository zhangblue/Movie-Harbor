# 公开站“只看私密”筛选设计

日期：2026-10-31

## 1. 背景与目标

Movie Harbor 的匿名访客只能发现已发布公开内容，普通用户登录后可以发现全部已发布公开与私密内容。当前登录只扩大可见范围，公开站首页不能进一步只查看私密内容。

本次变更新增一个仅对已登录普通用户显示的“只看私密”目录筛选。用户选中后，首页只显示其有权访问的已发布私密电影和私密剧集。该筛选只缩小已认证用户已有的可见范围，不改变认证、授权或媒体访问规则。

本设计是对 `2026-10-10-private-content-and-viewer-accounts-design.md` 中“不提供‘包含私密内容’开关”的增量修订：登录后的默认目录行为仍保持“公开与私密全部包含”；新增控件不是扩大权限的“包含私密”开关，而是仅在已有权限范围内进一步缩小结果的“只看私密”筛选。

## 2. 范围

“私密内容”包含：

- `is_private = true` 的电影；
- `is_private = true` 的整部剧集，剧集下的季和单集继续继承整剧访问范围。

本次不新增数据库字段，不改变电影、剧集或单集生命周期，不改变普通用户权限模型，也不改变媒体鉴权流程。

## 3. 首页交互

普通用户登录成功后，在首页顶部“全部 / 电影 / 剧集”内容类型切换控件右侧显示紧凑的复选项：

- 标签固定为“只看私密”；
- 未选中时，目录继续显示该用户可访问的全部已发布公开和私密内容；
- 选中时，目录只显示已发布私密电影和私密剧集；
- 该筛选可以与“全部 / 电影 / 剧集”和关键词搜索组合使用；
- 切换选中状态后立即重新请求目录，并回到第 1 页；
- 没有匹配结果时显示“没有找到私密内容”，不显示错误提示；
- 匿名访客不显示该控件。

私密卡片与详情中现有的锁形标识或“私密”标签保持不变。

## 4. URL 与浏览器导航

公开目录继续以 URL 作为筛选和分页状态来源。新增查询参数：

- `privacy=private`：启用“只看私密”；
- 参数缺失或不是受支持的值：不启用该筛选。

例如：

```text
/?privacy=private
/?kind=movie&privacy=private
/?kind=series&q=山海&privacy=private&page=2
```

切换“只看私密”、内容类型或关键词搜索时必须移除 `page`，避免沿用旧结果集的页码。浏览器刷新、前进和后退必须从 URL 恢复筛选状态。

普通用户退出登录、修改密码成功或会话失效时，前端必须移除 `privacy=private` 和 `page`，并重新加载匿名可见的公开目录。登录成功后默认不自动启用“只看私密”。

## 5. API 契约

现有 `GET /api/catalog` 增加可选查询参数：

```text
privacy=private
```

API 客户端的目录查询类型增加明确的可选字段：

```ts
privacy?: "private";
```

不新增 `/api/catalog/private` 等重复端点，也不接受布尔型 `include_private` 或由客户端声明认证范围的参数。客户端只能请求缩小结果；是否具有私密内容访问权仍由后端验证普通用户会话决定。

## 6. 服务端筛选与安全

目录查询根据普通用户会话和 `privacy` 参数形成以下行为：

| 普通用户会话 | `privacy` | 返回范围 |
| --- | --- | --- |
| 有效 | 缺失 | 全部已发布公开和私密电影、剧集 |
| 有效 | `private` | 仅已发布私密电影、剧集 |
| 无效或缺失 | 缺失 | 仅已发布公开电影、剧集 |
| 无效或缺失 | `private` | 空目录页 |

匿名或无效会话访问 `privacy=private` 时返回正常的空分页结构，不返回 `401`、`403`、私密总数或任何可用于枚举私密内容的信息。目录中的类型、关键词、私密范围、排序、总数和分页必须在同一服务端查询中完成，禁止前端只过滤当前页。

目录响应继续采用现有禁止共享缓存的策略，避免认证用户结果被共享给匿名请求。私密详情和媒体授权规则不做任何修改。

## 7. 前端状态与失败处理

首页从当前普通用户会话和 URL 共同派生控件状态：

- 只有有效普通用户会话存在时才渲染控件；
- 有效会话且 URL 为 `privacy=private` 时控件处于选中状态；
- 请求期间沿用现有目录加载和禁用交互规则，防止快速切换产生旧响应覆盖新结果；
- 目录请求失败时使用现有通用错误提示，不暴露后端响应正文；
- 会话刷新确认登录失效时，先清理私密筛选 URL，再按匿名范围重新请求目录。

## 8. 测试要求

### 后端目录测试

- 已登录普通用户不传 `privacy` 时可同时获得公开和私密内容；
- 已登录普通用户传 `privacy=private` 时只获得私密电影和私密剧集；
- 私密筛选与内容类型、关键词、稳定排序、总数和分页组合正确；
- 匿名或无效会话传 `privacy=private` 时返回空分页，不能发现私密内容；
- 未支持的 `privacy` 值不会扩大访问范围。

### API 客户端测试

- 只转发明确类型的 `privacy=private`；
- 不转发未知字段或旧式 `include_private` 参数；
- 现有目录响应类型保持兼容。

### 公开站组件测试

- 匿名状态不显示“只看私密”；
- 登录状态显示控件，选择后写入 URL 并请求 `privacy=private`；
- 切换筛选时清除 `page`；
- 内容类型、搜索和私密筛选可组合并由浏览器导航恢复；
- 退出登录、修改密码成功或会话失效后清理筛选并恢复公开目录；
- 私密筛选空结果使用专用空状态文案；
- 过期响应不能覆盖较新的筛选结果。

### 端到端测试

- 普通用户登录后选择“只看私密”，公开卡片消失，私密电影和私密剧集可见；
- 退出登录后控件消失、URL 清理，私密内容不再可见。

## 9. 非目标

- 不保存跨设备或跨登录会话的筛选偏好；
- 不在管理后台新增筛选行为；
- 不为匿名用户展示禁用态控件；
- 不新增“只看公开”或公开/私密三态筛选；
- 不调整卡片、详情或媒体文件的既有授权规则。
