# Movie Harbor 多存储卷媒体设计

日期：2026-09-16

## 1. 背景与目标

当前部署只允许通过 `MEDIA_HOST_DIR` 挂载一个媒体目录。电影视频和剧集单集持续增加后，单块硬盘可能先耗尽，而其他硬盘无法参与存储。

本次变更允许 `MEDIA_HOST_DIR` 表达至少一个宿主机媒体目录。每次上传电影海报、电影视频、剧集海报或单集视频时，系统从健康且空间足够的存储卷中选择当前剩余可用字节最多的一卷。扩容只需在配置末尾追加新目录，不移动或重新平衡已有文件。

本文档增量修订 `2026-09-12-host-data-bind-mounts-design.md` 和 `2026-09-12-media-ownership-and-publishing-design.md`。涉及媒体根目录数量、文件定位和跨卷删除恢复时，以本文档为准。

## 2. 配置接口

`.env` 没有原生数组类型，因此 `MEDIA_HOST_DIR` 使用分号分隔的有序路径列表：

```dotenv
# Linux
MEDIA_HOST_DIR=/mnt/disk1/movie-harbor;/mnt/disk2/movie-harbor

# Windows 11 Docker Desktop
MEDIA_HOST_DIR=D:/MovieHarbor/media;E:/MovieHarbor/media

MEDIA_DISK_RESERVE_BYTES=10737418240
```

配置规则：

- `MEDIA_HOST_DIR` 至少包含一个非空目录。
- 单一路径值继续有效，等价于只有一个元素的列表。
- 禁止空项、重复路径和包含分号的路径。
- Windows 路径统一使用正斜杠，避免反斜杠转义差异。
- 列表顺序形成稳定的逻辑卷编号 `0、1、2...`。升级后只允许在末尾追加路径，不允许删除、替换或重排已有项。
- `MEDIA_DISK_RESERVE_BYTES` 是每卷必须保留的安全空间，默认 10 GiB，必须为正整数。

宿主机部署入口解析列表并生成不纳入版本控制的 Compose 存储覆盖文件。每个目录分别挂载到 API 和初始化容器的 `/media/volumes/<编号>`，并以只读方式挂载到 Caddy 的 `/srv/media/volumes/<编号>`。Compose 不直接尝试把一个环境变量展开成多个挂载。

## 3. 存储卷身份与启动校验

每个媒体目录包含一个不公开的卷身份标记，记录逻辑卷编号和格式版本。首次启用多卷配置时，现有目录登记为卷 `0`；只创建身份标记，不移动或改写已有媒体文件。追加目录时为新卷写入对应编号的标记。

部署目录（`.env` 所在目录）另保存被 Git 忽略的 `.movie-harbor-storage-state.json`，仅记录格式版本与规范化的卷路径顺序。首次登记、末尾追加与普通重启由该记录区分；已有路径不得替换、删除或重排，已有卷缺标记时不得补写。全部候选校验通过后，先将登记写入同目录临时文件并 fsync、原子 rename、fsync 目录，再创建新卷标记；中断后失败关闭。记录缺失但已有标记或生成配置、记录损坏时拒绝启动，要求核对并恢复可信备份。仅首次登记的卷 0 允许已有媒体，新卷必须没有标记且为空。

上述两字段格式是正常登记；旧单卷的专用升级另使用第 8 节定义的 pending 格式。普通入口必须拒绝 pending，不创建或修复标记，不生成覆盖配置，也不启动 Compose。专用入口完成原卷校验和权限更新后才把 pending 转成正常登记，不能把普通重启变成自动升级入口。

部署入口与 API 启动时共同验证：

- 路径存在且指向目录，卷身份与数组位置一致。
- 各目录能够被媒体初始化容器和 UID `10001` 的 API 进程安全访问。
- 内部临时、隔离和操作目录满足现有独占权限与非符号链接要求。
- 数据库中任何媒体资产引用的卷编号都存在于当前配置。
- 同一目录不能以不同文本形式重复登记；能够可靠识别相同底层卷时也应拒绝重复登记。

缺盘、身份标记不符、顺序变化或已有资产引用未配置卷时，服务拒绝启动。系统不得自动创建一个空目录并把它误认为暂时离线的原硬盘。

初始化容器将卷根属主设为 `10001:10001`、权限设为 `0711`，仅允许其他宿主 UID 遍历已知路径并读取 `0644` 的非秘密卷标记，保证普通部署用户重启时仍可校验。内部临时、隔离和操作目录保持 `0700`，不递归放宽权限或修改媒体文件权限。

## 4. 数据模型与公开定位

`media_asset` 增加非空存储卷编号字段。迁移把全部已有资产设为卷 `0`，原 `storage_key` 及宿主机文件位置保持不变，不执行物理数据迁移。

受控存储键继续只表示卷内相对位置，例如 `video/ab/<uuid>.mp4`。完整文件定位由 `(storage_volume, storage_key)` 组成；代码不得根据当前剩余空间、数组长度或文件是否存在来猜测所属卷。

公开媒体 URL 带逻辑卷编号，例如：

```text
/media/v0/poster/ab/<uuid>.webp
/media/v2/video/cd/<uuid>.mp4
```

Caddy 只允许 `poster` 和 `video` 受控路径，并把卷编号映射到对应只读挂载。卷身份标记、上传临时区、隔离区和操作清单不得通过 `/media` 暴露。

## 5. 容量选择与并发上传

所有媒体类型使用同一分配算法，包括电影海报、电影视频、剧集海报和单集视频。

上传开始前，存储协调器读取每卷对 API 进程实际可用的剩余字节，而不是总容量。它依次：

1. 排除离线、不可写、容量查询失败或身份无效的卷。
2. 从可用字节中扣除该卷的安全保留空间和进程内尚未完成的上传预留量。
3. 排除无法容纳本次上传预估大小的卷。
4. 选择剩余可用字节最多的卷；数值相同时选择编号较小的卷。

浏览器请求提供可用长度时按其保守预留；缺少长度时按 `MAX_UPLOAD_BYTES` 预留。预留只协调当前 API 进程内的并发上传，不作为持久配额。文件完成、失败或请求取消后必须释放预留。

同一文件系统的多个逻辑卷属于同一容量域，以已验证根目录描述符的文件系统身份识别。一次分配对同域只采样一次可用容量，并共享安全保留空间与在途上传预留；同域健康候选的有效容量一致，按较小卷编号决胜。等待媒体变更锁的请求也计入该域预留，取消或完成时释放。不同容量域维持独立容量与预留。

临时文件从创建起就位于选定卷，校验通过后在同卷内原子提升到正式位置。系统不跨硬盘拆分单个文件，也不在流式写入中途切换卷。写入过程中遇到空间耗尽时，清理临时文件并返回结构化的存储空间不足错误；客户端可在释放空间后重新上传。

## 6. 替换、删除与崩溃恢复

媒体替换允许新旧文件位于不同卷：新文件先在新卷完整写入并验证，旧文件再按数据库记录的卷执行隔离。数据库同时切换卷编号和存储键。任何预提交步骤失败时删除新文件、恢复旧文件并回滚数据库。

删除电影、剧集、季或单集可能涉及多个卷。一次业务操作继续使用一个操作编号，但在各目标卷内分别创建持久清单并使用同文件系统原子重命名进行隔离。所有卷完成隔离后才能提交数据库事务；任一卷失败时恢复此前各卷已隔离的文件并回滚。

启动恢复扫描全部已配置卷的持久清单，以数据库是否仍引用 `(卷编号, 存储键)` 判断恢复原文件还是完成清理。恢复期间不得把文件复制到另一卷，也不得扫描和删除没有清单的普通孤立文件。

## 7. 错误与管理界面反馈

- 没有任何合格卷时，上传接口返回明确的结构化“媒体存储空间不足或不可用”错误。
- 单卷故障不阻止新上传选择其他健康卷，但引用故障卷中已有文件的读取、替换或删除必须失败并保留数据库状态。
- 管理界面显示中文可操作提示，不显示宿主机绝对路径、卷身份内容、存储键或底层系统错误。
- 健康检查可报告服务是否可运行；详细卷状态只允许认证后的管理接口读取。本次不新增容量仪表盘，除非后续单独设计。

## 8. 升级与运维

### 8.1 已有单卷的一次性特权升级

旧版 Compose 把媒体根设置为 UID/GID `10001:10001`、权限 `0700`，普通部署用户无法读取或创建新标记。为打破首次升级的权限死锁，增加 `tools/upgrade-media-storage.sh` 和对应 Node 实现，专门将既有单卷登记为卷 `0`。

运维顺序为：停止旧 API 写入并完成数据库与媒体的一致备份，使用原配置停止旧服务，保留 `.env` 和原 `MEDIA_HOST_DIR`，更新源码后执行 `./tools/upgrade-media-storage.sh --confirm-existing-volume-zero`。该参数是调用者对原卷 `0` 的显式确认。入口支持 `MOVIE_HARBOR_ENV_FILE`，只按文本解析环境文件，不 source 或执行其内容；只接受一个现存原目录，不接受多卷或正常登记的重复升级。

专用入口不启动应用。成功后提示用户运行 `./tools/start-compose.sh`，由普通入口生成覆盖配置并启动服务；数据库迁移在此时把已有媒体记录归到卷 `0`。最后验证原媒体能够播放、替换和删除。物理媒体始终留在原目录。

### 8.2 pending 状态与中断恢复

专用升级先原子持久保存 pending 登记，完成文件与目录 fsync 后才能调用临时 root 容器。pending 包含 `version`、单元素 `directories`，以及 `upgrade` 对象；后者记录 `kind: "legacy-volume-zero"`、随机操作 `id`、原根的 `device` 和 `inode` 字符串，以及布尔值 `markerAllowed`。专用入口严格校验格式、路径和根身份；普通入口不接纳这一格式。

首次 pending 的 `markerAllowed` 为 `false`。容器固定使用 `alpine:3.22`，只执行仓库内的升级逻辑，Docker 参数按 argv 传递，路径中的空格和 `$` 保持原义。容器先无跟随地验证根和标记，已有标记通过受控协议交给 Node 精确校验；确认标记缺失且原目录有效后，Node 先持久保存 `markerAllowed: true`，然后才授权容器原子发布卷 `0` 标记。没有发布许可时，不能因为重试就接纳凭空出现的标记；有许可的重试只接纳版本、卷号和字段均正确的标记，绝不覆盖错误内容。

每次升级与重试都验证原根仍是同一目录，且至少存在一个非符号链接的旧版结构目录：`.incoming`、`.quarantine`、`.operations`、`video` 或 `poster`。空目录、只有标记或升级临时物的目录不足以证明是旧卷，必须拒绝；入口不得自动创建宿主路径或旧版目录来绕过检查。根和标记的符号链接、特殊文件、路径身份变化、损坏登记或错误标记都必须失败关闭。

权限修改只作用于已验证的卷根与 marker：根为 UID/GID `10001:10001`、`0711`，marker 为 `0644`。不递归 chmod/chown，不改变原媒体 inode、内容、属主或权限，不改动 `.incoming`、`.quarantine`、`.operations` 的内容与 `0700` 权限。升级只管理本次操作自己的临时文件，不迁移、复制或删除媒体。

完成标记、权限和最终身份校验后，才原子写回正常的 `{version, directories}` 登记。pending 已写但 marker 未完成、marker 已完成但正常登记未提交等中断点均由同一专用命令安全重试；普通 `start-compose.sh` 始终拒绝 pending。重试必须继续核对操作标识、原路径与根身份，不接纳同路径替换的目录。登记或标记损坏时恢复可信备份，不能删除 pending 或改写标记来强制继续。

### 8.3 扩容与一致备份

扩容时停止服务，在 `MEDIA_HOST_DIR` 末尾追加新路径，初始化新卷后重新创建容器。系统不支持运行中热插拔，也不自动迁移、复制或重新平衡旧文件。移除或更换硬盘前必须由运维人员另行处理其中数据；本次不提供卷迁移工具。

数据库、部署卷登记记录和全部媒体卷仍必须作为同一个一致性备份集。只备份部分硬盘不构成完整备份。

## 9. 测试与验收

实现遵循测试驱动开发，至少覆盖：

- 单路径向后兼容，以及列表空项、重复、非法保留空间、删除和重排的拒绝行为。
- 既有数据库记录默认归属卷 `0`，升级不移动物理文件。
- 多卷剩余空间不同、空间相同、低于保留值、不可写和容量查询失败时的确定性选择。
- 海报、电影视频和单集视频使用同一算法。
- 并发上传预留、请求取消、超限、磁盘写满和临时文件清理。
- 新旧文件跨卷替换，以及电影、剧集、季和单集的跨卷删除回滚。
- 数据库提交前后中断时的多卷启动恢复。
- Caddy 只能公开对应卷的 `poster` 与 `video`，不能公开内部目录或跨卷路径。
- Compose 生成结果包含准确的 API 读写挂载和 Caddy 只读挂载。
- 真实 Linux 下旧卷属主为 `10001:10001`、根 `0700` 时，普通部署 UID 的首次普通启动失败；显式专用升级后，普通 UID 可以读取标记并运行普通启动入口，原媒体与私有目录保持不变。
- 专用升级的 pending 写入前后、marker 发布前后和最终正常登记前的中断可安全重试；普通启动不得恢复 pending，首次未授权标记、错误标记、符号链接、空挂载点、路径替换、多目录和正常登记重复升级均被拒绝。
- 专用入口支持含空格和 `$` 的原路径，安全解析 `.env`，仅调用固定临时升级容器且不启动最终 Compose 服务。
- Linux 多物理卷和 Windows 11 Docker Desktop 多盘环境中的真实上传、播放、替换、删除与重启验收。

## 10. 非目标

- 运行中热插拔或动态刷新卷列表。
- 自动迁移、重新平衡或复制已有媒体。
- RAID、纠删码、文件去重、镜像副本或硬盘故障恢复。
- 把单个媒体文件拆分到多个卷。
- 周期性扫描和删除普通孤立文件。
