# Codex 本机视频入库 MCP 设计

日期：2026-10-26

## 1. 背景与目标

Movie Harbor 已具备管理员内容管理、媒体校验与流式上传接口，也提供独立的本机视频转换 CLI。当前缺少的是一条适合 AI 对话的本机入库入口：用户希望在 Codex 桌面版中用自然语言指定视频、海报和内容元数据，由 Codex 调用本机 MCP 完成查询、创建、上传、按需转换，并在再次确认后发布。

本次增加一个仓库内独立 MCP 工程，路径固定为 `mcp/`。MCP 使用 STDIO 在用户电脑上运行，只读取明确允许的本地目录，通过受限独立密钥调用 Movie Harbor API。视频二进制不进入模型上下文，不使用 Base64 传输；MCP 从磁盘流式上传文件。

目标如下：

- 在 Codex 桌面版对话中导入电影或电视剧单集。
- 找不到内容时，能够创建电影、电视剧、季、单集和缺失题材。
- 创建前要求用户明确提供年代、题材和本地海报路径；时长从视频读取。
- MCP 创建电影或电视剧时强制绑定已经通过服务端校验的海报。
- 视频不符合网站要求时，先说明原因并询问；获得同意后调用现有本机转换模块。
- 上传完成后单独询问是否发布；只有再次获得允许后才执行发布。
- 将能力拆成原子 MCP 工具和独立公共服务，供后续批量入库、替换媒体、目录扫描等功能复用。
- 提供 `./mcp/install.sh`，把 MCP 全局安装到当前用户的 Codex 配置中。

本文是对主设计、媒体独占与发布、内容导入 CLI、视频转换 CLI、私密内容和公共函数提取规格的增量设计。冲突时只覆盖本文明确限定的 MCP 行为，不改变管理后台既有语义。

## 2. 边界与兼容性

### 2.1 保持不变的产品行为

- Movie Harbor 服务端仍不承担自动转码任务，不在 API 容器或发布镜像中安装 FFmpeg。
- 管理后台现有创建流程仍可创建没有海报的草稿；公开页面继续允许使用空白占位海报。
- MCP 入库流程使用更严格的规则：没有有效海报时，不允许通过 MCP 创建电影或电视剧。
- 现有管理员 Cookie、CSRF、普通用户权限和媒体鉴权规则保持不变。
- 现有媒体上传、替换、独占归属、乐观版本和发布校验继续作为权威规则。
- 不引入 TMDB 或其他第三方元数据服务。年代、题材、电影名、剧名和单集名由用户在对话中提供。

### 2.2 非目标

- 不把视频内容发送到模型上下文。
- 不支持 ChatGPT 网页端或云端执行环境直接读取 Mac 本地路径。
- 不自动猜测并发布内容。
- 不自动归档、删除或把已归档内容恢复为草稿。
- 不修改管理员、普通用户、密码、部署设置或数据库备份。
- 不为图像字幕增加烧录逻辑；沿用现有转换工具的拒绝规则。

```text
│   ├── tools/

│   │   ├── catalog.ts
│   │   ├── genres.ts
│   │   ├── movies.ts
│   │   ├── series.ts
│   │   ├── uploads.ts
│   │   └── publishing.ts
│   ├── services/

│   │   ├── path-policy.ts
│   │   ├── media-inspector.ts
│   │   ├── video-converter.ts
│   │   ├── upload-stream.ts
│   │   ├── generated-files.ts

│   └── schemas/

│       ├── media.ts
│       └── content.ts

```

MCP 使用 TypeScript、Node.js ESM、Model Context Protocol TypeScript SDK 和 Zod。`tools/` 只注册工具、验证输入并格式化结构化结果；共享路径策略、HTTP、FFprobe、FFmpeg、上传和错误映射放入专属 `services/`，不得建立无边界的 `utils` 或把完整入库流程塞入一个函数。

现有 `tools/video-conversion/` 保持视频探测与转换的权威实现。MCP 的 `media-inspector` 和 `video-converter` 通过稳定模块接口复用它们；如果现有模块需要新增导出，只做可复用的小型接口，不复制 FFmpeg 参数构造和进程生命周期。

现有 `tools/content-import/client.mjs` 中的流式 multipart 行为可作为契约参考。若运行时和错误模型能够保持一致，可提取最小共享上传模块；否则 MCP 在自己的 `upload-stream` 中实现同一安全边界，但不得复制业务编排器。

## 4. 原子 MCP 工具

### 4.1 本地媒体工具

- `inspect_video`：验证路径，调用 FFprobe，返回时长、容器、主视频轨、音轨、字幕轨和与网站要求的兼容性结论。只读。
- `validate_poster`：验证真实路径、普通文件、扩展名和图片内容，返回格式、大小和文件身份。只读。
- `convert_video`：按现有转换计划生成网站兼容 MP4。属于本地写操作，必须单独获得用户批准。
- `delete_generated_video`：只删除 MCP 记录为自己生成的转换文件。不得删除原视频、用户海报或任意传入路径。

### 4.2 查询工具

- `search_movies`：按规范化名称搜索电影并返回候选、状态、版本和已有元数据。
- `search_series`：按规范化名称搜索电视剧并返回候选、状态、版本和已有元数据。
- `get_series_structure`：读取季和单集结构，用于定位或确认目标。
- `list_genres`：读取题材及启用状态。

查询工具不做模糊合并。忽略首尾空白和大小写后的单一匹配可直接作为计划候选；多个候选必须返回给用户选择；零候选才进入创建计划。

### 4.3 题材、内容与海报工具

- `create_genre`：创建一个缺失题材。计划中必须提前列出；遇到同名并发冲突时重新查询并复用启用项。
- `stage_poster`：把已经本地预检的海报流式上传到服务端暂存区，返回一次性暂存凭证。
- `create_movie`：创建私密电影草稿，要求有效 `staged_poster_token`，并一次提交名称、年代、时长和题材。
- `create_series`：创建私密电视剧草稿，要求有效 `staged_poster_token`，并一次提交名称、年代和题材。
- `create_season`：在指定电视剧下创建季。
- `create_episode`：创建单集并提交集号、名称和探测到的时长。
- `update_movie_metadata`、`update_series_metadata`、`update_episode_metadata`：只修改草稿；均要求最新版本。

已有内容缺少海报、年代、题材或时长时，Codex 必须先展示修改计划并征得确认。已发布或已归档内容不自动改回草稿，MCP 返回可操作提示。

### 4.4 上传和发布工具

- `upload_movie_video`、`upload_episode_video`：仅在目标槽位为空时上传。
- `replace_movie_video`、`replace_episode_video`：目标已有视频时使用；工具名和结果必须明确表达替换，不能由普通上传隐式覆盖。
- `publish_movie`：发布电影。
- `publish_episode`：发布单集。
- `publish_series`：发布电视剧。

上传与替换继续使用服务端现有流式校验和同步替换协议。电影发布只发布电影；新电视剧单集先发布单集，再发布尚为草稿的父电视剧；已发布电视剧只发布新单集。已归档对象停止并提示管理员处理。

工具保持原子性，不提供 `execute_video_import`、`import_everything` 等巨型入口。完整流程由 Codex 根据工具描述和 MCP 提供的工作流提示依次编排。每个写工具都标记为非只读并具有清晰副作用描述，让 Codex 的写操作审批成为对话确认之外的第二道保护。

## 5. 对话工作流与确认点

典型电影流程：

```text
inspect_video
  → validate_poster
  → search_movies
  → list_genres / create_genre
  → 必要时 convert_video
  → stage_poster
  → create_movie 或更新既有电影
  → upload_movie_video / replace_movie_video
  → 询问是否发布
  → publish_movie
  → 上传成功后 delete_generated_video
```

典型单集流程：

```text
inspect_video
  → validate_poster
  → search_series / get_series_structure
  → list_genres / create_genre
  → 必要时 convert_video
  → 新剧才 stage_poster → create_series
  → 必要时 create_season → create_episode
  → upload_episode_video / replace_episode_video
  → 询问是否发布
  → publish_episode → 必要时 publish_series
  → 上传成功后 delete_generated_video
```

确认分成三个不可互相替代的阶段：

1. **转换确认：** 展示不兼容原因、轨道处理、输出位置和空间建议。
2. **入库确认：** 展示将创建、更新、替换和上传的全部对象及文件信息。
3. **发布确认：** 上传完成后单独展示要发布的电影，或单集与父电视剧。

AI 不能根据“确认入库”推断用户同意转换或发布。目标已有视频时必须明确显示替换；未得到替换确认时只能停止。

## 6. 元数据和海报规则

- 电影必须具有名称、年代、至少一个题材、视频时长和海报路径。
- 新电视剧必须具有名称、年代、至少一个题材和海报路径。
- 新单集必须具有季号、集号、用户提供的单集名称和视频时长。
- 时长由 FFprobe 读取并转换为网站接受的整数秒；探测不到可靠时长时询问用户，不伪造数值。
- 年代、题材和名称由用户提供；MCP 不根据模型记忆或视频内容擅自填充。
- 用户没有提供海报路径时，Codex 必须询问；不从视频自动截图，不调用图片生成。
- 缺失题材允许创建，但新增题材必须出现在入库确认计划中。
- 新建内容固定为私密草稿。发布后仍遵循 `is_private`；本 MCP 不自动改成公开内容。

## 7. 海报暂存与原子创建

现有管理后台先创建草稿再上传海报，无法满足 MCP 的“没有有效海报不得创建”要求。后端增加受限暂存能力：

1. `stage_poster` 使用 Tokio 流式接收文件，并执行现有 JPEG、PNG、WebP 内容校验。
2. 校验成功的文件进入媒体根目录内受控暂存区；数据库保存随机凭证的摘要、文件身份、创建主体和过期时间，不保存原始凭证。
3. 原始暂存凭证只返回一次，绑定当前 MCP 主体，只能使用一次并具有短有效期。
4. MCP 身份调用 `create_movie` 或 `create_series` 时必须传入凭证。后端在事务中锁定凭证，创建媒体资产和内容记录并建立独占归属；成功后凭证不可再次使用。
5. 数据库提交和文件最终化沿用项目现有的可恢复文件操作思想。任一步失败不得返回已创建内容；可判定的中断状态由启动恢复处理。
6. 过期暂存项只由明确的暂存记录清理，不扫描任意孤儿文件；清理范围和恢复规则必须拥有测试。

浏览器管理员会话仍可使用原有创建接口。只有独立 MCP 身份的创建请求强制 `staged_poster_token`，从而保持既有后台兼容性。

## 8. 独立密钥与授权模型

MCP 使用形如 `mhmcp_<随机值>` 的独立 Bearer 密钥。原始值只保存在本机私有凭据文件；后端配置或数据记录只保存 SHA-256 摘要，并使用常量时间比较。

后端认证中间件区分管理员会话和 MCP 主体：

- 管理员继续使用 Cookie、同源和 CSRF。
- MCP 使用 `Authorization: Bearer ...`，不使用浏览器 Cookie 或 CSRF。
- Host 和受信目标校验仍然执行。
- MCP 主体只在明确的方法与路由允许列表上通过。

允许权限：查询内容和题材、创建题材、暂存海报、创建或更新草稿、上传或替换视频、发布电影/单集/电视剧。

禁止权限：删除、归档、恢复草稿、导出、用户管理、密码、管理员会话、系统设置和任意文件读取。

错误响应和日志不得包含原始密钥、Authorization header、本机绝对文件路径或未经限制的服务端正文。密钥轮换不影响管理员密码和浏览器会话。

## 9. 本地路径与生成文件安全

默认允许根固定为：

```text
/Users/zhangdi/Downloads
```

所有本地文件工具必须：

- 要求绝对路径。
- 拒绝 NUL、目录和非普通文件。
- 解析真实路径后用路径组件关系确认仍位于允许根内，不能只做字符串前缀比较。
- 拒绝符号链接逃逸和执行期间文件身份变化。
- 在写操作前复核设备号、inode、大小和修改时间；变化时要求重新规划。
- 不把文件内容、密钥或完整绝对路径写入普通日志；面向用户的工具结果可以返回其主动提供的路径。

转换输出位于允许根内的受控子目录，名称由 MCP 生成且不覆盖已有文件。上传成功后自动删除转换输出；上传失败时保留并返回路径，供重试。`delete_generated_video` 必须验证生成记录和文件身份，不能把用户传入的任意路径当作删除目标。

## 10. 视频兼容性与转换

`inspect_video` 同时执行 FFprobe 探测和网站兼容性判断。服务端上传校验仍是最终权威，MCP 预检不能绕过它。

需要转换时，MCP 复用现有 `tools/video-conversion/`：

- H.264 且 `yuv420p` 的主视频轨可复制，否则使用 `libx264`、CRF 20、`medium`、偶数尺寸和 `yuv420p`。
- 视频标记使用 `avc1`。
- AAC 音轨复制，其他音轨转 AAC 192 kbps。
- 文本字幕转 `mov_text`；图像字幕在启动 FFmpeg 前拒绝。
- 保留显式选择的音轨、文本字幕、章节和元数据，并启用 faststart。
- 使用参数数组启动外部程序，不经过 shell，不覆盖原始文件和已有输出。
- 中断或失败清理不完整临时文件，并保留有界中文诊断。

MCP 启动时不要求 FFmpeg 必然存在；只有探测或转换相关工具被调用时才报告依赖错误。安装脚本检查 `ffmpeg` 和 `ffprobe`，缺失时停止注册并给出安装提示。

## 11. 全局安装到 Codex

仓库提供唯一入口：

```bash
./mcp/install.sh
```

安装脚本必须可重复执行，并完成：

1. 验证当前路径是完整 Movie Harbor 仓库。
2. 检查 Node.js、npm、Codex CLI、FFmpeg 和 FFprobe。
3. 在 `mcp/` 内使用锁文件安装依赖并构建生产入口。
4. 引导创建或读取本机 MCP 凭据文件，设置目录 `0700`、文件 `0600`，且不把密钥写入 Git、命令行参数或控制台日志。
5. 使用 Codex 官方 `codex mcp add` 能力注册全局 STDIO 服务 `movie-harbor`；启动命令、入口和工作目录使用绝对路径。
6. 配置 Movie Harbor 地址、凭据文件和允许目录。长时间转换与上传使用扩展工具超时，写工具保持需要批准。
7. 使用 `codex mcp list` 验证注册结果，并提示用户在 Codex 桌面设置的 MCP servers 中重启该服务。

安装脚本不得整体覆盖 `~/.codex/config.toml`，不得删除或改写其他 MCP、模型、权限或项目配置。已有 `movie-harbor` 条目由脚本识别并只更新该命名项；无法安全更新时停止并给出人工处理说明。

独立密钥的服务端摘要仍属于 Movie Harbor 部署配置。安装脚本可以在交互确认后为当前本地 `.env` 生成并写入专用字段，但不能自动重启整个 Compose、修改其他环境变量或假定远程部署路径。目标是远程 Movie Harbor 时，脚本只输出不含原始密钥的摘要配置步骤，等待用户完成服务端配置后再验证连接。

## 12. 错误、恢复和幂等

- 每个工具返回稳定错误分类和简短中文说明，不返回未过滤的响应头或完整底层异常。
- 查询和发布的重复调用保持幂等；创建遇到唯一冲突后重新读取，不盲目重建。
- 所有更新和上传使用服务端返回的最新版本。`409` 时停止并要求重新查询，不自动覆盖并发修改。
- 工具调用成功后返回足够的 ID、版本和下一步信息，Codex 不依靠猜测继续。
- 原子工具允许从失败步骤重试，不要求从头执行全部流程。
- 已经创建的私密草稿在后续视频上传失败时保留，供重试；海报原子创建保证该草稿已经具有有效海报。
- 转换成功但上传失败时保留转换文件；重新上传成功后再删除。
- 发布失败不撤销已成功上传的草稿和媒体。

## 13. 测试策略

实现遵循测试驱动开发，先写失败测试并确认失败原因，再实现最小行为。

### 13.1 后端与数据库

- 正确密钥只在允许路由生效；缺失、错误和已轮换密钥拒绝。
- MCP 密钥不能调用删除、归档、用户、导出、密码和系统接口。
- 管理员 Cookie/CSRF 和普通用户认证回归不变。
- 暂存海报拒绝伪造 MIME、损坏图片、超限、重复使用、过期和其他主体凭证。
- 创建电影或电视剧时，MCP 身份缺少有效暂存海报必然失败且不创建内容。
- 暂存消费、内容创建、媒体归属和题材关系满足事务、版本和恢复规则。
- 未使用暂存项只在明确记录范围内清理，不扫描媒体目录。
- 发布顺序、幂等和现有发布校验保持不变。

### 13.2 MCP 单元与集成测试

- 路径越界、符号链接逃逸、非普通文件和执行前文件变化被拒绝。
- 视频探测、海报验证、兼容性结论和时长映射正确。
- 每个 MCP 工具有独立 schema、稳定结果和副作用注解。
- 缺失题材创建、同名候选、重复季集、停用题材和版本冲突正确处理。
- multipart 上传分块读取、处理背压、远端中断和超时，不把大视频载入内存。
- 转换必须经单独工具调用；图像字幕、编码器缺失、中断和磁盘失败保持现有安全语义。
- 删除生成文件只作用于 MCP 记录的文件，上传失败不删除，成功后删除。
- 发布工具独立于创建和上传工具，不能由一次复合工具隐式触发。

### 13.3 安装与端到端

- 在隔离 HOME/CODEX_HOME 下验证首次安装、重复安装和更新，只修改 `movie-harbor` MCP 项。
- 验证缺少依赖、已有冲突配置、私有凭据权限和路径含空格。
- 验证 `codex mcp list` 能发现服务，STDIO 初始化和工具列表成功。

- 不使用生产数据目录，不读取或提交用户真实视频、海报和密钥。

## 14. 完成标准

- `mcp/` 是可独立构建、测试和运行的本机 MCP 工程。
- 对外能力由原子工具组成，共享能力位于有明确所有者的独立模块。
- Codex 能通过全局 STDIO 配置发现工具，并对写工具执行审批。
- 视频与海报只从允许目录读取，视频始终流式上传，不进入模型上下文。
- 新内容缺少有效海报时无法通过 MCP 创建。
- 缺失题材、电影、电视剧、季和单集可按确认计划创建。
- 不兼容视频只有在用户同意后转换；原文件永不修改，转换产物按约定清理。
- 发布只有在上传成功并获得独立确认后执行。
- `./mcp/install.sh` 可安全重复运行且不会覆盖其他 Codex 全局配置。
- 相关 Rust、Node、MCP、安装和隔离端到端验证全部通过。
