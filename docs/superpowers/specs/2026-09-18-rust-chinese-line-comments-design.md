# Rust 中文行注释设计规格

日期：2026-09-18

## 1. 目标

为 `backend/src/**/*.rs` 中的生产 Rust 代码补充中文行注释，使维护者能够同时理解业务规则和技术实现原因。注释应优先解释代码为何存在、保护了什么约束，以及关键实现如何保证事务、并发、安全和文件一致性，而不是逐字复述代码。

本次工作只调整注释，不改变运行行为、接口、数据结构、数据库查询或格式结构。

## 2. 范围

包含：

- `backend/src/` 下全部 Rust 生产代码。
- 现有英文 `//` 行注释的中文转换。
- 非简单函数的入口说明。
- 关键业务规则和技术边界附近的块级行注释。

不包含：

- `backend/tests/` 测试代码。
- `backend/migration/` 数据库迁移代码。
- `///`、`//!` 等 Rust 文档注释建设。
- 对导入、简单字段映射、显而易见的构造器、普通赋值或语法本身进行解释。
- 任何功能、接口、数据模型或测试行为变更。

## 3. 注释形式

- 统一使用中文 `//` 行注释。
- 注释放在所解释的函数或代码块之前。
- 单个说明通常控制在 1–3 行；只有复杂不变量确实需要时才允许更长。
- 术语、类型名、协议名和代码标识保持原文，例如 `RepeatableRead`、`CSRF`、`Argon2`、`sync_all`。
- 现有英文行注释必须转换成中文，同时保留其业务和技术含义。

## 4. 注释内容标准

### 4.1 业务解释

注释应在代码无法直接表达时说明：

- 生命周期状态为什么限制编辑、发布、归档或删除。
- 电影、剧集、季和单集之间的父子约束。
- 已停用题材、公开可见性和导出字段的业务语义。
- 媒体资产独占、同步删除和中断恢复的业务保证。
- 初始化管理员、会话撤销和错误语义的产品规则。

### 4.2 技术解释

注释应重点说明：

- 数据库事务范围、隔离级别和一致快照的用途。
- 锁顺序、乐观锁和并发重检如何避免竞态或死锁。
- 认证、CSRF、限流、常量时间处理和敏感信息保护。
- 受控存储键、目录能力、路径校验和符号链接防护。
- Tokio 流式写入、临时文件、原子提升、`fsync` 和故障恢复。
- 媒体格式解析中的边界检查、资源上限和拒绝策略。
- 错误映射、幂等性和失败关闭策略。

### 4.3 避免的注释

不得添加以下低价值内容：

- 复述下一行代码的操作，例如“给变量赋值”“调用函数”。
- 与变量名、类型名完全重复的信息。
- 无法由当前实现保证的承诺。
- 对未来功能的猜测或与当前需求无关的 TODO。
- 大段教程式说明，导致主要逻辑被注释淹没。

## 5. 模块执行顺序

按以下模块分批理解和处理：

1. 应用入口、配置、公共内容规则和路由参数。
2. 管理员认证、会话、CSRF 和登录限流。
3. 管理内容列表、内容导出、公开目录和题材管理。
4. 电影与剧集的仓储、服务和路由。
5. 媒体路径、删除、存储、上传与格式校验。
6. SeaORM 实体和简单 DTO：仅在存在非显然领域语义时补充，不机械覆盖。

每批必须先阅读完整函数上下文，再决定注释位置和内容。不得通过关键词替换或固定模板批量生成注释。

## 6. 验收标准

- `backend/src/` 中原有英文 `//` 行注释已统一转换为中文。
- 非简单函数的关键入口具备用途或机制说明。
- 事务、并发、安全、文件一致性和恢复逻辑具备与实现一致的中文说明。
- 简单代码没有被机械注释，代码可读性不因注释密度下降。
- Git 差异只包含注释和必要的格式变化，不包含行为变更。
- 以下验证全部通过：

```bash
docker compose -f docker-compose.test.yml up -d postgres
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
TEST_DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:55432/movie_harbor_test' cargo test --workspace
git diff --check
```

由于本次仅调整注释，不新增行为测试；现有编译、静态检查和完整 Rust 测试用于证明代码行为未受影响。
