# 网站兼容 MP4 转换 CLI 设计

日期：2026-10-01

## 1. 背景

Movie Harbor 的上传接口只接收经过结构化内容校验的视频。当前支持 WebM，以及使用 H.264（`avc1`/`avc3`）或 HEVC（`hvc1`/`hev1`）视频轨的 MP4；服务端不执行自动转码。管理员仍可能持有 MKV，或持有因视频、音频、像素格式、字幕封装等原因而不适合网页播放的 MP4，需要在上传前手动转换。

本功能提供源码仓库内的独立命令行工具。它只处理本机单个文件，不接入网站后端、数据库、上传 API 或媒体存储，也不改变“服务器不自动转码”的产品边界。

## 2. 目标

- 将单个 MKV 或 MP4 转换为适合 Movie Harbor 上传和网页播放的 MP4。
- 生成 H.264、`yuv420p` 视频，保留原始分辨率；只有奇数宽或高需要缩小 1 像素。
- 保留全部音轨；AAC 直接复制，其他音频逐轨转为 AAC。
- 保留全部文本字幕，并逐轨转换为 MP4 的 `mov_text`。
- 在写输出前识别图像字幕并明确拒绝，不能静默丢失字幕。
- 对已经兼容的媒体流使用流复制，避免不必要的质量损失和处理时间。
- 使用临时文件和最终原子改名，失败或中断不留下被误认为成功的输出。
- 提供中文进度、结果与可执行的错误提示。

## 3. 非目标

- 不把转码加入管理后台、API 服务、Docker Compose 或媒体上传流程。
- 不支持目录递归、批量队列、并行任务或远程 URL。
- 不覆盖已有输出文件，也不提供强制覆盖选项。
- 不执行图像字幕 OCR，不把字幕烧录进画面。
- 不保留附件、封面视频或其他数据轨。
- 不承诺无损转换，也不自动计算目标码率或限制输出分辨率。
- 不把 FFmpeg 或 FFprobe 二进制打包进仓库或半离线应用归档。

## 4. 命令行契约

工具沿用仓库现有 Node.js CLI 形态，由根工作区脚本启动：

```bash
npm run convert:video -- "/videos/movie.mkv"
npm run convert:video -- --help
```

第一版只接受一个位置参数。输入必须是本机普通文件，扩展名不区分大小写且只能为 `.mkv` 或 `.mp4`。

输出与输入位于同一目录，名称固定为 `<输入基本名>.movie-harbor.mp4`。例如 `/videos/movie.mkv` 生成 `/videos/movie.movie-harbor.mp4`。如果该路径已经存在，工具在媒体探测和转码前退出，不修改已有文件。

退出码约定：

- `0`：转换成功或显示帮助。
- `2`：命令行参数不合法。
- `1`：依赖检查、媒体探测、轨道校验、转码、清理或最终改名失败。

## 5. 组件边界

实现拆分为四个职责单一的单元：

1. **CLI 入口**：解析参数、校验输入和目标路径、串联流程、打印中文消息并设置退出码。
2. **媒体探测器**：以参数数组直接启动 FFprobe，解析 JSON，输出稳定的内部媒体描述；不通过 shell 拼接命令。
3. **转换规划器**：把媒体描述转换为纯数据形式的 FFmpeg 参数计划；负责轨道选择、复制或转码决策以及图像字幕拒绝。
4. **进程与文件执行器**：启动 FFmpeg、解析进度、转发中断、管理临时文件并在成功后原子改名。

规划器不访问文件系统或启动进程，因此可以用手工构造的媒体描述验证全部参数决策。CLI 与执行器通过临时目录中的真实测试替身进程验证外部边界，不在生产代码中加入仅供测试调用的方法。

## 6. 媒体探测与轨道选择

FFprobe 使用 JSON 输出读取格式时长和流信息，至少包括：轨道索引、类型、编码名称、像素格式、轨道 disposition、语言和标题标签。

轨道选择规则：

- 选择第一条 `codec_type=video` 且不是 `attached_pic` 的轨道作为主视频。
- 没有主视频时拒绝转换。
- 只输出这一条主视频；其余视频轨和封面视频不输出。
- 按输入顺序保留全部 `codec_type=audio` 轨道；允许没有音轨。
- 按输入顺序处理全部 `codec_type=subtitle` 轨道；允许没有字幕。
- 保留输入的全局元数据和章节。
- 不映射附件和数据轨。

已知图像字幕至少包括 PGS（`hdmv_pgs_subtitle`）、VobSub/DVD（`dvd_subtitle`）、DVB（`dvb_subtitle`）和 XSUB（`xsub`）。只要发现任意图像字幕，工具就在启动 FFmpeg 前失败，错误中列出输入轨道索引和编码名称。未知字幕编码不被静默丢弃；工具尝试按文本字幕转换，若 FFmpeg 不支持则以转码失败退出并展示诊断摘要。

## 7. 转换规则

### 7.1 视频

当主视频同时满足以下条件时直接复制：

- 编码为 H.264；
- 像素格式为 `yuv420p`。

其他视频统一使用 `libx264` 转码：

- 质量：CRF 20；
- 预设：`medium`；
- 像素格式：`yuv420p`；
- 输出样本项：H.264/AVC；
- 分辨率：保持原尺寸；宽或高为奇数时，使用确定性缩放表达式把对应边缩小 1 像素。

工具不设置固定 H.264 level，不放大或主动压低偶数尺寸的视频。

### 7.2 音频

全部输入音轨均按原顺序映射：

- AAC 音轨使用流复制。
- 非 AAC 音轨使用 FFmpeg 原生 AAC 编码器，目标码率为每轨 192 kbps。
- 不主动下混声道；由编码器在可表示范围内保留输入声道布局。
- 轨道语言、标题和 disposition 由 FFmpeg 的流映射与元数据映射保留。

复制和转码决策按输出音轨序号分别设置，不能用一个全局音频编码选项覆盖全部轨道。

### 7.3 字幕与容器

- 所有文本字幕按原顺序映射并转换为 `mov_text`。
- 输出保留全局元数据和章节。
- 输出启用 MP4 `faststart`，把播放所需元数据移动到文件前部。
- FFmpeg 使用明确的 `-map` 选项，不能依赖自动流选择。

## 8. 文件安全与进程生命周期

工具在最终输出所在目录创建唯一的临时 `.mp4` 文件。FFmpeg 只写该临时路径；仅当进程以成功状态退出且临时文件存在时，才把它原子改名为最终路径。

执行期间遵守以下规则：

- 所有外部程序均以可执行文件名和参数数组启动，不使用 shell。
- 启动前检查 FFmpeg 与 FFprobe 是否可执行；只有转换计划需要某编码器时，才验证对应编码器可用。
- FFmpeg 通过机器可读进度输出报告处理时间，工具结合探测到的有效时长显示百分比；缺少可靠时长时显示已处理时间而不伪造百分比。
- FFmpeg 的诊断写入有界缓冲区；正常运行不持续刷出完整调试日志，失败时展示最后一段诊断。
- 收到 `SIGINT` 或 `SIGTERM` 时，把信号转发给子进程，等待其结束并清理临时文件。
- 探测、转码、改名或清理失败都不得删除或修改输入文件和已有最终输出。

## 9. 错误处理

错误消息使用中文，并包含失败对象和下一步建议。至少区分：

- FFmpeg 或 FFprobe 未安装或不可执行；
- 当前 FFmpeg 缺少 `libx264`、AAC 或 `mov_text` 等本次计划需要的编码器；
- 输入不存在、不是普通文件或扩展名不支持；
- 输出已存在；
- FFprobe 输出无效或媒体没有主视频；
- 图像字幕不受支持；
- FFmpeg 因编码参数、磁盘空间或输入损坏而失败；
- 临时文件清理或最终原子改名失败。

错误信息不得把特殊文件名重新拼接成可复制执行的未转义 shell 命令，也不得隐藏 FFmpeg 返回的关键诊断。

## 10. 测试策略

实施遵循测试驱动开发。自动化测试使用 Node 内置测试框架，不要求测试机安装真实 FFmpeg：

1. 规划器表格测试覆盖 H.264/`yuv420p` 复制、其他视频转 H.264、全部音轨逐轨复制或转 AAC、全部文本字幕转 `mov_text`、封面视频排除和显式轨道映射。
2. 图像字幕测试覆盖 PGS、VobSub、DVB 和 XSUB，确认规划阶段失败且不会启动 FFmpeg。
3. CLI 集成测试在临时 `PATH` 中放置可执行的 FFprobe/FFmpeg 测试替身，实际启动 CLI，验证中文文件名、空格和 shell 元字符始终作为单个参数传递。
4. 文件生命周期测试验证目标存在时不覆盖、FFmpeg 失败和中断时删除临时文件、成功时才生成最终文件。
5. 依赖与异常测试覆盖缺少外部程序、无视频轨、异常 JSON、未知字幕转换失败和有界诊断输出。

测试断言可观察的退出码、参数、输出文件和清理副作用，不通过搜索生产源码文本验证实现细节。

## 11. 文档与项目入口

- 根 `package.json` 增加 `convert:video` 和该工具的聚焦测试脚本。
- 新增视频转换使用指南，说明 FFmpeg/FFprobe 依赖、命令、固定输出命名、编码参数、字幕限制、空间需求和上传前复核方式。
- README 的功能与指南索引链接到该文档，同时继续明确网站服务本身不自动转码。

## 12. 验收标准

- 单个 MKV 或 MP4 能通过约定命令生成固定命名的 MP4。
- 生成文件只有一条主视频轨，视频为 H.264/`yuv420p` 或由满足条件的同类输入直接复制。
- 输入的全部音轨和全部文本字幕按顺序保留，分别为 AAC 与 `mov_text`。
- 任意图像字幕都会在 FFmpeg 转码开始前触发包含轨道信息的错误。
- 已存在的目标永不被覆盖；失败或中断不留下最终文件或临时半成品。
- 中文、空格和 shell 元字符文件名可安全处理。
- 工具不接触数据库、API 或媒体库，不给生产服务增加 FFmpeg 运行时依赖。
- 工具聚焦测试、根 Node 契约测试和 `git diff --check` 通过。
