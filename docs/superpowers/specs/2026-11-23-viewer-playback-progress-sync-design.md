# 普通用户观看进度与跨设备同步设计

日期：2026-11-23

## 背景与目标

Movie Harbor 已有独立普通用户账号和浏览器本地观看进度，但登录用户的进度仍只保存在当前浏览器。换设备、清理浏览器数据或更换浏览器后，电影续播位置、剧集最近观看单集和“继续观看”都会丢失。

本阶段把登录普通用户的观看进度保存到服务端，并继续保留浏览器本地副本作为离线和瞬时失败时的缓存。登录账号可跨设备恢复电影或单集位置，完成单集后在其他设备继续时定位到下一集，并能从首页主动移除不想保留的记录。匿名访客仍只使用本地进度；登录后发现匿名记录时由用户选择是否合并，系统不得自动把共享设备上的匿名历史归属给当前账号。

## 范围

### 本阶段实现

- 登录普通用户的电影和单集观看进度服务端持久化。
- 同一账号跨设备读取与合并，以客户端记录时间较新的记录为准。
- 浏览器本地缓存与服务端同步失败时的非阻塞降级；播放本身不得因进度服务故障而失败。
- 播放结束自动保存“已看完”状态；已看完电影不再进入“继续观看”。
- 已看完单集作为剧集最近观看位置；存在下一集时，“继续观看”和未指定单集的剧集播放入口定位下一集。
- 首页“继续观看”可移除单条电影或整部剧集记录；移除剧集时删除该剧集下当前用户的全部单集进度。
- 剧集最近单集游标独立同步；只选择单集但尚未产生播放位置时，换设备后仍能定位该集。
- 登录后检测匿名本地记录，并明确提供“合并”和“暂不合并”选择；只有合并成功后才清除匿名副本。
- 用户删除时通过外键级联删除其全部观看进度；电影或单集永久删除时级联删除对应记录。

### 本阶段不实现

- 管理员查看普通用户观看历史。
- 收藏、想看、评分、评论、自定义片单或推荐算法。
- 独立的完整观看历史页面和按日期浏览。
- 匿名用户的服务端标识、匿名跨设备同步或浏览器指纹。
- 播放器自动开始播放下一集；本阶段只自动定位，不绕过浏览器播放策略。
- 按设备展示或解决多个设备同时播放的冲突界面。

## 数据模型

新增 `viewer_playback_progress` 表：

- `id UUID` 主键。
- `viewer_user_id UUID NOT NULL`，外键指向 `viewer_user(id)`，删除用户时级联删除。
- `movie_id UUID`，可空，外键指向 `movie(id)`，删除电影时级联删除。
- `episode_id UUID`，可空，外键指向 `episode(id)`，删除单集时级联删除。
- `position_seconds DOUBLE PRECISION NOT NULL`，必须大于等于 0 且为有限值。
- `duration_seconds DOUBLE PRECISION NOT NULL`，必须大于 0 且为有限值。
- `completed BOOLEAN NOT NULL DEFAULT FALSE`。
- `client_updated_at TIMESTAMPTZ NOT NULL`，用于跨设备合并。
- `updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`，记录服务端实际写入时间。

约束：

- `movie_id` 与 `episode_id` 必须且只能设置一个。
- 同一用户与同一电影最多一条记录；同一用户与同一单集最多一条记录，使用两个部分唯一索引保证。
- 电影、单集和用户的永久删除都清理关联进度，不保留不可访问目标的悬空记录。
- 数据库约束拒绝 `NaN`、无穷值、负位置、位置大于时长和非正时长，后端在进入数据库前也做同样校验并返回 `400`。

不冗余保存 `series_id`。单集所属剧集通过 `episode → season → series` 关系取得，避免移动或删除层级后出现不一致。

新增 `viewer_series_cursor` 表，保存当前用户每部剧集最近选择的单集：

- `viewer_user_id UUID NOT NULL`、`series_id UUID NOT NULL` 和 `episode_id UUID NOT NULL` 均使用级联外键。
- `client_updated_at TIMESTAMPTZ NOT NULL` 参与跨设备冲突处理。
- 以 `(viewer_user_id, series_id)` 为主键；后端在同一写入事务内查询并确认 `episode_id` 确实属于 `series_id`，数据库外键继续保证三个标识均存在。

新增 `viewer_playback_removal` 表，保存永久冲突截止时间：

- 可表示 `movie`、`episode` 或 `series` 三种删除范围，三个目标外键必须且只能设置一个。
- 同一用户和同一目标最多一条，以 `removed_at TIMESTAMPTZ NOT NULL` 保存用户最初执行移除的客户端时间。
- 墓碑不按时间清理；只有用户或对应内容永久删除时级联删除。这样长期离线设备的旧记录也不能在稍后重新出现。
- 后续观看产生的客户端时间严格晚于墓碑时，进度或游标可以重新建立；迟到或重复送达的旧删除不能覆盖这条较新进度。

## API

所有接口都位于现有普通用户认证中间件后，写请求沿用同源与 CSRF 校验，响应使用 `Cache-Control: no-store`。

```text
GET    /api/viewer/progress
POST   /api/viewer/progress/merge
PUT    /api/viewer/progress/{kind}/{id}
DELETE /api/viewer/progress/{kind}/{id}
```

进度写入的 `kind` 只允许 `movie` 或 `episode`；删除还允许 `series`，用来表达首页移除整剧。读取响应按 `client_updated_at DESC, id` 稳定排序，并返回：目标类别、目标 ID、单集所属剧集 ID、位置、时长、完成状态和客户端更新时间，同时返回当前仍有效的剧集游标。

单条写入和批量合并使用同一输入：

```json
{
  "position_seconds": 125.5,
  "duration_seconds": 600,
  "completed": false,
  "updated_at": "2026-11-23T12:30:00.000Z"
}
```

批量合并最多接收 500 个进度、游标和删除操作的总和，且同一请求中不允许重复目标。每个进度、游标和删除都携带原始客户端时间；离线重试不得改用重试时刻。服务端只在传入时间严格晚于同目标现有进度与适用墓碑时覆盖；相同或更旧的操作保持服务端版本。客户端时间超过服务端当前时间 24 小时的输入返回 `400`，避免错误设备时钟长期压制其他设备。

批量合并按条目返回 `accepted`、`ignored` 或 `rejected` 结果，并同时返回合并后的规范快照。已归档、永久删除、无视频或关系失效的旧缓存条目标记为 `rejected/not_found`，不拖累同批其他有效条目；前端从本地缓存移除这些不可恢复条目。只有数据库或事务故障才使整个请求失败并保留全部本地待同步数据。匿名合并时，只有 `accepted`、`ignored` 或明确 `not_found` 的条目可以从匿名空间清除。

写入前必须确认目标当前可由普通用户播放：电影必须已发布且有视频；单集及所属剧集都必须已发布且单集有视频。不存在、草稿、归档或关系无效统一返回 `404`。读取列表也过滤当前已不可播放的记录，但不删除它们；内容重新发布后原进度可以恢复。

删除请求必须提交 `removed_at`。删除 `movie` 只清除该电影，删除 `episode` 只清除该单集，供“从头播放”使用；删除 `series` 清除该剧集下的全部单集进度和游标，供首页“从继续观看移除整部剧集”使用。三种删除都会写入对应范围墓碑；不存在的进度仍返回成功，重复提交同一时间保持幂等。

## 前端同步与冲突规则

本地进度格式升级为版本 2，新增 `completed`、带时间的剧集游标和删除墓碑。读取版本 1 时按 `completed: false` 迁移进度；旧 `recentEpisodes` 指针使用对应单集进度时间，缺少进度时使用 Unix 纪元作为最低优先级游标。这样本机仍能定位旧单集，又不会覆盖服务端已有的更新游标。匿名空间与每个 `viewerId` 的空间继续隔离。

普通用户会话恢复或登录成功后：

1. 读取当前账号本地记录。
2. 调用批量合并接口；服务端按时间选择每个目标的新记录。
3. 用服务端返回的规范记录替换该账号本地缓存。
4. 若匿名空间存在有效记录，显示一次非阻塞合并提示。
5. 用户选择合并时，将匿名记录与账号本地记录一起批量提交；成功后清空匿名空间，失败则保留匿名记录并允许稍后重试。

播放期间仍先写本地缓存，并以最多每 5 秒一次、暂停、离页和结束等现有时机尝试写服务端。网络失败只保留本地记录，不中断播放；下一次会话恢复、窗口重新聚焦或后续保存时再次合并。迟到响应不得覆盖客户端时间更晚的本地记录，也不得影响已经切换的账号。

从头播放、移除电影或移除整剧都会先写本地墓碑并立即隐藏记录。若服务端请求失败，后续同步使用最初删除时间重试；迟到删除与新播放继续按同一时间规则合并。服务端规范快照不必暴露墓碑内容，但必须已经应用墓碑过滤；前端只用返回的有效进度和游标刷新可见缓存，同时保留尚未确认的本地操作。

## 播放和“继续观看”行为

- 电影或单集在距结尾不足 30 秒前仍保存可恢复位置；播放真正触发 `ended` 时才标记完成，避免短片或拖动到结尾被误判。
- 已完成电影不显示在“继续观看”。再次从头播放时写入新的未完成记录。
- 剧集播放入口优先使用最新游标；“继续观看”卡片取该剧集中 `client_updated_at` 最新的有效单集进度。若该单集已完成且存在下一集，卡片和游标定位下一集；若已是最后一集，整部剧集不显示在“继续观看”。
- 首页最多仍展示 6 张卡片，顺序按最终选中记录的客户端更新时间倒序。
- “移除”按钮必须是独立按钮，不能嵌套在播放链接中；操作期间禁用，成功后立即移除卡片，失败时保留并显示可重试错误。

## 安全与隐私

- 进度接口只使用当前普通用户会话中的 `viewer_user_id`，不接受客户端指定用户。
- 管理员 Cookie 不授予读取进度能力，普通用户也不能读取其他用户记录。
- 不可访问内容统一表现为不存在，不返回标题、状态或私密属性。
- 所有响应禁止共享缓存；请求体数量和数值范围受限，避免批量同步成为放大入口。
- 前端日志和错误界面不得输出 Cookie、CSRF 令牌或完整观看记录。

## 迁移、兼容与失败处理

- 新迁移只新增表和索引，不改写已有电影、剧集、单集或账号数据。
- 回滚迁移只删除观看进度表和索引，不影响内容与账号。
- 旧前端仍可继续使用本地进度；新后端接口不会改变目录、详情或媒体授权响应。
- 服务端不可用、合并失败或单条保存失败时继续允许播放，并保留本地待同步状态。
- 会话失效时停止服务端同步，保留按账号隔离的本地缓存；重新登录同一账号后再同步。

## 验收标准

- 同一普通用户在设备 A 保存电影位置后，设备 B 登录能恢复该位置。
- 两台设备对同一内容分别提交不同时间的记录时，较新的客户端时间胜出；过远未来时间被拒绝。
- 匿名记录不会在登录时自动进入账号，只有用户确认且同步成功后才从匿名空间删除。
- 播放完成单集后，另一设备的“继续观看”定位下一集；完成最后一集后不再显示该剧集。
- 从首页移除电影或剧集后，旧设备的更早记录不会把它恢复。
- 草稿、归档、被删除或无视频目标不能通过进度接口泄露状态，也不会显示在“继续观看”。
- 进度接口拒绝未登录、缺少 CSRF、跨来源、非法数值、重复批量目标和超过 500 条的请求。
- 进度服务故障不阻止内容加载和视频播放。
