# HEVC MP4 上传与中文错误提示设计

日期：2026-09-14

## 1. 背景

Movie Harbor 当前只对 MP4 中的 H.264（`avc1`/`avc3`）视频轨道执行内容校验。真实文件 `已加速- L餐馆 (2026).TC1080P.mp4` 是结构有效的 MP4，包含 `hvc1` HEVC Main 1080p 视频和 AAC 音频，因此被现有 H.264 专用校验器拒绝，并返回 `media content does not match its declared type`。

管理后台直接拼接后端英文错误信息，导致管理员看到“操作失败：media content does not match its declared type”，无法清楚理解失败原因。

## 2. 目标

- 接受结构有效、使用 `hvc1` 或 `hev1` 视频样本项的 HEVC MP4。
- 保留 MP4 容器、box 边界、采样表、媒体数据范围和长度前缀 NAL 的校验。
- 保持现有 H.264 深度校验及其安全边界不变。
- 为内容与声明类型不匹配提供稳定 API 错误码，并在管理后台显示明确中文提示。
- 使用小型、可重复的 HEVC fixture 覆盖真实上传入口，不把用户的大型视频加入仓库。

## 3. 非目标

- 不允许仅凭 `.mp4` 扩展名或客户端 MIME 放行文件。
- 不接受任意未知 MP4 视频编码。
- 不在服务端调用 FFmpeg、`ffprobe` 或浏览器进程。
- 不执行自动转码、转封装或媒体修复。
- 不承诺 HEVC 在所有浏览器、操作系统和硬件上均可播放。
- 不修改数据库结构、媒体资源 API 路径或部署拓扑。

## 4. MP4 校验设计

### 4.1 编码配置

现有 MP4 解析流程继续定位视频轨道的 `stsd` 样本描述。校验器根据视频样本项选择编码配置：

- `avc1`/`avc3`：继续要求并解析 `avcC`，沿用 H.264 SPS、PPS、尺寸和切片语义校验。
- `hvc1`/`hev1`：要求存在结构完整的 `hvcC`，读取 NAL 长度字段宽度，并验证配置数组及其边界。
- 其他视频样本项：继续拒绝。

HEVC 配置必须至少包含有效的 VPS、SPS 和 PPS 数组。每个数组与 NAL 单元的声明长度必须位于 `hvcC` box 内，禁止截断、越界或无法完整消费的尾部数据。

### 4.2 采样数据

现有 `stts`、`stsc`、`stsz`、`stco`/`co64` 一致性和 `mdat` 范围校验保持不变。H.264 与 HEVC 都必须证明每个声明样本完全位于已解析的 `mdat` 中。

HEVC 样本按 `hvcC` 声明的长度字段宽度逐个读取 NAL：

- NAL 长度必须非零且不得越过样本边界。
- NAL 头必须完整，`forbidden_zero_bit` 必须为零，`nuh_temporal_id_plus1` 必须非零。
- 每个样本必须包含至少一个 VCL NAL（NAL 类型 0 到 31）。
- 解析结束时必须恰好消费完整样本，不允许残缺长度前缀或多余字节。

这允许目标 HEVC 文件通过，同时不把 MP4 校验降级为文件头或扩展名检查。

## 5. 错误响应与中文提示

后端遇到 `MediaError::ContentMismatch` 时继续返回 HTTP `415 Unsupported Media Type`，响应增加稳定错误码：

```json
{
  "error": "media content does not match its declared type",
  "code": "media_content_mismatch"
}
```

英文 `error` 保留用于 API 兼容和诊断；管理后台不得再直接向用户展示该英文字符串。电影和剧集编辑器识别 `media_content_mismatch` 后显示：

```text
上传失败：文件内容与声明的类型不匹配，请确认文件格式正确且未损坏。
```

其他未识别错误继续使用现有回退行为。本变更不顺带本地化所有后端错误。

## 6. 测试策略

实施遵循 TDD：

1. 先添加微型 `hvc1` 和 `hev1` HEVC MP4 上传用例，确认现有实现以内容不匹配失败。
2. 添加损坏 `hvcC`、缺失 VPS/SPS/PPS、非法 NAL 头、样本越界及未知编码样本项的拒绝测试。
3. 添加路由测试，确认内容不匹配返回 HTTP 415、英文诊断信息和 `media_content_mismatch` 错误码。
4. 添加电影与单集编辑器测试，确认该错误码显示约定的中文提示。
5. 实现最小 HEVC 分支并运行媒体上传、后端、前端及静态检查回归。
6. 使用用户提供的真实 HEVC 文件通过同一校验入口做只读验证，不复制、移动或提交该文件。

## 7. 验收标准

- 目标 `hvc1` HEVC Main/AAC MP4 通过后端内容校验并可完成上传。
- 合法 `hev1` fixture 同样通过。
- H.264、WebM 和海报的既有合法输入继续通过。
- 损坏、截断、越界、未知编码或缺少必要 HEVC 参数集的 MP4 继续被拒绝。
- 电影视频和单集视频上传遇到内容不匹配时显示约定的中文提示，不再展示英文原文。
- 不新增运行时 FFmpeg 依赖，不修改数据库，不把用户视频纳入版本库。
