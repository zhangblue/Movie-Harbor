# Movie Harbor README 重构设计

## 目标

将根目录 `README.md` 重构为同时服务自托管部署者和源码开发者的入口文档。读者应能在首次阅读时快速理解项目用途，并分别完成生产部署、本地开发、源码打包、配置检查和测试验收。

## 读者与阅读路径

- 自托管部署者：工程概览 → 环境要求 → Docker Compose 快速启动 → 配置表 → HTTPS 与安全 → 备份恢复 → 升级与运维。
- 开发者：工程概览 → 架构与目录 → 本地依赖 → 数据库启动 → 后端和前端开发运行 → 源码构建 → 测试与 E2E。

README 开头提供导航和两条快速路径，避免两类说明互相穿插。

## 内容结构

1. 工程介绍、核心能力和技术架构。
2. 环境要求与端口约定。
3. 生产环境快速启动。
4. 本地开发环境初始化与服务启动顺序。
5. 前端、后端和 Docker 镜像打包方法及产物位置。
6. 环境变量参考表，说明必填项、默认值、作用范围和安全要求。
7. 运行、健康检查、日志、停止与升级命令。
8. 单元测试、构建检查和 Playwright 跨服务验收。
9. 媒体格式、目录权限、公开 URL、可信代理和 HTTPS 边界。
10. 数据库与媒体卷的一致备份、恢复和历史测试 schema 清理。
11. Demo、目录结构、常见问题和首版非目标。

## 准确性约束

- 所有命令必须来自当前仓库实际存在的脚本、Cargo workspace、Compose 服务和环境变量。
- Docker Compose 使用 `docker compose ... --wait` 等 Compose v2 语法；不写不存在的封装脚本。
- 区分“源码构建产物”和“容器镜像构建”，并明确 Vite 产物目录及 Rust release 二进制位置。
- 本地开发不假设已经存在数据库：提供项目自带的 `docker-compose.test.yml` 启动方式，并说明测试数据库 URL。
- 不在示例中给出可直接用于生产的密码；可信代理秘密要求至少 32 字节。
- 保留初始管理员变量只在空库首次生效、媒体卷与数据库必须一致备份、公开媒体不防下载等重要边界。
- 危险命令必须明确风险；不得把 `down --volumes` 写成普通停止命令。

## 验证

- 对照 `package.json`、Cargo workspace、`.env.example`、`docker-compose.yml`、`docker-compose.test.yml` 和 Dockerfile 核对每条命令及产物。
- 检查 README 中引用的本地路径全部存在。
- 运行 Markdown 文本检查、`git diff --check` 和相关配置解析命令。
- README 仅修改文档，不改变应用或部署行为。
