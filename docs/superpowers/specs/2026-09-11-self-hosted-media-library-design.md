# 自托管电影与剧集媒体库设计规格

日期：2026-09-11

## 1. 产品概述

本产品面向个人或小型团队，是一个可自行部署的电影与剧集媒体库。公开访客无需登录即可浏览、搜索和播放已发布内容；单一管理员通过独立后台维护电影、剧集、季、单集、题材、海报和视频，并管理内容从草稿到发布、归档和永久删除的生命周期。

首版强调单机部署、维护成本低和状态规则清晰。它不承担视频转码、账号社区或数字版权保护能力。

## 2. 目标

- 提供无需登录的公开内容浏览、搜索、详情和播放体验。
- 支持电影以及“剧集 → 季 → 集”的内容结构。
- 支持管理员上传浏览器可直接播放的视频以及海报图片。
- 通过严格的状态机约束内容编辑、公开和删除行为。
- 支持系统默认题材，并允许管理员新增、改名、排序和停用。
- 以 Docker Compose 在个人服务器、NAS 或小型 VPS 上部署。
- 保留元数据导入、对象存储和视频转码的扩展边界，但首版不实现。

## 3. 非目标

首版不包含：

- 自动转码、码率自适应或 FFmpeg 任务队列。
- 外挂字幕管理；只使用视频文件中浏览器能够识别的内嵌轨道。
- 多管理员、团队成员或角色权限。
- 服务端观看历史、跨设备进度同步、收藏、评分或评论。
- 第三方元数据导入。
- S3、MinIO 等对象存储实现。
- 防下载、数字版权保护或可靠的防盗链能力。
- 回收站；永久删除不可恢复。

## 4. 总体架构

系统采用前后端完全分离的架构，由以下部署单元组成：

1. **公开站前端**：提供首页、搜索、详情和播放体验，不包含后台代码。
2. **管理后台前端**：提供登录、内容维护、题材配置和系统设置。
3. **统一后端 API**：同时提供公开只读 API 和需要管理员会话的管理 API，内部按认证、内容目录、生命周期、题材和媒体文件划分职责。
4. **关系型数据库**：保存账号、内容元数据、题材、状态和媒体文件引用。
5. **本地媒体卷**：保存海报和视频二进制文件，通过宿主机持久化挂载。

公开站和管理后台是两个独立工程与构建产物，但生产环境通过反向代理使用同一域名：

- `/`：公开站
- `/admin`：管理后台
- `/api`：统一后端 API
- `/media`：公开媒体文件

Docker Compose 编排公开站、管理后台、后端 API 和数据库，并挂载持久媒体目录。反向代理是推荐的生产入口，但不强制内置于核心应用。

### 4.1 技术栈

- 公开站与管理后台：React、Vite、TypeScript，分别构建为独立前端应用。
- 后端：Rust、Axum。
- 数据访问与迁移：SeaORM 稳定版本线，连接 PostgreSQL。
- 异步运行时与异步文件操作：Tokio。
- 部署：Docker Compose；生产环境由同源反向代理统一暴露 `/`、`/admin`、`/api` 和 `/media`。

## 5. 内容与分类模型

### 5.1 内容形态

首版支持两种固定内容形态：电影和剧集。它们属于系统结构，不由管理员增删。

电影包含：

- 名称
- 简介
- 年份
- 时长
- 一个或多个题材
- 海报
- 可播放视频
- 生命周期状态

剧集包含：

- 名称
- 简介
- 年份
- 一个或多个题材
- 海报
- 生命周期状态
- 一个或多个季

季是纯组织容器，只保存季序号，不保存名称或简介，也没有独立生命周期。

单集包含：

- 所属季
- 集序号
- 由管理员输入的集名称
- 简介
- 时长
- 可播放视频
- 生命周期状态

### 5.2 题材

题材与电影、剧集是多对多关系，例如剧情、恐怖、科幻。系统提供默认题材，管理员可以新增、改名、排序和停用。

- 已被内容引用的题材不得直接删除，只能停用。
- 停用题材仍保留在已有内容上，但创建或编辑草稿时不可再新增选择。
- 首页卡片按照管理员配置的顺序展示题材。

### 5.3 媒体资源

数据库只保存受控文件标识、相对路径、类型、大小和必要元数据，不保存海报或视频二进制。

媒体文件保存在通过部署配置挂载的本地目录。业务层通过统一存储接口访问文件，以便未来增加对象存储实现。

## 6. 生命周期与编辑约束

电影、剧集和单集使用相同的状态集合：

- **草稿**：唯一允许编辑内容字段、题材和关联文件的状态。
- **已发布**：对访客公开，自身数据只读。
- **已归档**：对访客隐藏，自身数据只读。

允许的主要状态流转是：

```text
草稿 → 已发布 → 已归档
                   ├─ 原样重新发布
                   ├─ 转为草稿后编辑
                   └─ 永久删除

草稿 ─────────────────→ 永久删除
```

约束如下：

- 已发布内容不能直接编辑或永久删除，必须先归档。
- 已归档内容不能直接编辑；必须先转为草稿。
- 已归档内容可以不修改地原样重新发布。
- 草稿和已归档内容可以永久删除。
- 永久删除是不可逆操作，不存在回收站。
- 所有状态变更由后端校验，不能只依赖前端隐藏按钮。

### 6.1 发布前最低要求

- 电影：名称、海报、存在且可访问的浏览器兼容视频。
- 剧集：名称、海报、至少一个已发布单集。
- 单集：季序号、集序号、管理员输入的集名称、存在且可访问的浏览器兼容视频。

### 6.2 剧集与单集可见性

单集公开可见必须同时满足：所属剧集已发布，且单集自身已发布。

归档剧集会立即隐藏其全部季和单集，但不改变各单集自身状态。剧集原样重新发布后，原本已发布的单集恢复公开。

为了支持边更新边发布：

- 已发布剧集的自身字段和海报保持只读。
- 已发布剧集下允许新建季和草稿单集。
- 新增或修改下级内容不改变剧集自身状态。
- 已发布单集必须先归档、再转为草稿，才能修改。
- 季下存在已发布单集时，季序号不可修改，季不可删除。
- 季下没有已发布单集时，允许修改季序号或删除季。

## 7. 公开站体验

### 7.1 首页布局

首页参照已确认的本地参考页布局：

- 深色整体背景。
- 顶部左侧显示站点名称。
- 顶部右侧依次显示“全部 / 电影 / 剧集”内容形态切换和短搜索框。
- 顶部下方直接展示海报卡片网格；桌面端默认五列，随视口宽度逐级减少列数。
- 不提供题材、年份或排序筛选控件。

卡片依次显示：

1. 海报
2. 内容名称
3. “电影/剧集 · 年份”
4. 题材标签

卡片最多展示三个题材；空间不足或超过上限时使用“+N”，完整题材在详情页展示。首页默认混合展示已发布电影和剧集。

### 7.2 搜索与详情

- 搜索匹配电影或剧集的名称和简介，不单独搜索单集。
- 搜索结果仅包含有效发布内容。
- 电影详情显示海报、名称、年份、时长、题材、简介和播放入口。
- 剧集详情显示海报、名称、年份、题材、简介、季切换和已发布单集列表。
- 季在界面中以“第 N 季”呈现；单集显示“第 N 集 · 集名称”。
- 已归档或不存在的内容对访客统一表现为不存在，避免泄露后台状态。

### 7.3 播放与本地进度

- 服务器不转码，管理员必须上传浏览器可直接播放的格式。
- 视频通过公开媒体 URL 提供，并支持浏览器 Range 请求与拖动播放。
- 产品不承诺阻止下载或外部直接引用媒体地址。
- 观看进度按内容保存在当前浏览器本地。
- 再次进入时，访客可以选择继续上次播放或从头播放。
- 剧集额外记录最近观看单集，并提供上一集、下一集和当前季选集。
- 清除浏览器数据后，观看进度不可恢复，也不会跨设备同步。

## 8. 管理后台体验

### 8.1 账号区域

登录成功后，页面右上角显示当前管理员名称。点击名称展开下拉菜单：

- 修改密码
- 退出登录

退出入口不重复出现在侧边导航中。

### 8.2 导航与查询

侧边导航包含：

- 内容管理
- 题材配置
- 系统设置

内容列表查询区使用紧凑控件：

- 内容形态下拉框
- 状态下拉框
- 较短的名称关键词输入框
- 查询按钮
- 新建内容按钮

名称不是有限枚举，因此保留文本输入，不使用下拉框。

### 8.3 内容列表

列表至少展示：

- 海报缩略图
- 名称
- 内容形态
- 状态
- 可用操作

可用操作必须显示为与其他按钮一致的小型圆角按钮。普通操作使用深色主题的蓝灰样式，永久删除使用同样结构的风险色样式。

不同状态下的操作：

- 草稿：编辑、发布、永久删除。
- 已发布：查看、归档。
- 已归档：查看、原样发布、转为草稿、永久删除。

### 8.4 草稿编辑

编辑页使用紧凑、固定最大宽度的表单，不让输入控件横向铺满内容区。

- 名称、年份、时长和题材控件使用与内容匹配的较短宽度。
- 简介和视频区域可以适当加宽。
- 添加海报时显示空海报占位，点击选择文件。
- 选中文件后立即显示本地预览。
- 编辑草稿时显示当前海报，点击海报可以选择替换。
- 已发布和已归档页面只显示海报，不提供替换能力。

管理后台与公开首页共用深色背景、蓝灰卡片、浅色文字、细描边、圆角和按钮风格。状态颜色只作为辅助提示，不能成为唯一的信息表达方式。

## 9. 文件写入与替换

创建新内容时先建立草稿记录，再进入编辑与上传流程。

海报或视频保存遵循以下流程：

1. 客户端展示待上传文件信息；海报同时提供本地预览。
2. 后端以流式方式写入临时文件，避免将大视频完整载入内存。
3. 后端校验扩展名、MIME、大小限制和必要的实际内容特征。
4. 校验通过后，以原子方式将临时文件移动为正式文件并更新数据库引用。
5. 替换场景中，新文件和数据库更新成功后才清理旧文件。
6. 任一步骤失败时保留旧文件与旧数据库引用。

系统定期清理超过安全期限且未被任何内容引用的临时文件。

## 10. 永久删除

永久删除前，确认界面必须列出受影响的季、单集、海报和视频数量，并要求管理员再次输入内容名称。

- 删除电影或单集时，删除对应记录以及其独占媒体文件。
- 删除剧集时，级联删除其季、单集和独占媒体文件。
- 数据库关系先进入一致的删除结果，再清理文件。
- 文件清理失败时记录待清理任务，并向管理员提示；不能让数据库停留在半删除状态。
- 状态操作和清理任务必须能够安全重试，避免重复记录或错误删除。

## 11. 认证与安全

### 11.1 首次初始化

Docker Compose 通过部署环境变量提供初始管理员名称和密码。后端只在数据库不存在管理员时写入初始账号；账号存在后，环境变量不得覆盖名称或密码。

### 11.2 会话和密码

- 登录后使用 `HttpOnly`、`Secure`、`SameSite=Lax` 的会话 Cookie。
- 不把登录令牌保存到浏览器本地存储。
- 密码只保存强哈希结果。
- 修改密码必须验证当前密码。
- 修改成功后撤销已有会话并要求重新登录。
- 登录接口限制连续失败尝试，降低暴力破解风险。

### 11.3 请求和文件安全

- 管理操作具备 CSRF 防护，并只接受配置允许的同源请求。
- 公开 API 只返回当前真正可见的字段和内容。
- 上传文件名由系统生成，用户文件名不得直接用作磁盘路径。
- 所有文件访问必须限制在配置的媒体根目录内，阻止路径穿越。
- `/media` 禁止目录浏览。
- 生产环境推荐 HTTPS。

## 12. 错误与并发处理

- 前端提供即时校验，后端始终执行权威校验。
- 发布校验失败时保留草稿状态，并返回明确的缺失项或错误字段。
- 对只读状态执行修改时，后端返回状态冲突，不进行部分更新。
- 对已变化的数据拒绝盲目覆盖，提示管理员刷新后重试。
- 发布、归档等状态操作保持幂等；重复请求不会制造重复记录。
- 公开请求不区分“未找到”“草稿”或“已归档”，统一返回不可见结果。
- 存储空间不足、上传中断和文件校验失败均不得破坏已有正式文件。

## 13. 部署与持久化

首版交付单机 Docker Compose 配置，适用于 NAS、个人服务器和小型 VPS。

必须持久化：

- 数据库数据目录
- 海报和视频媒体目录

首次部署应完成数据库初始化和管理员创建。容器重启或升级不得丢失数据库与媒体文件。部署文档需要明确媒体目录权限、容量规划、备份范围、公开媒体 URL 的含义以及 HTTPS 建议。

## 14. 测试与验收

### 14.1 自动化测试重点

- 生命周期允许与禁止的状态转换。
- 只有草稿允许编辑。
- 发布前最低要求。
- 剧集、季和单集的组合可见性。
- 已发布剧集下新增季和草稿单集。
- 季序号修改和删除约束。
- 题材新增、排序、停用和引用保护。
- 管理员首次初始化、登录、修改密码、退出和会话撤销。
- CSRF、登录限流、上传校验和路径穿越防护。
- 大文件流式上传、失败回滚、原子替换和临时文件清理。
- 永久删除、级联范围和文件清理重试。
- 公开搜索只返回有效发布内容。
- 视频 Range 请求和浏览器本地进度恢复。

### 14.2 端到端验收

- 访客无需登录即可完成浏览、搜索、查看详情和播放。
- 首页布局、深色主题、海报卡片和题材展示符合确认稿，并适配桌面与移动端。
- 管理员可以完成电影和剧集从新建草稿到发布、归档、转回草稿与删除的完整流程。
- 已发布和已归档内容无法编辑。
- 已发布剧集能够持续增加和发布新单集，而无需修改剧集自身。
- Docker Compose 能在空数据目录启动并初始化管理员。
- 服务重启后账号、内容数据和媒体文件保持完整。

## 15. 后续扩展边界

未来可以在不改变核心内容模型的前提下增加：

- FFmpeg 转码与异步任务模块。
- 可选的第三方元数据提供方。
- S3/MinIO 存储实现。
- 多管理员与细粒度权限。
- 外挂字幕与多语言轨道管理。
- 服务端观看历史与跨设备同步。

这些能力不进入首版任务范围。
