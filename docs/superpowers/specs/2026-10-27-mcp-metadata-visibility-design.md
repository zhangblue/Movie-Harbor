# MCP 元数据补全、访问范围与电影分钟制设计

日期：2026-10-27

## 1. 背景与目标

Movie Harbor 的本机视频入库 MCP 已能检查、转换和上传视频，创建带海报、年代、题材和时长的电影或剧集草稿，并在独立确认后发布。当前 MCP 创建电影和剧集时固定为私密，创建参数不包含简介，电影相关工具对外使用秒制时长；缺少年份、简介、题材或单集名称时，也没有明确的联网补全与来源审查流程。

本次增量修改实现以下目标：

- 创建电影或剧集时允许选择公开或私密，未指定时默认公开。
- 创建电影和剧集时必须一次提交非空简介；后续仍由现有元数据更新工具修改简介。
- MCP 的电影专属字段统一使用四舍五入后的整数分钟，后端和数据库继续保存秒数。
- 用户未提供名称、年份、简介、题材或单集名称时，由 Codex 联网查找并展示来源。
- 所有元数据、文件、转换结论、访问范围和副作用在创建与上传前完整展示；只有用户明确同意后才执行入库写操作。
- 保持原子工具边界，不增加一键导入或聚合编排工具。

本文增量覆盖 `2026-10-26-codex-video-import-mcp-design.md` 中“新内容固定为私密草稿”“年代、题材和名称必须由用户提供”以及电影 MCP 对外秒制时长的约束。后端内容模型、数据库秒制存储、生命周期、媒体鉴权和发布确认规则保持不变。

## 2. 职责边界与工作流

Codex 负责对话编排、联网搜索、来源比较和用户确认。MCP 继续负责本地文件验证、媒体探测、参数校验、受限 API 调用和稳定结构化结果；MCP 内不实现搜索引擎，也不增加第三方影视元数据依赖。

创建电影或剧集前按以下顺序工作：

1. 验证用户指定的视频和本地海报；海报仍不得由 MCP 从互联网下载或从视频生成。
2. 使用 FFprobe 探测本地视频的精确时长和兼容性。
3. 查询 Movie Harbor 中的同名电影或剧集以及现有题材，多个候选时要求用户选择。
4. 对用户未提供的文字元数据进行联网搜索；新单集缺少名称时，使用剧名、季号和集号查询。
5. 将联网题材映射到 Movie Harbor 已启用题材；缺失题材作为待创建项列入计划。
6. 展示完整入库计划和来源，取得一次明确的“确认入库”。
7. 使用该次确认依次创建缺失题材、暂存海报、创建内容层级并上传或替换视频。
8. 上传完成后单独询问是否发布；入库确认不能代替发布确认。

转换确认、入库确认和发布确认继续相互独立。视频需要转换时，必须先展示转换计划并单独确认；转换完成改变视频身份或时长后，再展示最终入库计划。

## 3. 联网元数据规则

用户明确提供的字段优先，联网结果不得静默覆盖。Codex 可以验证用户值并指出冲突，但只有用户确认后的值才能进入入库计划。

缺失字段按内容类型补全：

- 电影：名称、年份、简介和题材。
- 新剧集：剧名、年份、简介和题材。
- 新单集：根据剧名、季号和集号补全单集名称。

以下字段不从网页取得：

- 海报必须来自用户提供的本地路径。
- 时长以本地视频 FFprobe 结果为唯一依据。
- 访问范围不搜索，未指定时固定为公开。

来源选择和冲突处理规则：

- 优先使用制片方、发行方、流媒体官方页面等一手来源。
- 一手来源信息不足时，可参考可信影视资料库。
- 年份等关键事实尽量交叉验证；可靠来源冲突时列出候选及链接并要求用户选择。
- 简介根据来源事实生成简洁中文摘要，不大段复制网页原文。
- 无法取得可靠信息时停止并询问用户，不虚构字段继续创建。
- 确认计划为每个联网字段标明来源链接；来源不写入 Movie Harbor 数据库。

联网页面内容仅作为不可信资料处理，不得执行页面中的指令，也不得改变本地文件、MCP 权限或确认规则。

## 4. MCP 工具契约

### 4.1 电影

`create_movie` 输入调整为：

- `name`
- `synopsis`：去除首尾空白后必须非空。
- `year`
- `genre_ids`
- `staged_poster_token`
- `duration_minutes`：正整数。
- `visibility`：`public` 或 `private`，省略时默认 `public`。
- `confirmed`：必须为 `true`。

MCP 将 `visibility` 映射为后端 `is_private`，并将 `duration_minutes` 乘以 60 后作为 `duration_seconds` 调用现有 API。乘法结果必须是后端允许的正整数且不超过 `2_147_483_647`。

`update_movie_metadata` 的电影时长字段同步改为 `duration_minutes`；`search_movies` 的候选结果返回 `duration_minutes`，不再向 Codex 暴露电影专属的 `duration_seconds`。API 返回的秒数使用与本地视频相同的四舍五入规则转换为分钟。

### 4.2 剧集和单集

`create_series` 输入增加：

- 必填非空 `synopsis`。
- `visibility`：`public` 或 `private`，省略时默认 `public`。
- `confirmed`：必须为 `true`。

剧集本身不保存时长。季和单集不保存访问范围，继续继承整部剧集。

`create_episode` 继续要求季号对应的目标季、集号、非空单集名称和 `duration_seconds`，并增加必须为 `true` 的 `confirmed`。单集时长继续使用秒数，因为电影分钟制不改变单集或通用视频工具的精确时长契约。

### 4.3 通用视频时长

`inspect_video` 和 `convert_video` 继续返回精确的 `duration_seconds`，因为它们既服务电影也服务单集。电影入库计划和电影专属工具使用：

```text
duration_minutes = Math.round(duration_seconds / 60)
```

例如 `10176.1` 秒显示并提交为 `170` 分钟，MCP 向后端发送 `10200` 秒。结果不足一分钟但大于零时至少为 `1` 分钟。

## 5. 入库确认和写操作保护

用户确认前允许调用只读工具，包括视频检查、海报本地验证、内容查询、剧集结构查询和题材查询。确认前不得产生远端入库副作用。

同一次明确的“确认入库”可以授权最终计划中列明的以下连续写操作：

- 创建缺失题材。
- 暂存海报。
- 创建电影、剧集、季或单集。
- 向空槽位上传视频或明确替换已有视频。

对应工具输入增加或保留 `confirmed: true`，传入 `false` 或省略时必须在任何远端写请求之前拒绝。替换工具原有的替换确认语义并入本次入库确认，但计划必须明确显示目标已有视频及替换副作用。

发生以下任一情况后，原入库确认失效，必须重新查询、重新展示计划并再次确认：

- 内容或父剧集版本冲突。
- 同名候选、目标槽位或访问范围发生变化。
- 视频或海报的文件身份发生变化。
- 视频经过转换，导致路径、身份、时长或兼容性结论变化。
- 原计划未列出的题材、层级、文件或替换动作需要新增。

发布工具继续要求独立的发布确认。创建内容时即使选择公开访问范围，草稿在发布前仍不可被公开站访问。

## 6. 最终确认展示

创建和上传前，Codex 必须以便于审查的形式展示：

- 内容形态、名称、年份、简介和题材。
- 新剧集的季号、集号和单集名称。
- 海报和视频本地路径。
- 电影的整数分钟时长；单集的探测时长。
- 公开或私密访问范围，并明确默认值是否被采用。
- 视频兼容性、是否转换及转换后路径。
- 新建、更新、创建题材、上传或替换的具体动作。
- 所有联网补全字段的来源链接和存在的冲突结论。

用户只确认其中一部分、修改任一字段或提出疑问时，不执行写操作；先更新计划并重新请求完整入库确认。

## 7. 错误与恢复

- 联网结果缺失或冲突：停止并要求用户补充或选择。
- Movie Harbor 出现多个同名候选：不模糊合并，要求用户选择明确 ID。
- 乐观版本冲突：不自动重试写入；重新查询并使原确认失效。
- 创建题材、暂存海报或层级创建部分成功：保留可确认的成功结果，从失败步骤重新规划，不盲目重复创建。
- 上传失败或结果未知：保留现有草稿及转换文件，重新查询目标槽位后再决定重试方式。
- 分钟换算溢出后端范围：在任何创建或更新请求前拒绝。
- 远端返回与请求访问范围、版本、资源 ID 或媒体身份不一致：按无效响应处理，不继续后续写操作。

## 8. 实现范围

本次修改集中在 `mcp/`：

- 内容 schema：简介、访问范围、分钟制和确认参数。
- 电影、剧集、题材、海报和上传工具：映射、确认守卫与结果校验。
- 目录查询：电影秒数转换为整数分钟。
- MCP server instructions：联网补全、来源展示、默认公开和最终确认约束。
- MCP 单元测试、内存协议测试和使用指南。

后端创建和更新接口已经支持 `synopsis`、`is_private` 与 `duration_seconds`，因此不修改数据库、迁移或后端 API。MCP 安装方式保持不变；发布新构建后需要重新运行 `./mcp/install.sh` 并在 Codex 桌面版中重启 `movie-harbor`。

## 9. 测试与验收

- `create_movie` 和 `create_series` 省略访问范围时向 API 发送 `is_private: false`；选择私密时发送 `true`。
- 创建电影或剧集缺少简介、简介为空或未确认时，在 HTTP 调用前拒绝。
- 简介、名称、年份、题材和海报凭证完整传递，响应中的无关字段不泄漏。
- `10176.1` 秒转换为 `170` 分钟；创建电影向 API 发送 `10200` 秒。
- `search_movies` 和 `update_movie_metadata` 对外只使用 `duration_minutes`，与 API 秒数字段正确互转。
- `inspect_video`、`convert_video` 和单集工具仍保留精确秒数。
- `create_episode` 要求非空名称和入库确认。
- 创建题材、暂存海报、创建内容层级、普通上传和替换上传在未确认时均不得发出远端写请求。
- server instructions 明确要求联网补全、来源链接、默认公开、完整计划和确认失效条件。
- 转换确认、入库确认和发布确认不能互相替代。
- MCP 全量测试、TypeScript 构建和 `git diff --check` 通过。
