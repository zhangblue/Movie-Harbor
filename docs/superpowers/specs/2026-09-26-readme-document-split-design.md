# README 文档拆分设计

日期：2026-09-26

## 1. 背景

根目录 `README.md` 当前同时承担项目介绍、部署手册、内容迁移、媒体运维、半离线发布、开发验收和目录说明等职责，篇幅已增长到约 300 行。首次进入仓库的读者不容易快速识别项目定位，具体操作说明也不便于独立维护和引用。

## 2. 目标

- 让根目录 `README.md` 聚焦项目介绍与文档导航。
- 将操作性内容按读者任务拆分到 `docs/guides/` 下的独立 Markdown 文件。
- 保留现有技术事实、安全警告、命令示例和权威设计文档入口。
- 让所有拆分文档都能从 README 直接到达，并提供返回 README 的入口。

## 3. 方案比较

### 方案 A：每个现有二级章节单独成文

边界最直接，但会产生大量短文件，部署相关信息被切散，读者需要频繁跳转。

### 方案 B：按读者任务归并

将相关章节归并为部署、半离线发布、内容迁移、媒体与备份、开发五份指南。文件数量适中，每份文档有单一主题，同时保留完整上下文。

### 方案 C：只按使用者与开发者拆成两份

导航简单，但使用者文档仍会混合部署、导入、媒体安全和备份恢复，后续增长后容易再次变得臃肿。

采用方案 B。

## 4. 文档结构

### 4.1 根 README

`README.md` 只保留：

- 项目名称与用途简介。
- 当前状态与主要能力。
- 核心设计和技术栈。
- 面向使用者、运维人员和开发者的文档导航。
- 产品设计、实现计划与协作约定等权威项目文档入口。
- 首版非目标，作为项目范围介绍的一部分。

README 不再承载长篇命令、环境变量表、升级步骤或测试流程。

### 4.2 独立指南

- `docs/guides/deployment.md`：生产部署、访问模式、环境变量、代理信任、上传格式与容量。
- `docs/guides/offline-package.md`：半离线发布包的构建、校验、部署、升级和数据目录注意事项。
- `docs/guides/content-transfer.md`：管理媒体路径、内容 JSON 导出、导入命令、恢复进度和安全边界。
- `docs/guides/media-and-backup.md`：媒体目录权限、媒体独占与同步删除、数据库迁移 v5、一致备份与恢复。
- `docs/guides/development.md`：源码环境、测试与构建、E2E 隔离与清理、UI Demo、目录结构。

每份指南以返回根 README 的链接开头。指南之间存在前置关系时使用相对链接，例如部署和半离线指南链接到媒体与备份指南。

## 5. 内容迁移原则

- 以移动和重组为主，不借此次拆分改变产品行为、配置默认值或安全边界。
- 命令、变量名、端口、镜像版本和路径保持不变。
- 原 README 中的所有操作性信息必须在新指南中找到对应位置，不因缩短入口页而丢失。
- 中文文案遵循中英文与数字间留空格、中文语境使用全角标点等现有排版习惯。
- 新增链接全部使用仓库内相对路径，并验证目标存在。

## 6. 验收标准

- README 只包含工程介绍、范围说明和文档导航，不包含部署或开发操作步骤。
- 5 份指南职责清晰，覆盖原 README 的全部操作性章节。
- README 可以直接链接到全部指南，指南可以返回 README。
- 文档内相对链接均指向存在的文件。
- `git diff --check` 通过，Markdown 标题结构与代码围栏完整。
