# MCP 管理维护与上传容量保护设计

日期：2026-11-23

## 1. 背景与意图

Movie Harbor 的本机 MCP 已经能够创建内容、补全元数据、上传或替换视频并发布内容，但管理员在对话中进行日常维护时仍缺少五类原子能力：修改电影或整剧的访问范围、补传或替换海报、精确查找缺少视频的电影或单集、读取完整系统概览，以及统一转换电影、整剧和单集的生命周期。

视频上传还存在容量风险。系统概览能够报告媒体卷总量、可用量和 10 GiB 安全保留空间，但现有 MCP 上传工具不会在发送大文件前使用这些数据，媒体存储路径也没有依据本次文件大小执行同一容量门槛。用户希望在上传开始前拒绝确定无法容纳的新视频，而不是传输结束后才发现磁盘不足。

本设计把这些需求实现为彼此独立的原子 MCP 工具，不把它们强行串成一条管理链路。Codex 可以根据具体任务组合工具，例如先把已发布电影转为草稿，再替换海报；单个工具仍保持窄职责、明确确认和最小权限。

本文是以下设计的增量规格：

- `2026-09-11-self-hosted-media-library-design.md`
- `2026-09-12-media-ownership-and-publishing-design.md`
- `2026-10-10-private-content-and-viewer-accounts-design.md`
- `2026-10-26-codex-video-import-mcp-design.md`
- `2026-10-27-mcp-metadata-visibility-design.md`
- `2026-11-23-admin-system-overview-design.md`

发生冲突时，本文只覆盖 MCP 管理维护、MCP 系统概览权限和视频上传容量保护。媒体独占、同步替换、公开访问、管理员会话以及其他生命周期规则保持不变。

## 2. 目标

- 用一个工具修改电影或整剧的公开、私密范围。
- 用一个工具给电影或整剧补传第一张海报，或原子替换已有海报。
- 用一个分页工具分别查询缺少视频的电影和缺少视频的具体单集。
- 用一个只读工具取得管理后台已经提供的完整系统概览。
- 用一个工具转换电影、整剧或单集的生命周期，并自动完成已发布内容转草稿所需的合法中间步骤。
- 所有电影和单集视频上传、替换在读取并发送大文件前自动检查媒体卷容量。
- 服务端在写入临时文件前复核文件声明大小和容量门槛，避免只依赖 MCP 预检。
- 继续使用乐观版本、明确确认、路径白名单和 MCP 路由白名单保护写操作。

## 3. 非目标与反目标

- 不实现一键维护、批量修复或把五项能力合并为一个巨型工具。
- 不允许删除已有海报；海报槽位只能从空变为有，或从旧海报原子替换为新海报。
- 不给季或单集增加独立访问范围；它们继续继承整剧。
- 不自动把更换海报后的内容重新发布，也不记忆并恢复原发布状态。
- 不把缺少任何单集的空剧集伪装成“某一集缺视频”；只有已经存在的单集才能返回季号和集号。
- 不计算视频转换产物、Multipart 开销、临时文件或新旧视频短暂共存的峰值空间。
- 替换视频时不使用旧视频大小抵扣本次容量要求。
- 不在系统概览工具中执行备份、恢复、清理、升级或任何宿主机写操作。
- 不扩大 MCP 到删除、用户管理、密码、导出、备份或任意系统接口。

## 4. 工具总览

新增五个工具：

1. `set_content_visibility`
2. `set_content_poster`
3. `list_missing_videos`
4. `get_system_overview`
5. `transition_content_lifecycle`

调整四个现有工具：

- `upload_movie_video`
- `replace_movie_video`
- `upload_episode_video`
- `replace_episode_video`

现有 `publish_movie`、`publish_episode` 和 `publish_series` 为兼容既有调用暂时保留；工具说明和文档把新的统一生命周期工具作为后续管理流程的首选。此次不做破坏性移除。

所有命名函数、类型、工具注册、测试和关键调用点继续遵守项目中文注释要求。

## 5. 修改访问范围

### 5.1 工具契约

`set_content_visibility` 输入：

- `content_type`：必填，`movie` 或 `series`。
- `content_id`：电影或整剧 UUID。
- `version`：必填正整数，必须等于服务端当前版本。
- `visibility`：`public` 或 `private`。
- `confirmed`：必须为 `true`。

输出至少包含内容类型、内容 ID、最终访问范围和新版本，并提供适合下一步读取或维护的 `next_actions`。

工具根据 `content_type` 调用既有单对象隐私接口：

- `PUT /api/admin/movies/{id}/privacy`
- `PUT /api/admin/series/{id}/privacy`

MCP HTTP 客户端增加受控 `PUT` 支持，但目标仍必须位于同源 `/api/admin/`。后端 MCP 路由白名单只增加上述两个带合法 UUID 的精确模式，不开放通用 `PUT`。

### 5.2 行为

- 草稿、已发布和已归档内容均可修改访问范围。
- 目标范围与当前范围相同时，沿用后端既有幂等语义，不伪造版本增长。
- 单集和季不接受此工具；整剧变更立即作用于其海报及所有单集媒体授权。
- 版本冲突返回稳定冲突错误，要求重新查询，不自动重试覆盖。

## 6. 补传或替换海报

### 6.1 工具契约

`set_content_poster` 输入：

- `content_type`：必填，`movie` 或 `series`。
- `content_id`：电影或整剧 UUID。
- `version`：必填正整数。
- `path`：用户提供、位于 MCP 允许根目录内的本机图片绝对路径。
- `confirmed`：必须为 `true`。

输出包含内容类型、内容 ID、新版本、新媒体 ID、格式、字节数、动作类型 `added|replaced` 和后续动作。工具不提供 `remove` 或空路径语义。

### 6.2 调用顺序

1. 按现有路径策略检查真实路径、普通文件、允许根目录和文件身份。
2. 复用海报预检，确认 JPEG、PNG 或 WebP 的基本结构；服务端完整解码仍是最终权威。
3. 读取电影或整剧详情，核对 ID、版本和生命周期。
4. 目标不是草稿时拒绝，不在海报工具内部暗中改变生命周期；错误提示调用 `transition_content_lifecycle`。
5. 根据当前是否已有海报，把动作标记为补传或替换，并要求 `confirmed: true`。
6. 流式调用既有海报接口：
   - `POST /api/admin/media/movies/{id}/poster?version=...`
   - `POST /api/admin/media/series/{id}/poster?version=...`
7. 校验响应媒体元数据和版本恰好推进一次后返回。

后端继续沿用同步媒体替换协议：新海报上传或校验失败不触碰旧海报；旧文件无法隔离时取消替换并保留旧海报；成功响应前切换数据库引用并同步移除旧文件。

这两个海报路由加入 MCP 精确白名单。创建内容使用的 `stage_poster` 保持不变，不能用暂存凭证绕过既有内容创建契约。

## 7. 缺少视频查询

### 7.1 后端接口

新增只读接口：

```text
GET /api/admin/contents/missing-videos?content_type=movie|series&page=N
```

- `content_type` 必填，不提供混合模式。
- `page` 省略时为 1，固定每页 20 条，沿用管理内容分页上限。
- 查询总数和当前页必须来自同一个只读、可重复读事务快照。
- 响应包含 `content_type`、`page`、`size`、`total` 和 `items`。
- 使用稳定排序；电影按创建时间倒序、ID 升序，单集按剧名、季号、集号及 ID 升序，具体空值与同名顺序在实现计划中固定并测试。

电影模式筛选 `video_asset_id IS NULL`，每项包含：

- `movie_id`
- `movie_name`
- `status`
- `version`
- `is_private`

剧集模式只返回已经存在且 `video_asset_id IS NULL` 的单集，每项包含：

- `series_id`、`series_name`、`series_status`、`series_version`
- `season_id`、`season_number`
- `episode_id`、`episode_number`、`episode_name`
- `episode_status`、`episode_version`
- `is_private`，值来自整剧，帮助调用方理解媒体访问范围

整剧没有任何季或单集时不返回虚构条目；本工具也不检查文件系统中视频文件是否意外丢失。数据库引用存在但物理文件不可访问属于存储一致性问题，应另行诊断。

### 7.2 MCP 工具

`list_missing_videos` 输入只包含必填 `content_type` 和可选 `page`。工具直接映射后端分页结构，不逐页读取全部电影或展开所有剧集，也不自动上传、创建或修改内容。

该接口加入 MCP 的精确 `GET` 白名单。工具标记为只读、幂等、非破坏。

## 8. 只读系统概览

`get_system_overview` 无业务输入，调用现有：

```text
GET /api/admin/system/overview
```

工具完整返回现有稳定字段：采样时间、应用版本、总体状态、电影/剧集/单集生命周期计数、普通用户计数、海报和视频统计、媒体卷容量与可上传状态、备份不可验证状态以及告警。

MCP 不重新计算总体状态、可写字节或告警，不返回宿主机路径、容器路径、存储键或环境变量。接口继续使用 `Cache-Control: private, no-store`。容量未知时明确返回 `null` 和 `storage_capacity_unavailable`，不能改写为零。

后端 MCP 白名单只新增该只读路径，不开放系统设置的通用前缀，也不改变页面的管理员会话行为。

## 9. 通用生命周期转换

### 9.1 工具契约

`transition_content_lifecycle` 输入：

- `content_type`：`movie`、`series` 或 `episode`。
- `content_id`：电影、整剧或单集 UUID。
- `series_id`、`season_id`：单集时必填，其他类型禁止提交。
- `version`：目标内容当前版本。
- `target_status`：`draft`、`published` 或 `archived`。
- `confirmed`：必须为 `true`。

输出包含原状态、按顺序实际经过的状态数组、最终状态、最终版本以及整剧受单集转换影响后的版本（适用时）。返回的状态路径来自真实成功响应，不能只根据预期拼装。

### 9.2 路径规则

工具先读取当前详情并校验 ID、层级和版本，再按现有状态机执行：

- 当前状态等于目标状态：幂等成功，不发写请求。
- `draft -> published`：执行发布，继续接受现有媒体和发布最低条件校验。
- `published -> archived`：执行归档。
- `archived -> published`：执行原样重新发布，并重新执行现有发布校验。
- `archived -> draft`：执行转草稿。
- `published -> draft`：在同一次工具调用中依次执行归档、转草稿，第二步使用第一步返回的新版本。
- `draft -> archived`：不是现有状态机允许的转换，直接拒绝。

已发布内容转草稿会立即从公开目录和媒体授权中消失，调用前必须明确展示下线副作用。工具本身不自动执行后续海报修改，也不在修改后恢复发布。

`published -> draft` 是两个既有后端请求，不宣称跨请求原子。如果归档已经成功而第二步因网络、服务或并发问题失败，工具必须返回“部分完成”错误，明确最终可确认状态为已归档或状态未知，并要求重新读取；不得谎报仍为已发布或自动发布补偿。

单集请求始终使用带剧集、季、单集三层 ID 的既有路由，后端重新验证归属。整剧与单集仍各自遵守发布最低要求，转换单集时父剧集版本按现有规则推进。

MCP 白名单补齐合法 UUID 的单集 `archive` 和 `draft` 路径。已有电影、整剧的 publish/archive/draft 与单集 publish 路径继续复用；不增加删除或直接改写状态的后门。

## 10. 视频上传容量预检与服务端保护

### 10.1 判定规则

所有电影、单集视频上传和替换使用同一规则：

```text
available_bytes - new_video_bytes >= reserve_bytes
```

等价实现必须使用防下溢比较：

```text
available_bytes >= new_video_bytes + reserve_bytes
```

加法溢出按容量不足处理。`reserve_bytes` 使用系统概览当前返回的 10 GiB 固定保留值，不在 MCP 中复制另一个常量。

只计算最终要上传的新视频字节数：

- 不估算转换输出、Multipart 开销或临时文件峰值。
- 替换时不扣除或抵扣旧视频大小。
- 容量采样未知、卷不接受上传或数值溢出时一律提前拒绝。

### 10.2 MCP 预检

四个视频工具完成本地路径、身份和兼容性检查后，在读取目标详情和启动上传流之前调用系统概览。它们取得卷 0 的 `available_bytes`、`reserve_bytes` 和 `accepts_uploads`，使用本地已验证文件大小执行规则。

拒绝结果返回稳定机器码和中文说明，并包含非敏感的文件大小、可用空间、预留空间与差额；不得包含密钥、服务端路径或无限制底层错误。预检成功不承诺上传必然成功，因为其他进程仍可能消耗空间。

### 10.3 服务端权威复核

视频上传请求增加受控的声明文件大小头，名称在实现计划中固定；MCP 使用已验证本地文件身份中的大小，管理后台使用浏览器 `File.size`。海报上传不使用此容量契约。

电影和单集视频路由要求合法的非负声明大小，并把它传入媒体存储。媒体存储取得现有全局变更锁后、创建临时文件前：

1. 读取同一已打开媒体根目录的当前容量。
2. 按声明的新视频大小和 10 GiB 保留空间复核门槛。
3. 容量读取失败或空间不足时，在消费文件流前返回稳定错误。
4. 流式写入期间累计实际字节；实际大小一旦超过声明立即终止并清理临时文件。
5. 流结束后实际大小必须等于声明，否则拒绝并清理。

全局变更锁使同一 API 进程内的媒体写操作在容量复核与文件落盘期间串行，避免两个通过同一容量快照的视频同时写入。它不能阻止宿主机其他进程或其他 API 实例使用同一文件系统，因此真实 I/O 的 `ENOSPC` 仍需映射为容量错误并保持原内容。

服务端错误至少区分：

- `storage_capacity_unavailable`
- `storage_space_low`
- `declared_size_invalid`
- `declared_size_mismatch`

容量不足错误可以返回本次判定所需的非敏感数值，但不得返回路径。替换在任何预检或写入失败时必须保留旧视频和数据库引用。

## 11. 权限与安全边界

MCP Bearer 主体只新增以下精确权限：

- 两个隐私 `PUT` 路由。
- 两个电影/整剧海报 `POST` 路由。
- 缺视频查询 `GET` 路由。
- 系统概览 `GET` 路由。
- 单集归档和转草稿 `POST` 路由。

已有生命周期和视频路由继续沿用现有权限。每个含 ID 的白名单模式都先解析 UUID；方法不匹配、附加路径段、非法 ID 和未知系统路径均拒绝。

工具层的 `confirmed: true`、MCP 写工具注解和对话确认是用户体验保护，不替代后端身份、版本、状态、层级和媒体校验。直接持有 MCP 密钥的调用方仍只能访问白名单中的窄能力。

日志和错误不得记录 Bearer 值、Authorization header、用户本机绝对路径或服务端媒体路径。系统概览和容量错误不得扩大为宿主机探测接口。

## 12. 错误处理与恢复

- 查询参数、枚举、UUID、版本或层级无效：返回稳定无效请求错误。
- 内容不存在或层级不匹配：返回不存在语义，不泄露其他内容。
- 乐观版本冲突：停止操作并提示重新读取，不自动覆盖。
- 非草稿海报目标：不上传文件，提示先调用生命周期转换。
- 海报验证、上传或替换失败：保留旧海报；补传失败时保持空槽位。
- 生命周期发布条件不满足：返回后端结构化字段的本地化说明，不跳过校验。
- 两步生命周期部分成功：报告已确认的最后状态和重新读取动作，不自动补偿发布。
- 容量未知或不足：在 MCP 侧不启动上传流；若服务端复核才发现则清理新临时文件并保留旧媒体。
- 网络失败后的远端结果未知：不得根据本地请求推断成功，返回重新查询目标的动作。

## 13. 文档与兼容性

更新 `docs/guides/codex-mcp.md` 的工具表、调用示例、安全说明和容量错误排查。说明生命周期转换与海报修改是两个独立工具，Codex 负责按用户意图编排；不能把“确认转草稿”推断为“确认更换海报”或“确认重新发布”。

MCP 工具数量契约、服务端白名单契约和安装构建测试同步更新。旧发布工具继续可用，因此现有对话脚本不会因本次升级立即失效。

不修改数据库结构，不需要迁移。系统概览响应保持现有结构，只扩大 MCP 只读访问主体。

## 14. 测试与验收

实现遵循测试驱动开发，先确认新增测试因缺少目标行为而失败。

### 14.1 后端

- MCP 白名单仅允许设计列出的精确方法和路径，并拒绝相邻、非法 UUID、删除、用户、导出及其他系统路径。
- 电影和整剧隐私修改在三种生命周期下均成功，版本冲突失败。
- 海报补传和替换继续要求草稿，失败保留旧文件与引用。
- 缺视频电影查询只返回空视频槽电影，总数和分页一致。
- 缺视频剧集查询返回准确的剧名、季号、集号、层级 ID、状态和版本；空剧集不产生虚构单集。
- 缺视频查询的稳定排序、第二页和非法参数有覆盖。
- MCP 能读取系统概览，但不能访问其他系统操作；响应继续禁止缓存且不含敏感路径。
- 视频容量刚好满足边界时允许，少一字节时拒绝；容量未知、溢出和声明无效均拒绝。
- 服务端在创建临时文件前拒绝容量不足，请求正文不被继续消费。
- 实际流大于、小于声明均失败并清理；相等时沿用现有媒体校验和登记。
- 上传和替换容量失败均保留原内容与旧视频。
- 同一存储实例的并发视频上传在锁内重新采样，不能共享过期容量结论。
- 底层空间耗尽映射为稳定容量错误且不泄露路径。

涉及存储与事务的测试使用真实临时文件系统和必要的真实 PostgreSQL；路由认证与参数契约优先使用 `Router::oneshot`。

### 14.2 MCP

- 五个新增工具名称、输入输出 schema、中文说明和只读/写入注解正确。
- 访问范围工具只接受电影或整剧，并按类型调用精确 `PUT` 路由。
- 海报工具区分补传与替换，拒绝非草稿和无确认请求，不提供删除语义。
- 缺视频工具强制选择电影或剧集，不出现混合返回。
- 系统概览工具保持服务端字段并拒绝异常响应。
- 生命周期工具覆盖全部合法路径、非法 `draft -> archived`、单集层级校验和幂等目标。
- `published -> draft` 使用第一次响应版本执行第二步，并覆盖第二步失败的部分完成结果。
- 四个视频工具在容量不足或未知时不创建上传请求。
- 容量允许时上传请求携带经过文件身份复核的声明大小。
- 错误输出不泄露密钥、Authorization 或服务端路径。

### 14.3 管理前端与跨服务

- 管理后台视频上传发送 `File.size` 声明，并正确显示容量未知、空间不足和声明不一致错误。
- 既有海报、视频、生命周期和系统概览页面行为没有回归。
- 隔离 Docker Compose 与 Playwright E2E 覆盖：MCP 主体读取概览和缺视频列表、修改隐私、转草稿、补传或替换海报，以及容量不足时视频上传在媒体写入前被拒绝。

## 15. 完成标准

- 五个新增原子工具可以独立调用，输入输出与本文一致。
- 缺视频查询能够精确指出剧名、第几季、第几集，而不是只返回整剧。
- 已发布或已归档内容可经统一生命周期工具安全转为草稿，海报工具不会暗中改变或恢复状态。
- 海报只可补传或替换，无法通过 MCP 删除为空。
- 系统概览保持完整只读语义。
- 所有电影和单集视频上传、替换在 MCP 传输前预检，并由服务端在临时写入前按新文件大小和保留空间复核。
- 新权限保持精确白名单，未开放任何不相关后台能力。
- 相关 Rust、MCP、前端、契约与 E2E 检查按项目要求通过，`git diff --check` 通过。
