# 管理后台内容批量操作设计

日期：2026-11-23

## 1. 背景与目标

管理后台内容列表固定每页 20 条，目前访问范围、归档和题材维护都需要逐条进入或操作。内容数量增长后，同类管理工作重复且容易遗漏；直接对“全部筛选结果”执行操作又会隐式影响管理员未看见的跨页内容，并要求引入异步任务、筛选快照、进度和恢复机制。

本次采用“当前页明确勾选”方案：管理员最多选择当前页 20 条电影或剧集，批量设置公开/私密、添加或移除题材，或归档全部符合条件的已发布内容。服务端在一个事务中先校验完整批次，只有所有项目均可执行时才统一写入；任何一项冲突或不适用都不产生部分修改。

## 2. 范围与安全边界

首期支持三类操作：

1. 设置访问范围：把所选电影和剧集统一设为公开或私密，适用于草稿、已发布和已归档状态。
2. 调整题材：给所选内容添加一个或多个启用题材，或移除一个或多个已有题材。
3. 批量归档：只接受当前均为已发布状态的电影和剧集。

首期明确不支持：

- 批量永久删除、媒体替换或文件清理。
- 批量发布、转为草稿、原样重新发布或创建内容。
- 修改名称、简介、年份、时长、季、集或海报。
- 跨页选择、全选筛选结果、后台异步任务或定时操作。

限制是产品安全边界，不通过隐藏按钮代替后端校验。

## 3. 列表选择与交互

内容表格首列增加复选框，表头复选框只选择当前响应中的 20 条记录。页面显示“已选择 N 项”和批量操作栏。

选择规则：

- 翻页、修改筛选、执行新查询、离开内容列表或刷新列表时清空选择。
- 同一页因普通状态操作刷新后也清空选择，避免保留已变化记录的陈旧版本。
- 选择只保存在当前 React 页面状态，不进入 URL、本地存储或数据库。
- 表头复选框具有全选、部分选择和未选择三态，并提供正确的无障碍名称。
- 未选择任何内容时批量按钮禁用。

操作前弹出确认框，列出操作名称、目标数量和关键影响。访问范围确认框显示目标范围；题材确认框显示添加或移除及题材名称；归档确认框明确说明内容将从公开目录和媒体访问中立即消失。

永久删除不进入任何批量菜单。

## 4. 管理 API

新增：

```text
POST /api/admin/contents/bulk-actions
```

请求体使用带判别字段的结构。示例：

```json
{
  "action": "set_privacy",
  "is_private": true,
  "targets": [
    { "kind": "movie", "id": "UUID", "version": 4 },
    { "kind": "series", "id": "UUID", "version": 7 }
  ]
}
```

```json
{
  "action": "update_genres",
  "mode": "add",
  "genre_ids": ["UUID", "UUID"],
  "targets": [{ "kind": "movie", "id": "UUID", "version": 4 }]
}
```

```json
{
  "action": "archive",
  "targets": [{ "kind": "series", "id": "UUID", "version": 7 }]
}
```

输入约束：

- `targets` 至少 1 条、最多 20 条。
- 同一 `kind + id` 不得重复；`kind` 只接受 `movie` 或 `series`。
- ID 必须是 UUID，版本必须为正整数。
- 题材操作至少包含 1 个、最多 20 个去重后的题材 ID。
- 添加题材只接受当前启用题材；移除题材接受仍存在但已停用的题材，便于清理旧关联。
- 不接受客户端传入筛选条件、页码、内容名称、当前状态或预期题材列表作为授权依据。

成功响应返回每个目标的新版本、状态、访问范围和题材摘要，使前端能够明确核对结果；前端随后仍刷新当前页，以服务端列表作为最终显示来源。

## 5. 原子校验与并发

整个批次在一个数据库事务中处理：

1. 规范化并验证请求结构。
2. 按固定的 `kind + id` 顺序锁定目标电影和剧集行，避免并发批次以不同顺序形成死锁。
3. 验证所有目标存在、类型正确且版本与请求一致。
4. 根据动作验证全部状态和题材前置条件。
5. 只有全部校验通过才执行关联或内容更新。
6. 每个实际参与操作的内容版本递增一次并提交事务。

任何目标不存在、版本过期、状态不适用或题材无效时，事务不写入任何目标。服务端完成全部可执行的只读校验并一次返回所有已发现问题，不遇到第一项错误就提前结束；锁定或查询本身失败仍直接回滚并返回 `500`。

领域前置条件失败统一返回 `409` 和顶层错误码 `bulk_validation_failed`，错误体包含 `problems` 数组。目标问题使用 `{ "scope": "target", "kind": "movie|series", "id": "UUID", "reason": "not_found|version_conflict|invalid_state" }`；题材问题使用 `{ "scope": "genre", "genre_id": "UUID", "reason": "not_found|inactive" }`。数组按请求中目标和题材的规范顺序返回。不存在与冲突混合出现时仍只返回一个 `409`，避免 HTTP 状态优先级影响客户端解释。响应不返回名称、当前版本或其他敏感字段。前端保留选择，在对应行显示“内容已变化，请刷新”或具体不适用原因；题材问题显示在确认框中。

幂等语义：

- 设置为当前已有访问范围仍视为成功，并统一递增一次版本，保证整个明确提交的批次具有一致结果。
- 添加已经关联的题材或移除未关联的题材视为允许的无效果子操作；只要请求整体有效，每个目标仍递增一次版本。
- 用成功响应中的旧版本重复提交会因版本冲突而整批失败，不会再次修改。

这些规则避免前端为了判断“是否已存在”额外逐条读取详情，也让一次批量确认对应一次清晰的版本变化。

## 6. 各动作领域规则

### 6.1 设置访问范围

复用电影和剧集既有 `is_private`、版本和媒体实时鉴权语义。操作提交后，新媒体请求立即按新范围授权；不修改生命周期状态、单集状态或媒体引用。

### 6.2 调整题材

只操作电影或剧集与题材的关联表，不修改题材自身。添加模式要求题材启用；移除模式允许移除已停用题材。一次请求只允许添加或移除，不能同时做两种方向，减少确认歧义。

### 6.3 批量归档

所有目标必须在事务锁定后仍为已发布。电影和剧集沿用现有归档状态转换与版本规则；剧集归档只隐藏整剧及其单集，不改变下级单集各自状态。任何草稿或已归档目标都会使整批失败。

批量归档不涉及物理媒体删除，因此事务内不调用媒体隔离或删除流程。

## 7. 后端结构

在 `admin_content` 边界中增加批量命令 DTO、路由和服务，不让前端循环调用现有单条接口。服务层可以复用电影、剧集领域规则，但必须提供能够加入同一外层事务的内部操作，不能为每条内容各自开启和提交事务。

题材关联操作复用现有实体和题材启用规则。不得把批量逻辑抽成无领域边界的全局工具，也不得绕过版本条件直接更新所有匹配 ID。

## 8. 错误与恢复

- `400`：请求结构、数量、重复目标或动作参数无效。
- `401/403`：沿用管理员认证、来源和 CSRF 规则。
- `409`：目标不存在、版本冲突、状态不适用或题材前置条件变化，使用 `bulk_validation_failed` 与完整 `problems`，整批未写入。
- `500`：数据库故障，事务回滚。

前端网络失败时不得假设成功；重新加载列表后才能再次提交。成功响应返回但刷新失败时显示“操作已完成，列表刷新失败”，保留旧表格只作为过期视图并提供重试，不自动重复写请求。

## 9. 非目标

- 跨页或按筛选条件批量执行。
- 部分成功、逐项提交或自动跳过不适用项目。
- 异步任务、进度条、取消、重跑和任务历史。
- 批量删除、发布、媒体操作或季/单集操作。
- 撤销批量操作；管理员需要用新的显式批量操作恢复访问范围或题材。

## 10. 测试与验收

后端路由测试覆盖认证、CSRF、输入上限、重复目标和错误码。真实 PostgreSQL 测试覆盖电影与剧集混合事务、稳定锁定顺序、版本冲突整批回滚、无效状态整批回滚、题材添加移除、停用题材规则、版本递增、重复提交和归档后公开可见性。

管理前端测试覆盖当前页全选三态、翻页和筛选清空选择、三种确认框、请求体版本、冲突后保留选择、成功后清空并刷新、刷新失败不重复写入和键盘操作。端到端测试验证混合选择的原子成功与原子失败，并确认永久删除和媒体操作不会出现在批量入口。
