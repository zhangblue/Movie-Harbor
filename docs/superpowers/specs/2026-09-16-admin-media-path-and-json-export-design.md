# 管理媒体路径显示与内容 JSON 导出设计

## 背景与目标

管理员需要在电影和剧集详情中确认已上传视频实际对应的容器内存储路径，并从内容管理页一次导出全部电影、剧集、季、集及其年份、题材和媒体路径。该功能只提供查看和导出，不允许通过路径字段修改、替换或删除媒体。

本设计中的“本地存储路径”固定指容器内完整路径，例如 `/media/video/ab/<uuid>.mp4` 或 `/media/poster/ab/<uuid>.jpg`，不是宿主机路径。路径由数据库中的受控媒体存储键派生，客户端不能提交或修改。

## 用户界面

### 详情页路径显示

- 电影详情的视频区域显示当前已持久化视频的只读“本地存储路径”。
- 剧集详情中每一集的视频区域显示该集当前已持久化视频的只读“本地存储路径”。
- 没有已上传视频时继续显示现有空媒体状态，不伪造路径。
- 新选择但尚未上传的浏览器本地文件不显示服务端路径。
- 海报路径不新增到详情页；海报路径只进入导出文件。
- 路径使用适合长文本的只读样式，不提供编辑、复制以外的业务操作，也不增加删除按钮。

### 导出入口

- 在管理后台“内容管理”标题行，将“导出 JSON”按钮放在“新建内容”按钮旁边。
- 导出范围始终是数据库中的全部电影和剧集，包括草稿、已发布和已归档内容；不受当前列表筛选、搜索条件或页码影响。
- 导出期间按钮禁用，防止重复请求；原有列表操作保持可用状态不变。
- 下载失败时在内容管理页显示明确错误，不创建空文件或残缺文件。
- 成功文件名为 `movie-harbor-content-export-YYYYMMDD-HHmmss.json`，时间使用服务端 UTC 导出时间。

## 管理 API 与媒体路径

管理详情响应中的 `MediaSummary` 新增只读字段：

```json
{
  "id": "...",
  "url": "/media/video/ab/file.mp4",
  "local_path": "/media/video/ab/file.mp4",
  "original_name": "movie.mp4",
  "mime_type": "video/mp4",
  "byte_size": 1234
}
```

`local_path` 与当前 URL 在首版部署中可能具有相同文本，但语义不同：`url` 是浏览器访问地址，`local_path` 是管理员查看和导出使用的容器内文件路径。二者分别生成，调用方不得从 URL 猜测存储路径。公共目录与详情 API 不增加该字段，避免向访客额外暴露存储语义。

新增已认证管理员接口：

```text
GET /api/admin/contents/export
```

接口返回 `application/json; charset=utf-8`，并通过 `Content-Disposition: attachment` 提供安全文件名。未登录请求返回 `401`。接口不接收筛选、分页或路径参数。

## 导出数据结构

导出结构固定为英文键名，不包含内容状态、数据库 ID、媒体 ID、文件大小或 MIME 类型。电影和剧集对象包含年份与题材名称数组；单集不重复导出所属剧的年份和题材：

```json
{
  "exported_at": "2026-09-16T12:00:00Z",
  "movies": [
    {
      "name": "电影名",
      "synopsis": "简介",
      "year": 2024,
      "genres": ["剧情", "科幻"],
      "poster_path": "/media/poster/ab/poster.jpg",
      "video_path": "/media/video/ab/movie.mp4",
      "duration_seconds": 7200
    }
  ],
  "series": [
    {
      "name": "剧名",
      "synopsis": "简介",
      "year": 2023,
      "genres": ["悬疑"],
      "poster_path": "/media/poster/cd/poster.jpg",
      "episodes": [
        {
          "season_number": 1,
          "episode_number": 3,
          "name": "第三集",
          "video_path": "/media/video/cd/episode.mp4",
          "duration_seconds": 2700
        }
      ]
    }
  ]
}
```

- 缺少海报、视频或时长时，对应字段为 `null`，不省略字段。
- 缺少年份时 `year` 为 `null`；没有题材时 `genres` 为 `[]`，字段均不省略。
- `genres` 只包含题材名称，不包含题材 ID、启用状态或排序值；顺序按题材 `sort_order`、内部 ID 升序稳定排列。
- `duration_seconds` 沿用数据库的秒数，避免分钟换算损失。
- 每个单集显式包含 `season_number` 和 `episode_number`，剧集不再为导出结果嵌套季数组。
- 年份和题材只属于电影或整部剧；单集没有独立年份和题材字段，不在每一集内重复导出。
- 电影和剧集按名称升序、内部 ID 升序稳定排序；内部 ID 只用于消除同名内容的排序歧义，不写入 JSON。
- 单集按季编号、集编号、内部 ID 升序排列。

## 数据读取与一致性

导出查询放在独立的管理导出边界中，不复用带分页的管理列表，也不由前端逐条请求详情。后端在一个只读、可重复读事务中读取电影、剧集、季、单集、题材关联和媒体记录，确保一个导出文件不会混合多个数据库时点。题材使用批量关联查询并按电影或剧集 ID 组装，不逐条调用详情接口，也不产生逐内容查询。

查询只读取数据库元数据，不检查物理文件是否仍存在，也不遍历媒体目录。路径统一由共享的受控路径构造函数将 `storage_key` 转换为 `/media/<storage_key>`；无效存储键使导出失败，不输出未经控制的路径。

响应在查询和序列化全部成功后才返回。首版不实现流式超大导出、压缩包、导入功能或导出历史记录。

## 前端下载流程

共享 API 客户端增加认证下载能力，复用现有同源凭据、会话过期处理和响应错误语义。管理内容页调用专用导出函数，读取后端文件名并创建临时对象 URL 触发下载；完成后立即撤销对象 URL。

若响应为 `401`，沿用现有管理员会话过期流程。其他失败显示“内容导出失败，请重试”，且不影响列表数据和筛选状态。

## 测试与验收

### 后端

- 未认证导出返回 `401`。
- 一次导出包含草稿、已发布和已归档内容，但 JSON 中没有 `status` 字段。
- 电影包含简介、年份、题材名称数组、海报路径、视频路径和时长。
- 剧集包含简介、年份、题材名称数组、海报路径，以及带季编号、集编号、名称、视频路径和时长的扁平单集数组；单集不增加年份或题材字段。
- 缺失年份、媒体和时长序列化为 `null`，没有题材序列化为 `[]`。
- 电影和剧集的多个题材按系统题材顺序稳定导出。
- 同名内容及乱序季集仍产生稳定顺序。
- 管理电影和剧集详情返回 `local_path`，公共 API 不返回该字段。
- 导出读取保持同一数据库快照。

### 前端

- 电影详情只读显示已有视频路径。
- 每个单集分别显示自身视频路径；未上传视频不显示伪路径。
- “导出 JSON”位于“新建内容”旁边。
- 导出成功使用响应文件名下载并撤销对象 URL。
- 重复点击在请求期间被阻止；失败和会话过期得到正确提示。

### 端到端

创建不同状态的电影和剧集，设置年份和多个题材，上传电影海报、电影视频、剧集海报及单集视频；验证详情路径和导出 JSON 的年份、题材顺序、路径、秒数、季编号、集编号、空值及无 `status` 字段，并确认单集不重复包含年份或题材。

## 非目标

- 不显示或导出宿主机绝对路径。
- 不允许通过路径字段编辑、移动或删除文件。
- 不实现 JSON 导入、选择性导出、按当前筛选导出或后台异步导出任务。
- 不改变公共站点响应和页面。
