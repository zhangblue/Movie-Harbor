# Ubuntu 半离线部署协作规则设计

日期：2026-10-10

## 目标

把已在 Ubuntu 服务器上验证成功的 Movie Harbor 半离线升级步骤固化到根目录 `AGENTS.md`，使后续代理在用户要求部署 AMD64 离线包时采用同一套安全流程。

## 固定环境

- SSH 主机别名：`ubuntu`。
- 部署目录：`/home/zhangdi/works/movie_harbor/serve`。
- 离线包：本地 `dist/offline/movie-harbor-offline-linux-amd64-<版本>.tar.gz`。
- 服务器架构必须为 `x86_64`/`linux/amd64`，并已安装 Docker Engine 与 Docker Compose v2。

版本号、包名和备份时间戳必须从本次部署目标与服务器实际时间取得，不得复用历史命令中的固定值。

## 部署流程

1. 阅读项目部署、半离线发布和媒体备份文档，并通过 Context7 核对本次使用的 Docker Compose CLI 行为。
2. 在本地校验包的 SHA-256；通过 SSH 只读检查服务器架构、Docker/Compose 版本、磁盘空间、现有容器、镜像和部署目录。
3. 只记录现有 `.env` 的 SHA-256 和配置项名称，不输出秘密值。读取 `DATABASE_HOST_DIR` 与 `MEDIA_HOST_DIR` 仅用于确认数据路径。
4. 上传离线包到部署目录的上级目录，并确认服务器端 SHA-256 与本地一致。
5. 创建权限为 `0700` 的唯一备份目录。备份当前部署文件及 `.env`，停止 API 以冻结写入，再使用 PostgreSQL 自带工具生成自定义格式数据库备份并验证其目录清单可读取。
6. 默认不备份媒体目录，不复制、移动、删除或改写现有媒体；如果用户另行明确要求媒体备份，再单独执行。中止的媒体备份必须停止对应临时容器并删除不完整归档。
7. 在唯一临时目录解压发布包，运行包内 `load-images.sh` 校验文件并导入三个自研镜像。
8. 使用现有 `.env` 对新版 `compose.yml` 执行配置校验并核对镜像标签。校验通过后只替换发布文件，明确排除 `.env`；替换后再次核对 `.env` SHA-256。
9. 在原部署目录执行 `docker compose --env-file .env -f compose.yml up -d --no-build --wait --wait-timeout 180`。API 启动时自动执行数据库迁移；任一服务未健康时停止后续清理并保留现场。
10. 验证健康接口、公开站和管理后台 HTTP 响应、所有容器健康状态、三个自研镜像版本、数据库迁移新增结构、原内容数量、数据库及媒体挂载源、API 日志和 `.env` SHA-256。
11. 将包含数据库或 `.env` 的备份文件权限设为 `0600`。成功后删除本次临时解压目录和不完整临时文件；保留外层发布包、数据库备份与旧部署备份。

## 失败与回滚边界

- 包校验、配置校验或备份验证失败时，不替换正式部署文件。
- API 已停止但正式文件尚未替换时，先排查失败原因；需要恢复服务时仍使用原部署文件启动。
- 正式文件替换或新服务启动失败时，保留日志和容器现场，使用本次旧部署备份恢复发布文件及 `.env`，再用原镜像标签启动；不得修改数据库或媒体目录来规避启动错误。
- 数据库迁移已提交后不自动执行向下迁移。需要回滚数据库时必须获得用户明确授权，并从升级前数据库备份恢复。
- 不执行 `docker compose down -v`，不删除数据库目录或媒体目录，不显示 `.env` 内容。

## 验收标准

- 所有服务均为 `healthy`，健康接口返回 `{"status":"ok"}`。
- 自研服务使用目标版本的 `linux-amd64` 镜像。
- `.env` 升级前后 SHA-256 完全一致。
- PostgreSQL 和 API 仍挂载原数据库与媒体目录。
- 数据库备份可由 `pg_restore -l` 读取，旧部署备份包含原 `.env`，两者权限均为 `0600`。
- 新迁移结构存在，升级前内容数量未减少；原有内容的默认公开范围保持不变。
- 媒体目录未被备份或改动，除非用户对本次部署另有明确要求。
