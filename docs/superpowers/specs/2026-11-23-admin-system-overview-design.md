# 管理后台系统概览设计

日期：2026-11-23

## 1. 背景与目标

管理后台已有“系统设置”导航，但当前只显示未开放占位页。部署者需要进入宿主机、查看容器或执行数据库命令，才能判断应用、数据库和媒体卷是否仍适合继续上传；同时，应用无法验证宿主机上独立执行的数据库与媒体备份，界面也没有明确表达这一事实。

本次把“系统设置”实现为只读系统概览：管理员可以查看应用版本、内容与媒体统计、媒体卷容量和当前可写状态，并获得准确的备份边界说明。页面不直接执行备份、恢复、升级、清理、迁移或任何宿主机写操作。

本文档增量修订主设计中的系统设置占位约定。仓库虽已有 `2026-09-16-multi-volume-media-storage-design.md`，但当前生产实现仍使用单一 `MEDIA_HOST_DIR`，本次不把多卷迁移、卷身份或跨卷媒体生命周期纳入前置范围。接口使用卷数组承载当前唯一媒体目录，为未来单独实现多卷后扩展响应数量保留兼容边界。

## 2. 核心原则

- 系统概览是观测面，不是运维执行面。
- 只报告后端能够在当前请求中直接验证的状态，不根据时间、文件名或管理员未确认的信息猜测备份是否成功。
- 页面不显示宿主机绝对路径、容器内路径、存储键、数据库连接串、Cookie 配置、密钥、环境变量值或底层错误文本。
- 单个可选统计失败时尽量返回降级结果；认证失败和数据库不可用仍使用现有统一错误流程。
- 所有数据只供已认证管理员查看，响应禁止缓存。

## 3. 页面结构

后台保留“系统设置”导航名称，打开后显示以下区域。

### 3.1 总体状态

页首显示应用版本、采样时间和总体状态：

- `正常`：数据库查询成功，所有已配置媒体卷身份有效、可读取，并且至少有一个卷在扣除安全保留空间后仍可写。
- `需注意`：应用仍可提供主要功能，但存在容量不足、单卷运行期不可用、卷只读或某项统计无法取得。
- `不可用`：系统概览请求本身失败。此状态由前端错误页表达，不伪造局部正常结果。

总体状态只概括 API 当前能直接观察的数据库与媒体存储，不声称已经探测公开站、管理站、Caddy、外部 DNS、TLS 或宿主机容器运行状况。

### 3.2 资源摘要

摘要卡片显示：

- 电影数，按草稿、已发布、已归档拆分。
- 剧集数，按草稿、已发布、已归档拆分。
- 单集数，按草稿、已发布、已归档拆分。
- 普通用户总数和当前存在有效会话的用户数。
- 媒体资产数量和数据库记录的媒体总字节数，按海报与视频拆分。

这些数字用于容量和运营判断，不作为财务、审计或实时监控指标。数据库统计在一个只读事务快照内取得，避免同一响应中的分项互相矛盾。

### 3.3 媒体卷状态

当前唯一媒体目录显示为“卷 0”：

- 逻辑卷编号，例如“卷 0”。
- 当前状态：健康、空间不足或不可访问。
- 总容量、当前可用容量、安全保留空间和扣除保留值后的可上传容量。
- 当前归属该卷的媒体资产数量和数据库记录字节数。
- 是否可接受新上传。

容量值来自 API 进程对现有媒体根目录实际取得的文件系统信息；资产数量和媒体字节来自数据库，当前全部归入卷 0。两者采样时点不同，页面明确标注为当前近似状态。卷卡片不得返回或渲染宿主机路径、容器路径、卷身份标记内容或任何媒体存储键。

状态优先级固定为“不可访问 > 空间不足 > 健康”：容量元数据无法读取时为不可访问；可用字节不大于配置的安全保留空间时为空间不足；否则为健康。概览不通过写探针推断只读状态，真实上传、替换和删除仍由现有媒体写入路径执行权威校验。若未来实现多卷，必须在多卷实现设计中补充身份异常、只读和跨卷状态契约，不能由本页面自行猜测。

### 3.4 备份边界

首期不新增备份记录表，也不通过网页或 API 创建备份。页面固定说明：

- Movie Harbor 无法验证在宿主机或外部备份系统中执行的备份是否存在、完整或可恢复。
- 完整灾难恢复必须把数据库和全部媒体卷作为同一一致性备份集。
- 只备份数据库和部署文件只能称为升级安全备份，不能称为完整灾备。
- 页面直接展示上述稳定边界，并注明详细操作文档路径 `docs/guides/media-and-backup.md`；生产页面不尝试打开仓库本地文件、不识别部署方式，也不返回未经验证的环境专用命令。

因此页面显示“备份状态：应用无法验证”，而不是“未备份”或虚构“最近备份时间”。若未来需要读取外部备份工具生成的受信清单，应另行设计清单来源、原子写入、身份校验和过期语义。

## 4. 管理接口

新增：

```text
GET /api/admin/system/overview
```

响应结构示意：

```json
{
  "sampled_at": "2026-11-23T10:00:00+08:00",
  "application_version": "1.0.0",
  "status": "healthy",
  "counts": {
    "movies": { "draft": 3, "published": 20, "archived": 1 },
    "series": { "draft": 2, "published": 8, "archived": 0 },
    "episodes": { "draft": 5, "published": 120, "archived": 2 },
    "viewer_users": 4,
    "active_viewer_users": 2,
    "posters": { "count": 31, "bytes": 84000000 },
    "videos": { "count": 148, "bytes": 920000000000 }
  },
  "volumes": [
    {
      "number": 0,
      "status": "healthy",
      "total_bytes": 2000000000000,
      "available_bytes": 1080000000000,
      "reserve_bytes": 10737418240,
      "writable_bytes": 1069262581760,
      "accepts_uploads": true,
      "asset_count": 179,
      "recorded_asset_bytes": 920084000000
    }
  ],
  "backup": { "status": "unverifiable" },
  "warnings": []
}
```

卷容量采样失败时，`total_bytes`、`available_bytes` 和 `writable_bytes` 明确返回 `null`，不得用零伪装未知事实；数据库记录的 `asset_count` 和 `recorded_asset_bytes` 仍可返回。`warnings` 元素固定为 `{ "code": "storage_capacity_unavailable", "scope": "volume:0", "message": "无法读取媒体卷容量" }`。首期只允许 `storage_capacity_unavailable` 和 `storage_space_low` 两个告警码；数据库摘要失败不降级为告警，而是使请求返回 `500`。

枚举值和告警结构由共享 API 类型约束。已知字节数使用非负 64 位整数语义；前端只负责单位格式化，不重新推断卷健康状态。应用版本来自构建产物，不读取或返回镜像仓库凭据、Git 工作区或宿主机文件。

接口沿用管理员会话和 CSRF 之外的只读认证规则，返回 `Cache-Control: private, no-store`。未登录返回 `401`；数据库统计失败返回 `500`，不把零值伪装为真实统计；媒体根目录的文件系统采样失败时保留数据库统计、把卷 0 标记为不可访问并返回对应告警。

## 5. 后端边界

新增独立 `admin_system` 模块，负责 DTO、路由、数据库摘要查询和状态组合。媒体容量探测使用应用启动时已经解析并验证的媒体根目录，不在系统模块中再次读取原始环境变量，也不扫描普通媒体文件。实现计划需先从现有媒体存储状态暴露只读容量采样边界；不得顺带实现多卷配置、数据库卷编号或跨卷生命周期。

数据库查询只读取实体表和 `media_asset` 元数据，不读取或计算视频文件哈希。卷容量检查不写探针文件，不申请上传预留，不移动媒体，也不触发恢复流程。

## 6. 前端交互

- 首次进入显示骨架或明确的加载状态。
- 请求失败显示中文错误和“重新加载”，不保留可能过期的正常状态徽标。
- 页面停留期间不自动高频轮询；管理员点击“刷新状态”才重新采样，避免容量探测和统计查询成为后台负担。
- 字节数统一使用易读单位，同时保留完整数值的无障碍文本或提示。
- 状态除颜色外始终显示文字和说明。
- 容量过低、卷异常或统计不可用时在页首汇总，并在对应卡片中给出影响，例如“该卷暂不接受新上传”。
- 页面不提供“立即备份”“恢复”“清理”“检查更新”或其他执行按钮。

## 7. 非目标

- 在网页中执行备份、恢复、升级、迁移、重启或日志清理。
- 探测 Docker、Compose、Caddy、DNS、TLS 或宿主机进程状态。
- 自动发现未配置磁盘、重排存储卷或迁移媒体。
- 扫描、校验或删除普通孤立文件。
- 建立 Prometheus、告警通知、历史指标或容量趋势系统。
- 把人工确认或外部文件存在当作已验证的可恢复备份。

## 8. 测试与验收

后端测试覆盖管理员认证、统计快照、媒体类型汇总、单卷容量、保留空间扣减、容量采样失败、空间不足、敏感字段不进入响应和禁止缓存。卷状态测试使用可注入的容量读取边界，不依赖开发机真实剩余空间。

管理前端测试覆盖加载、正常、降级、失败重试、手动刷新、容量格式化、无障碍状态文字和备份不可验证说明。端到端验收使用隔离 Compose 数据目录，验证管理员可见、匿名不可见，并确认页面没有任何会改变数据库、媒体或宿主机状态的操作。
