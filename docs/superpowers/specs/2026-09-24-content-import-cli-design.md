# Movie Harbor 内容导入 CLI 设计

日期：2026-09-24

## 背景与目标

Movie Harbor 管理后台可以导出完整内容元数据，但导出 JSON 只记录容器内媒体路径，不包含媒体文件本身，也没有对应的导入能力。管理员需要把一套旧 Movie Harbor 的导出 JSON 与宿主机媒体目录迁移到一套全新部署的 Movie Harbor，并通过目标平台现有管理 API 重建题材、电影、剧集、季、单集和媒体关联。

本工具采用仓库内独立 Node.js CLI。它不修改目标数据库，不直接复制目标媒体目录，也不新增批量导入 API。所有目标数据都通过现有登录、题材、内容和媒体接口创建，从而复用目标平台的认证、校验、版本控制与媒体存储规则。

## 使用界面

根 `package.json` 增加 `import:content` 命令。调用方式如下：

```bash
npm run import:content -- \
  --json /path/movie-harbor-content-export.json \
  --media-root /Volumes/Samsung_T5/movies/media \
  --target https://new-movie-harbor.example.com \
  --admin-name admin
```

参数语义：

- `--json`：管理后台导出的 JSON 文件。
- `--media-root`：旧平台 `/media` 对应的宿主机目录。
- `--target`：新平台根地址，只接受 `http` 或 `https`。
- `--admin-name`：新平台管理员名称。

管理员密码通过交互式隐藏输入读取，不接受命令行密码参数，避免密码进入 shell 历史或进程列表。工具不提供跳过 TLS 证书校验的选项；生产环境应使用有效 HTTPS，本机或受信局域网测试可以显式使用 HTTP 地址。

默认进度文件与导出文件位于同一目录，名称为：

```text
<导出文件名>.movie-harbor-import-progress.json
```

## 输入模型与预检

工具接受当前管理导出结构：顶层包含 `exported_at`、`movies` 和 `series`。电影包含名称、简介、年份、题材、海报路径、视频路径和时长；剧集包含名称、简介、年份、题材、海报路径与扁平单集数组；单集包含季号、集号、名称、视频路径和时长。

在登录和任何目标写操作前，工具完成整个输入的严格预检：

- 顶层、电影、剧集和单集字段类型必须符合导出契约。
- 名称、季号和集号必须满足目标 API 的基础要求。
- 可空的年份、时长和媒体路径只接受对应类型或 `null`。
- `genres` 必须是字符串数组。
- 同一导出文件内不允许出现同名电影或同名剧集。导出结构不含内容 ID，无法为同类型重名项建立无歧义的冲突与断点身份；发现时预检失败。
- 海报路径只接受规范的 `/media/poster/...`，视频路径只接受规范的 `/media/video/...`。
- 媒体 URL 的 `/media/` 前缀从映射时移除，再连接到 `media-root`。例如 `/media/video/ab/file.mp4` 映射为 `<media-root>/video/ab/file.mp4`。
- 路径规范化及符号链接解析后的真实文件必须仍位于 `media-root` 内，拒绝 `..`、绝对路径注入和符号链接逃逸。
- 所有非空媒体引用必须指向普通文件；任一引用缺失时，预检失败且不修改目标平台。

导出文件不含生命周期状态，因此所有导入内容固定保留为草稿。工具不尝试推断或恢复旧平台状态。

## 认证与 API 客户端

CLI 使用目标平台现有管理认证流程：

1. 向 `/api/admin/login` 提交管理员名称和交互读取的密码。
2. 保存响应中的会话 Cookie。
3. 请求 `/api/admin/session` 获取 CSRF Token。
4. 后续写请求同时携带 Cookie、`Origin` 和 `X-CSRF-Token`。

API 客户端只在内存中保存认证信息。日志、错误消息和进度文件均不得包含密码、Cookie 或 CSRF Token。目标返回 `401` 或 `403` 时视为认证或会话失效，不继续发送写请求。

JSON 请求使用 Node.js 原生 HTTP 能力。媒体请求构造单文件 `multipart/form-data`，通过文件流发送并设置准确的 `Content-Length`。工具处理请求背压、文件读取错误、远端提前断开和超时，不把完整视频载入内存。文件名取本地文件 basename；声明 MIME 类型根据受支持的媒体扩展名确定，并仍由目标 Movie Harbor 执行实际媒体校验。

## 题材同步

导入内容前，工具汇总 JSON 中电影和剧集的全部题材名称，并读取目标平台题材配置。

- 名称使用精确字符串匹配，不做大小写折叠、空白修剪后的模糊合并或别名映射。
- 目标已有同名且启用的题材时直接复用其 ID。
- 目标已有同名但停用的题材时，题材同步失败并提示管理员先在目标平台处理。现有 API 不提供重新启用能力，工具不得绕过草稿题材约束或擅自改动题材状态。
- 目标缺少题材时自动调用题材创建接口。新题材使用目标平台默认的启用状态和排序行为。
- 若并发创建造成同名冲突，工具重新读取题材列表；读取到同名项后继续，否则将其视为失败。
- 工具不重排、不改名、不停用或删除目标平台已有题材。

题材同步完成后建立稳定的“名称到目标 ID”映射，内容更新只提交目标题材 ID。

## 冲突识别

导入前读取目标平台现有电影和剧集，按“内容类型 + 完全相同的名称”建立冲突索引。同名电影与同名剧集互不冲突。

- 进度文件已记录的内容使用已保存的目标 ID 续传，不参与同名冲突判断。
- 不在进度文件中、但目标平台已有同类型同名内容时，打印 `SKIP` 并继续处理后续内容。
- 工具不覆盖、合并、删除或修改冲突内容。
- 结束汇总列出所有跳过项及其类型、名称和原因。

该规则允许正常断点续传，同时避免把工具先前创建的半成品误判成外部冲突。

## 电影导入流程

每部非冲突电影按以下顺序处理：

1. 创建电影草稿，记录目标电影 ID 和返回版本。
2. 更新名称、简介、年份、时长和题材 ID，记录新版本。
3. 若 `poster_path` 非空，流式上传海报并记录新版本与海报完成标记。
4. 若 `video_path` 非空，流式上传视频并记录新版本与视频完成标记。
5. 标记该电影导入完成，但不调用发布接口。

恢复时从第一个没有成功标记的步骤继续。每次写操作都使用进度文件记录的最新版本，不能猜测或盲目覆盖目标版本。

## 剧集导入流程

每部非冲突剧集按以下顺序处理：

1. 创建剧集草稿，记录目标剧集 ID 和返回版本。
2. 更新名称、简介、年份和题材 ID，记录新版本。
3. 若 `poster_path` 非空，流式上传海报并记录新版本与海报完成标记。
4. 按季号升序汇总单集；每个不同季号创建一个季，记录季 ID 和剧集新版本。
5. 在对应季下按集号升序创建单集，记录单集 ID、单集版本和剧集新版本。
6. 更新单集时长，记录新单集版本和剧集版本。
7. 若 `video_path` 非空，流式上传单集视频，并记录接口返回的新单集版本和剧集版本。
8. 所有季和单集完成后标记剧集导入完成，但不发布单集或剧集。

同一剧集内串行处理季和单集。父剧集版本、单集版本及媒体上传返回的 `series_version` 都必须及时保存，确保后续请求遵循目标平台的乐观并发控制。

## 进度文件

进度文件只记录已经成功的步骤，不记录失败尝试。其逻辑内容包括：

- 格式版本。
- 规范化后的目标平台 origin。
- 源文件身份，包括 `exported_at` 和源 JSON 内容摘要。
- 已成功创建或确认的题材名称与目标 ID。
- 每部电影的目标 ID、当前版本、元数据更新状态、海报状态、视频状态和完成状态。
- 每部剧集的目标 ID、当前版本、元数据与海报状态、季映射、单集映射、各单集版本、视频状态和完成状态。

每个成功步骤返回后立即更新内存状态，并以同目录临时文件写入完整 JSON，刷新成功后原子重命名覆盖正式进度文件。新建文件权限为 `0600`。失败步骤不会提前写入完成标记。

启动恢复时校验进度格式版本、目标 origin、源 `exported_at` 和源内容摘要。任一项不匹配即停止，避免把断点应用到其他导出文件或其他目标平台。

如果进度记录的目标对象已被人工删除，或其当前版本与进度记录不一致，该内容打印 `FAILED` 并跳过剩余步骤；工具不搜索同名对象接管，也不覆盖人工修改。

## 执行顺序与资源控制

工具默认串行导入：一次只处理一个内容，也只上传一个媒体文件。串行策略避免多个大视频同时占用源磁盘、网络带宽和目标临时空间，并消除同一剧集内的版本竞争。

控制台为每个阶段输出简洁状态：

```text
CREATE genre 科幻
IMPORT movie 光年正传
UPLOAD movie 光年正传 poster
UPLOAD movie 光年正传 video
SKIP series 已存在的剧集
FAILED movie 上传失败的电影: <安全错误摘要>
```

日志不得输出认证信息，也不得输出包含响应头的原始对象。服务端错误正文只保留经过长度限制和敏感字段过滤的摘要。

## 错误处理与退出语义

错误分为以下几类：

- **预检错误：** JSON 结构错误、源内容同类型重名、路径越界、符号链接逃逸或媒体文件缺失。任何目标写操作前停止。
- **题材同步错误：** 目标存在同名停用题材，或缺失题材创建后仍无法读取。停止内容导入，并保留已经成功创建的题材供下次运行复用。
- **认证错误：** 登录失败、会话失效或 CSRF 拒绝。停止本次运行。
- **连接级错误：** 目标不可达、网络中断、请求超时或远端提前断开。停止本次运行，保留已成功进度，等待重跑。
- **单内容错误：** 目标 API 对某个内容返回业务校验错误，或进度对象已删除、版本不一致。打印 `FAILED`，保留成功步骤并继续下一内容。
- **冲突：** 外部同类型同名内容。打印 `SKIP` 并继续，不计为失败。

执行结束输出成功完成、续传完成、冲突跳过和失败的数量及明细。只有全部非冲突内容成功时返回退出码 `0`；存在失败项时返回非零退出码。单纯存在冲突跳过项不改变成功退出码。

## 文件边界

实现预计包含：

- `tools/import-content.mjs`：CLI 入口、参数解析与隐藏密码输入。
- `tools/content-import/schema.mjs`：导出 JSON 校验与规范化。
- `tools/content-import/media-path.mjs`：媒体路径映射与真实路径边界检查。
- `tools/content-import/client.mjs`：认证、JSON 请求、Cookie/CSRF 管理和流式 multipart 上传。
- `tools/content-import/progress.mjs`：进度身份校验与原子持久化。
- `tools/content-import/importer.mjs`：题材同步、冲突识别和内容导入编排。
- `tests/content-import.test.mjs`：CLI 核心行为的 Node.js 契约测试。
- `package.json`：新增 `import:content` 脚本。
- `README.md`：新增操作说明和安全边界。

模块以明确数据接口协作。路径校验、HTTP 传输、进度持久化和业务编排可以分别测试，不建立无边界的通用 `utils`。

## 测试与验收

测试使用 Node.js 内置测试运行器、临时目录和本地模拟 HTTP 服务，不依赖真实管理员密码或真实媒体库。覆盖：

- 电影的元数据、题材、海报和视频按正确顺序导入。
- 剧集、季、单集、时长和媒体按正确层级导入，所有版本号使用上一响应的返回值。
- 缺失题材自动创建，已有题材按精确名称复用。
- 同名停用题材给出明确错误且不开始内容导入。
- 同名电影和剧集互不冲突；外部同类型同名内容打印 `SKIP` 并继续。
- multipart 请求包含单一 `file` 字段、正确文件名、MIME 类型和长度，文件通过流发送。
- 成功步骤才写入进度；失败后重跑不会重复创建或重复上传。
- 进度目标、源时间或源摘要不匹配时拒绝恢复。
- 目标对象被删除或版本变化时只失败当前内容，不覆盖人工改动。
- 路径穿越、绝对路径注入、符号链接逃逸、缺失文件和畸形 JSON 在写目标前失败。
- 源 JSON 内同类型重名内容在写目标前失败。
- 认证失败、会话失效、网络中断和单内容业务错误遵循规定的停止或继续语义。
- 日志与进度文件不包含密码、Cookie 或 CSRF Token。
- 进度文件使用原子替换，并以 `0600` 权限创建。

实现完成后运行相关 Node.js 测试、现有根契约测试、工作区构建及 `git diff --check`。由于工具通过现有跨服务管理 API 工作，还应在隔离的 Docker Compose 与 Playwright 环境中增加至少一个小型端到端导入场景，验证真实认证、CSRF、版本递增、媒体落盘和草稿状态。

## 非目标

- 不恢复旧平台内容的发布或归档状态。
- 不覆盖、合并或删除目标平台已有的同名内容。
- 不直接访问目标 PostgreSQL 或目标媒体挂载目录。
- 不新增服务端批量导入接口或后台任务。
- 不并发上传多个媒体文件。
- 不改变目标平台已有题材的名称、启用状态或顺序。
- 不支持其他产品的导出格式。
- 不把导出 JSON 与媒体文件重新打包为归档文件。
