# Movie Harbor 公共函数提取设计

日期：2026-09-15

## 1. 背景与目标

当前前后端实现已经形成电影、剧集、单集和公开播放等完整流程，但部分后来并行演进的模块包含功能相同或高度相似的私有函数。重复逻辑主要集中在内容字段校验、生命周期状态转换、媒体记录处理、路由参数解析、前端 API 响应校验、管理编辑器辅助逻辑，以及公开剧集排序。

本次变更只做行为保持型重构：把至少有两个真实调用方、语义和错误边界一致的逻辑提取为公共函数，并让原调用方复用。不得改变 API 路径、请求与响应结构、数据库结构、生命周期规则、媒体文件协议、页面文案或视觉布局。

## 2. 提取原则

- 只有语义和变化原因一致的函数才合并；仅代码形状相似但承担不同领域职责的函数继续独立存在。
- 公共函数放在最小共同所有者中，不建立无边界的全局 `utils` 文件。
- 公共函数应保持纯函数或明确的基础设施职责，调用方继续负责电影、剧集、单集各自的业务编排和错误响应。
- 不用复杂泛型隐藏 SeaORM 查询，不把完整编辑器状态机压入参数众多的通用 Hook。
- 保持现有错误分类和中文提示；公共函数返回稳定的通用结果，由领域层映射为现有错误类型。

## 3. 后端公共函数

### 3.1 内容规则模块

新增 `backend/src/content.rs`，承载电影、剧集和单集共同使用的内容规则：

- `Patch<T>` 的反序列化语义。
- 必填名称去除首尾空白并拒绝空字符串。
- 正整数版本和序号校验。
- 当前版本与预期版本比较。
- 字符串 UUID 列表解析与去重校验。
- 文本 Patch 和可选整数 Patch 应用。
- 生命周期目标解析、幂等状态判断、合法转换判断。
- `status`、`published_at`、`archived_at` 的统一状态写入。

模块使用小型公共错误分类区分“请求无效”和“状态/版本冲突”。`MovieError` 与 `SeriesError` 分别实现转换，现有 HTTP 状态码和响应正文不变。电影服务改用统一状态写入函数，消除其与剧集服务之间的状态时间戳实现差异。

### 3.2 媒体记录与删除事务

现有 `backend/src/media/removal.rs` 是媒体同步删除协议的所有者，因此在该模块集中：

- 按媒体资产 ID 加载 `OwnedMedia`。
- 批量删除媒体资产记录。
- 完成“数据库操作结果 → 回滚并恢复 / 提交 / 清理隔离文件”的公共事务收尾流程。

公共收尾函数区分提交前业务或数据库错误、提交/恢复失败、提交后物理清理失败。电影和剧集服务继续把这些结果映射到各自现有的 `Conflict`、`MediaDelete` 和 `MediaDeleteFinalization`，删除响应结构保持不变。

### 3.3 路由 UUID 解析

新增后端 HTTP 辅助模块中的泛型 UUID 解析函数。调用方传入本领域的错误值，因此：

- 管理电影、剧集、题材和媒体路由继续返回原有错误分类。
- 公开目录中的非法 UUID 继续表现为不存在。

不合并各路由处理函数，因为它们调用的服务、权限和返回 DTO 不同。

### 3.4 不提取的后端逻辑

- 电影和剧集 repository 的 `find`、`persist`、题材关联查询虽然形状接近，但实体、字段集合、锁顺序和错误语义不同，强行泛化会把 SeaORM 类型细节泄漏到公共接口。
- 电影、剧集和单集发布条件不同，只复用基础字段与媒体判断，不合并完整发布校验函数。
- 剧集层级锁、父版本递增、季和单集删除范围继续留在剧集服务。

## 4. 前端公共函数

### 4.1 API 客户端

将管理和公开客户端中重复的“响应体不可为 `undefined`”校验移动到 `frontend/packages/api-client/src/http.ts`，作为共享请求边界函数。所有现有客户端方法继续返回相同类型，并在异常空响应时抛出相同 `TypeError`。

### 4.2 管理后台内容辅助逻辑

在管理后台内容域新增小型公共辅助模块：

- 合并当前可选题材与内容已关联但已停用的题材，保持去重和原顺序。
- 把电影和剧集编辑器重复识别的写操作错误归类为会话失效、需要恢复的 403、媒体删除失败、媒体替换失败、媒体内容不匹配、版本冲突、字段校验失败和普通错误。

编辑器仍自行决定状态更新，例如是否关闭删除对话框、是否设置冲突状态、是否清空待上传文件。不会创建参数众多的通用编辑器 Hook，也不会合并电影和剧集的保存流程。

发布错误列表的共同展示部分提取为内容域组件或函数；剧集缺少已发布单集的专属中文说明仍保留在剧集组件中。

### 4.3 公开站剧集排序

将按季序号、单集序号排序和构造可播放单集序列的纯函数放入公开站的剧集辅助模块。剧集详情、选集器和播放器共同复用，且不原地修改 API 返回数组。

### 4.4 不提取的前端逻辑

- 电影和剧集编辑器的 `fieldsOf`、保存、刷新和删除编排拥有不同字段及父子版本规则，继续分开。
- `PosterPicker` 与 `VideoPicker` 的交互和预览需求不同，不合并为一个配置驱动组件。
- 电影与剧集播放器虽共用请求状态，但渲染结构和选集行为不同，不额外抽象页面组件。

## 5. 测试策略

实现遵循测试驱动开发。

1. 先为后端内容规则、UUID 解析和媒体公共函数添加单元测试，导入尚不存在的公共接口并确认测试因接口缺失而失败。
2. 为前端 API 响应校验、题材合并、错误归类、发布字段列表和剧集排序添加行为测试，确认公共接口缺失时失败。
3. 实现最小公共函数，使专用测试通过。
4. 逐个替换现有调用方并删除重复私有函数；每组替换后运行对应电影、剧集、媒体、API 客户端、管理后台和公开站测试。
5. 使用现有集成测试确认 HTTP 状态、JSON、中文文案、生命周期、媒体同步删除及页面交互均未改变。

测试断言面向输入输出和可观察副作用，不通过搜索源代码判断函数是否已提取。完成前执行项目约定中的 Rust 格式、Clippy、数据库测试、前端测试与构建、Node 契约测试、端到端测试和 `git diff --check`。

## 6. 兼容性与风险控制

- 不新增数据库迁移，不修改部署配置或半离线包结构。
- 不改变公共 TypeScript API 的既有导出，新增导出仅服务内部复用和测试。
- 不改变后端已有错误响应；公共错误必须在领域边界完成映射。
- 时间相关生命周期测试只断言状态和时间戳存在/清空规则，避免依赖精确时钟值。
- 媒体删除事务继续保持“数据库提交前失败可恢复、提交后清理失败返回最终化错误”的现有语义。
- 若提取过程中发现两个候选函数的边界条件不一致，优先保留独立实现并记录原因，不通过扩大参数集合制造表面复用。

## 7. 完成标准

- 本文列出的公共逻辑均只有一个生产实现，并被至少两个真实调用方复用。
- 原有重复私有函数已删除。
- 未把领域专属流程错误地泛化为公共函数。
- 现有对外行为和数据保持不变。
- 相关专用测试、项目回归测试、构建与端到端验收全部通过。
