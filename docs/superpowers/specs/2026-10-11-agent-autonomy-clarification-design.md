## AGENTS.md 规则

### 资料读取

只有修改产品行为、接口、数据结构、媒体生命周期或部署机制时，才必须读取主规格及与本次变更直接相关的最新增量规格。纯文档、格式、注释、已有流程执行和只读审阅只读取直接相关资料。

增量规格按变更领域选择，不要求读取该分类下所有历史文件。

### 冲突优先级

需求冲突按以下顺序处理：

1. 用户本次明确要求。
2. 同领域最新且已确认的增量规格。
3. 主规格。

当前实现只作为现状证据，不自动覆盖规格。只有冲突会实质改变结果、数据安全或任务范围时才询问用户；能够用上述优先级消解的冲突直接处理并说明依据。

### Context7

回答库、框架、SDK、API、CLI 或云服务的用法问题，以及选择、修改或排查其参数、配置和版本差异时，继续按现有 Context7 规则查询当前官方文档。

执行仓库已经固定且验证过的命令、运行现有测试脚本，以及普通 `git status`、`git diff`、`git add`、`git commit` 等仓库操作，不要求重复查询 Context7。该调整只减少资料查询，不扩大文件、网络或外部系统权限。

### 实现计划与测试驱动

只有任务已经存在经用户确认的实现计划时，才要求按计划顺序推进。诊断、审阅和小型维护任务可以直接执行；如果工作会改变多个组件或引入新的产品行为，仍先完成设计和计划。

可执行代码的功能、修复和行为变化继续采用失败测试优先。文档、Skill、静态配置和一次性运维规则采用与风险相符的契约测试、链接校验、schema 校验、构建或聚焦检查，不为满足形式要求编写无意义测试。

### 数据与媒体备份

完整灾难恢复，以及任何可能同时改变数据库与媒体的操作，必须把数据库和媒体作为同一一致性备份集。

仅升级应用并保证媒体目录不变时，可以只创建数据库和部署文件安全备份，但不得称为完整灾备。如果迁移前置条件要求媒体一致备份，则必须暂停并取得媒体备份明确授权。

### 完成前验证

按实际变更范围运行足以验证本次工作的命令，无关检查不需要执行，也不需要为跳过无关检查向用户确认。只有实际运行并读取输出的检查才能报告为通过：

- Rust 代码或迁移：格式化、Clippy 与相关 Rust 测试；涉及数据库约束时使用真实 PostgreSQL。
- 前端代码：受影响 workspace 的测试与构建。
- 根工具或契约：相关 Node 测试。
- 修改跨服务代码、部署配置或发布工具：隔离的 Docker Compose 与 Playwright E2E。
- 只执行已发布且已验证的部署包：使用项目部署 Skill 的生产验收，不要求重新运行本地构建与 E2E。
- 仅文档或 Skill：文档契约、Skill 校验和 `git diff --check`。

## 部署 Skill 授权

用户明确要求将指定发布包部署或升级到 Skill 固定的 `ubuntu` 主机时，即授权执行 runbook 中的标准部署步骤，包括只读预检、通过既定 SSH 主机上传、创建部署文件与数据库安全备份、替换已校验的发布文件、启动服务和验收。不得再次请求总确认。

以下情况仍必须停止并请求明确授权或澄清：

- 目标主机、发布包、正式目录、Compose 项目或数据挂载存在会改变目标或数据集的实质冲突。
- 需要数据库恢复、向下迁移、媒体备份、修改媒体、重置账号、重新初始化数据库或其他标准部署步骤之外的操作。
- 用户只要求方案、审阅或说明，没有要求执行部署。

明确标准上传和标准部署步骤属于原始部署请求的权限范围，会增加代理在该已授权范围内的操作自主性，但不会授权新的主机、数据集或恢复操作。

## 失败停止与回滚

“失败后停止”指停止继续向前升级、停止清理现场和停止扩大排障范围，不等于让原服务保持下线。

在数据库未恢复、媒体未改动的前提下，标准部署授权同时包含 runbook 明确规定的应用级回滚：

- 恢复已验证的旧发布文件。
- 恢复字节一致且哈希匹配的原 `.env` 备份，但不得编辑、猜测、补写或重建配置。
- 使用预检记录的旧镜像恢复原服务并重新验收。

这项澄清使应用级回滚不再要求二次确认，属于在原部署目标内恢复原状态的操作自主性。数据库恢复、媒体恢复或任何可能改变持久数据的操作仍不在其中，必须重新取得明确授权。

如果原 `.env` 哈希无法恢复、旧镜像缺失、数据库已经迁移且与旧版本不兼容，或应用级回滚可能改变持久数据，则停止并报告，不猜测修复。

## 保留的保障措施

- 数据库恢复必须重新获得本次明确授权。
- 媒体备份与媒体恢复必须独立明确授权。
- 禁止 `docker compose down -v`，禁止删除或重定向数据库与媒体目录。
- 不输出 `.env` 值、密码、Cookie、令牌或完整环境配置。
- 用户只要求方案时不得连接服务器。
- 目标或数据集存在实质歧义时，在任何写操作前停止。

## 验证

- 为文档契约测试增加对关键自主性和授权边界的结构化断言，先验证旧文案无法满足新契约，再实施修改。
- 使用 Skill 校验器验证 frontmatter 与目录结构。
- 运行文档契约测试与 `git diff --check`。
- 使用两个独立只读行为场景验证：明确部署请求不会触发重复总确认；数据库恢复请求仍会要求单独授权。
- 不连接生产服务器，不执行真实部署。
